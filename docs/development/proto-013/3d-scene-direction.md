# 013 套圈改造摊：三维地摊场景方向

版本：v0.6；日期：2026-10-09（Asia/Shanghai）。状态：用户新方向与首组三维场景合同。实现、测试、构建及真实 Player 的最终事实统一见 [本轮开发记录](2026-10-09-p0.md)，本文件不宣称这些步骤已经完成。

## 1. 决策与历史边界

**用户明确决定**：采用真实三维，场景使用斜视角，玩家在镜头前向前抛圈，呈现现实地摊套圈的空间感。此前的平面占位画面和固定正交 2.5D 主路线被这一决定替换。Unity 2022.3.62f3c1、PC 单机、Steam 目标及兑现/留场经济保持。

**助手的首组实施方案**：相机固定在玩家身后上方，六奖品按地面两排三列陈列，近处展示持圈手与实体环；场地采用暖灯夜市、条纹棚、帆布摊地和暖色旧物道具。相机精确位置、俯角、视野、地面间距、道具尺寸、材质与输入灵敏度均是需实景校准的实施建议。

此前二维 P0 的源码、参数与实测结果作为历史记录保留。它们可以支持账目、事务或通用数学回归，不能直接证明三维布局、空间命中、遮挡、模型或新输入已经正确。新旧模拟与布局版本分开记录，回放不混用。

## 2. 首组范围

本轮制作范围限定为一个可操作三维摊场，继续使用普通圈、风扇与反弹板及单摊处置。六槽 S1–S6 的稳定身份保持，空间配置改为有左右与纵深的两排三列。其精确位置由同一场景/规则配置提供，按前排左至右、后排左至右建立清楚编号。

首组交付需包含：三维地面/帆布与棚架、暖灯与少量周边摊景、可辨六奖品、实际环与近处持圈表现、斜视固定相机、左右瞄准/仰角/力度、轻量 UI 和当前单摊命令。场景读图与实投先成立，再扩完整人物、三章与更多机关。

完整剧情、十二摊、磁盘存档/恢复、跨摊、局外解锁、特殊圈、后续四机关、完整音乐/环境、手柄全流程和 Steam 接入继续按完整方案分阶段完成，不因这次视觉方向变更记为已交付。

## 3. 相机与构图

- 固定透视相机位于玩家后方和上方，朝摊地略俯视；允许轻微侧偏帮助看清环与道具体积，避免极端俯视或侧面舞台构图。没有自由漫游、绕场操作或探索夜市要求。
- 下部近景包含出手位置、握圈手/简化手部与待投环；中部是完整两排奖品和落点区，上部是棚架、暖灯与低对比夜市背景。近景手与圈不得挡住近排接受区。
- 远排保留真实透视缩小，通过间距、轮廓、受光和焦点标记提高识别；不按屏幕大小悄悄扩大远排判定。场景中可读的槽标记跟随实际三维锚点。
- 所有支持宽高比保留两排六物、出手点和弹道最高点所需空间；UI 缩放只改覆盖层，不拉伸世界。相机碰到棚架遮挡时优先调整棚架与镜头，不移动独立判定体来迎合画面。

## 4. 三维真值与表现合同

建议采用 Unity 坐标约定：Y 向上、X 为左右、Z 为玩家向奖品的前方；左右瞄准控制水平朝向，仰角控制抬手方向，力度控制出手速度。正式采用的坐标与量化方式写入实际配置/接口说明。

规则使用真实三维位置、发射方向和接触几何。奖品位置、接受锚点、圈中心、机关有效面/作用体积、地面与场地边界均与视图共用同一版本化配置。相机只投影结果，屏幕鼠标坐标先经明确选取/瞄准映射，不能用另一个二维领奖层补偿不一致。

环、奖品与机关需要可观察的实体体积。稳定可练习的公开几何简化仍可使用，但要明确记录三维接受范围、接触和落地规则；不能把看似套中但判定点在别处的结果称为三维一致。装饰网格、阴影和手部动画不额外发奖或施加冲量。

04 的现金、耐久、圈数/调整、补救和标量物理建议不在本次文档里改值。旧单排 XY 坐标、侧视接受线和二维接触样本属于历史几何方案；新三维槽位/接受/接触必须有自身版本与实际验证，不直接套用旧可达结论。当前参数入口为 [Core 三维说明](../../../prototypes/proto-013-ring-toss/game/RingTossWorkshop/Assets/RingToss/Core/README-3D.md)，采用与验证状态看开发记录。任何后续实际参数变更另在权威规则和记录中同步。

## 5. 输入与轻量 UI

- 瞄准独立显示左右方向、仰角与力度；鼠标或键盘能逐项微调，确认发射后冻结本投输入。近处环随瞄准预备，出手事件与真实模拟使用同一输入，不让动画延迟重新采样。
- 场地占主要画面。顶部只保留回款/目标、钱包、剩圈与调整，底部以短控件表示瞄准和主动作；机关详情、帮助和完整事件记录按需展开。移除大块常驻坐标网格、侧栏和调试示意面板，开发调试层只在明确模式显示。
- 选中奖品/机关时短暂突出其三维锚点及公开范围。确认中奖后才弹出同层级兑现/留场选择；完成处置再接下一投。机关转向先预选再确认，预算在成功提交时消费。
- 暂停/慢放、重开和回放沿单摊状态边界处理；回放使用已保存的三维输入和发射前场景，不改正式现金、圈数或耐久。前一次二维回放不能在三维场景中静默重新结算。

具体已实现快捷键与可操作状态以 [工程 README](../../../prototypes/proto-013-ring-toss/game/RingTossWorkshop/README.md) 和开发记录为准，不把本节建议的输入方案直接列为已支持。

## 6. 美术生产与验收

首组优先制作有厚度的普通环、台扇/板材、地面帆布、条纹棚顶/柱、灯笼/灯串与少量箱具。Blender 制作源和明确 FBX 导出保留；程序构建可用于形体起步，材质与照明必须在真实斜视相机下复核。二维画像可以作为后续对白 UI，二维图不能替代本轮主体摊地、奖品或环的空间体积。

验收要同时看到三维实景和可核对的规则范围：从近处向前抛，能选择两排左右目标；环经过、下降、接触/失手与命中的位置和视图一致；棚架/手/前排物不遮关键路径；UI轻覆盖、最低分辨率可读；暂停/慢放/回放与正式输入不重复提交经济事务。截图、真实输入、事件及构建版本分别记录。

这组检查由实现代理在实际 Player 中完成，本文件只是方向和合同。此前音频许可结论、七个原创原型音和 Steam 目标保持，不为新场景引入未核实的付费服务或参考仓受限媒体。
