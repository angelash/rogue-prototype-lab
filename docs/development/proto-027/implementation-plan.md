## 2. 有限包装与内容

建议短题材：“玻璃棚的接力：身体是一套工具，也是一段需要留出空间的路线。”主蛇在生态孵化盘采集样本送回交付点，尾段可成为小蛇接手公开任务；回收需靠近、花行动并处理货物。这是同一轮内的协作，不新增局外资源或剧情分支。

- 开场：“先把样本送回孵化盘。身体变长时，看看哪段能力值得留下。”
- 切尾提示：“这段身体交给小蛇，能力也跟着它走。先看清路线与回收位置。”
- 回收提示：“收回的是实际模块和货物；装不下的留在看得见的地面。”
- 结算：“样本交付完了。回看你留下的身体、分出的任务和回收成本。”

最小文本采用原生中文，必要规则与阻塞原因完整；无人物支线、配音服务或大型故事资产。本图有限清单包括墙/通道、模块、普通货物、交付点、主蛇及至多两分身；其ID、坐标、数量和模块能力由Core唯一配置登记，不按镜头随机重抽。

## 3. 规则权威与接口冻结

本工程 [Rules.cs](../../../prototypes/proto-027-snake-hatchery/game/SnakeHatchery/Assets/SnakeHatchery/Core/Rules.cs)、[Session.cs](../../../prototypes/proto-027-snake-hatchery/game/SnakeHatchery/Assets/SnakeHatchery/Core/Session.cs) 和 [Core README](../../../prototypes/proto-027-snake-hatchery/game/SnakeHatchery/Assets/SnakeHatchery/Core/README.md) 拥有规则版本、地图/有限内容、初始有序身体、方向、模块能力、载量、行动预算、切点/回收门槛、两行为路线、冲突次序、交付/胜负、事件与快照。本合同仅摘录已只读核对的权威源码，不另建可编辑配置；测试、HUD和预告共用同一版本。

- Rules版本 `0.2.0`、快照格式1；图8×6、行动80、每个新提交命令1行动、主蛇至少保留2节、分身上限2。主蛇动作提交后，仍Active时依clone稳定ID串行尝试移动/采货/适用交付，新分身本步跳过；所有本步动作完成后先判交付8完成，再判行动耗尽。碰撞是已提交失败并耗1，停止该步后续分身；普通非法命令/重复ID不收费。
- 三种节：Basic只增加长度；Collector每节给采集速率+1；Warehouse每节给货物容量+2；每条蛇基础采集1、基础容量2。模块库存容量2，与货物容量分离，库存节不直接给身体能力。
- 总模块7、货物8/交付目标8。短/长同图同总量，初始方向Up。Short有序身体：头ID1 Basic `(1,1)` → ID2 Basic `(1,0)` → ID3 Collector `(0,0)`；库存ID4/5 Warehouse，容量2/速率2。Long再接ID4 Warehouse `(0,1)` → ID5 Warehouse `(0,2)`，库存空、容量6/速率2。两预置地面均为ID6 Collector `(0,4)` / ID7 Warehouse `(7,4)`；所有实际ID归属唯一，不由UI生成。
- 墙为 `(3,1)` / `(3,2)` / `(3,4)`；两货物点 `(2,3)`4 / `(6,3)`4；交付点 `(1,1)`。Core坐标x向右/y向后、0起，ID=`y×8+x`。
- 两行为PatrolCollect巡线一圈后停、Shuttle公开闭合路线循环；同一默认路线依次为 `(0,0)→(1,0)→(1,1)→(2,1)→(2,2)→(2,3)→(1,3)→(0,3)→(0,2)→(0,1)→(0,0)`，以实际切头格循环旋转起点。切头不在该线则无推荐路线，Runtime不自动寻路补路。最长路线32点是Core限制，不代表首轮制作32条内容。

Core接受2–32点、首点为新头、逐点正交相邻的公开路线，越界/跳格拒绝；公开墙格可进入路线配置，预告明确含墙且执行到墙前等待。Shuttle还需闭合并经过货物初始点与交付点。当前Runtime只采用作者左区默认环，没有玩家路径编辑器或右区自定义任务；不将API允许的所有路线写成已在UI提供的关卡内容。

以上都是v0.2助手实施初值，不是平衡/路线体验结论。旧v0.1两端点往返为草案，本候选采用上述公开闭合循环，不宣称已制作另一套端点运输。

接口已核对：`Session.CreatePrototype(PresetKind.Short/Long)` / `Retry()`，`State` / `LastEvents` 返回拷贝；`PreviewMove(Direction)` / `PreviewSplit(keepSegments,behavior,route)` / `PreviewReclaim(cloneId)` 只读合法性/成本/能力及物料预告。`Move`、`Wait`、`Collect`、`Deliver`、`Split`、`Reclaim`、`CollectModule`、`DropModule` 返回 `CommandResult`，可带命令ID；已提交ID再次调用返回AlreadyApplied且无新事件，不能重复收费/采集。`ExportSnapshot()` / 静态 `TryRestore` / `ValidateSnapshot` 是完整纯数据合同。

能力从当前归属的实际节计算；Unity场景、HUD、动画、声音和磁盘层不能另算能力、复制节或增加货物。Move只自动吞目标格最低ID地面模块并追加旧尾格，不自动采普通货物；主蛇Collect只在当前货物格按采集速率/余容量取料。clone移动不吞模块，但移动后按自身速率/容量取当前货物；Patrol不自动交付，Shuttle入Dock交真实货物。

输入读取离散方向/格/切点/行为/实体ID，预览读取同一规则；行动消耗、分身资格和事件次序可复算。主蛇直接反向进前一节禁止，长度2也不能借旧尾格例外反向；其它自己的旧尾格在不成长时合法，成长时旧尾不腾位。规则审阅发现的长度2反向例外已按原v0.1约束修复，对应正式Unity回归通过，不将旧源码行为当设计决定。

## 4. 可直接制作的循环与事务边界

1. 新轮显示固定地图、交付目标、行动预算、主蛇方向/有序节/当前能力、货物容量和可用模块；先展示无分身基础采集与交付。
2. WASD/方向键直接提交下一步方向，无额外确认面板；侧栏四向安全/成长/碰撞提示读MovePreview。身体真实跟随，按直接反向限制与旧尾是否腾位判断，不能凭缩短动画逃碰撞。
3. 采集只能领取真实地面模块/货物；模块追加身体后，同时改变长度、占格和能力。不能增长出免费能力，也不能满载后把地面货物删掉。
4. 合法切点预览保留段、移交段、切后能力/载量、货物去向及新小蛇行为。确认只转移现有节；新分身当步不免费行动，上限满时拒绝且状态不变。
5. 每个全局有效动作按公开次序提交主蛇与分身。分身使用两种短而公开的行为，无全图寻路；遇主蛇本步占位/墙/其他蛇时等待并显示原因，按稳定ID裁决。
6. 回收需主蛇头与分身头曼哈顿距离≤1、花1行动；先预告再确认，成功移除分身。实际所有节按分身顺序优先填库存，满则各模块留原节格；货物先填主蛇余容量，余量留分身原头格。不能无成本重新长回身体。
7. 到合法交付点交付真实货物，核对地面/携带/已交付总量；完成/失败给具体原因，可按同配置重试。新轮不带旧身体、货物、行动或收益。

预览、帮助、选择、复盘和无效菜单不推进规则；合法不移动命令也花1行动并让既有分身尝试任务。确认撞墙/未腾位身体/直接反向时记录碰撞和失败、花1行动并保存该已提交失败状态；非法切尾/回收距离不足/满模块库存等只拒绝，阶段/预算不变。交付最后一步先完成再预算是027实际合同，不由051类推。

## 5. 模块与货物守恒

每个模块有稳定唯一ID，同一时刻只归属主蛇、某一分身、携带模块库存或地面之一。切尾只是移动所属实体；回收只是移动模块/货物归属；拒绝、恢复、复盘、重复命令不改变总数。回收后的模块若未实施重新装身规则，就不能从库存免费获得身体能力。

普通货物守恒：8＝当前地面＋主蛇携带＋各分身携带＋已交付；本轮无货物销毁/弃置或现金。切尾先将货物保留到主蛇新容量，溢出优先给新分身容量，剩余落新分身头格；回收去向如前述。地面模块可同格多ID，也可在身体格下存在，主蛇Move只吞最低ID；放库存模块在头格不会当步自动长身。可见掉落与堆叠表现需从实际完整状态重建，不能静默丢物。

分身数量不增加全局行动预算；身体长度与能力取同一真实序列。货仓空间归属变化不能让旧货物同时留主蛇又进入分身，采集能力只作用于拥有它的实体。UI只读实际归属及净变化，声音只消费新事件。

## 6. 验收矩阵、黄金输入与体验去留

下列是本项目独立验收程序；对应Core规则及存储用例已在 [正式报告](evidence/test-results.xml) 32/32中通过，实际UI/动态与真人体验仍按开发记录待验。Core README记录合法生产命令与独立预期，不用任意改快照证明可达。

无分身完整路线由独立推导提供预期并采用为唯一黄金输入，对应真实Unity用例已通过。记U/R/D/L为 `Move(Up/Right/Down/Left)`，每个词都是一次新命令：

- 两预置共用A回合：`U,U,R,Collect,D,D,L,Deliver`，8行动交付2；B回合：`U,U,R,R,R,R,R,Collect,U,L,L,D,L,L,D,D,L,Deliver`，18行动交付2。A×2再B×2共52行动、交付8、余28；无分身、模块归属不变，两货物点清空。B返程经 `(6,4)→(5,4)→(4,4)→(4,3)`，短/长都不撞身。
- Long容量优化：A只走一回、到货物点Collect两次再交付，共9行动交4；B只走一回、Collect两次，共19行动交4。合计28行动、余52。速率仍2，减少的是往返，不是免费增加采集收益。

独立预期已由实际生产命令测试核对；不能把路线通过或相机图写成已证明长身/分身策略优劣。

可操作分身对照以Core README为权威：Short原地保留2节切出ID3，主蛇 `R,U,U,L,U,R` 停 `(2,4)`；Patrol后Wait×8跑完一圈停 `(0,0)`、携货2，主蛇 `D,L,D,D,L` 到 `(0,1)` 回收，满库存使ID3落 `(0,0)`、货物2转主蛇。若停车点之后改走 `D,Collect,Collect,D,L,D,L` 先把主蛇也装满，回收货物2同样留 `(0,0)`。Shuttle用同前6移动再Wait×10交2并继续循环。对应实际生产命令规则测试通过，不用篡改快照造样本；这些动态画面仍未验。

- **SNK-A01成长**：记录成长前后身体ID/占格/次序、地面模块减少、能力和容量；无模块移动不得增长，吃入模块的旧尾格例外需边界样本。
- **SNK-A02切尾**：合法切点前后模块集合相等且归属互斥；主蛇能力立即减少，分身只持实际移交节。补切后降载的真实货物去向，不允许免费复制或隐藏丢失。
- **SNK-A03两分身/冲突**：先通过合法动作达到两分身，再尝试第三次切尾，状态/预算不变且有上限原因；分别验证墙、主蛇本步格、另一分身和同物竞争的稳定等待次序。
- **SNK-A04回收**：验证相邻/不相邻、空/满载、载模块/货物两类去向；成功删除唯一分身并花行动，溢出可见，重复ID/恢复不重复得料或增加能力。
- **SNK-A05基础保底与复现**：同图无分身的合法采集/交付完整路线；短/长蛇、1/2分身的路径/碰撞样本，同配置同动作终态/预算/事件一致。
- **保存与输入边界**：生产命令导出恢复全字段、非法新档不提交、坏主档/唯一有效备份、中断/写失败、恢复/重试/新局与同帧动作隔离；UI预览、暂停、复盘不收费或推进分身。

真实玩家假设分别登记：SNK-H01主动短体/切尾；H02通道/目标变化会改变身体次序或任务；H03能解释失去哪段能力、为何值得以及回收成本。当前固定一图只覆盖其中有限样本，不宣称已证明通道变化的全部体验。长身/两分身恒优、无分身无解或小蛇管理负担重时先修基础规则，不扩科技树。

## 8. 完整保存与工作顺序
