# 051 回收保洁队：首次可玩候选实施方案

版本：v0.2；日期：2026-10-10（Asia/Shanghai）。状态：首次可玩候选已实现并只读核对本项目Core/API/初值、黄金路线和Runtime绑定；Prepare成功、实际EditMode28/28通过，最终构建与相机证据已归档，原生操作与听感待验。分项事实见 [开发记录](2026-10-10-slice-01.md)，不称完整纵切验收。

## 1. 授权、依据与本轮范围

用户授权首批其余项目逐个开发；本轮助手采用各项目合同的首次可玩纵切范围。032已单独提交/推送，本轮只做051，单项备份后再接续；首次纵切阶段、顺序和参数不是用户逐项指定。默认遵循 [共同规范](../../../DEVELOPMENT_STANDARD.md)，使用Unity2022.3.62f3c1、Windows x64普通Mono Strict包/PC单机，Steam仍是后续目标准备。

依据是 [需求v0.1](../../design/first-batch/proto-051-recycling-cleaners/requirements.md)、[设计v0.1](../../design/first-batch/proto-051-recycling-cleaners/design.md) 和 [项目DEVELOPMENT](../../../prototypes/proto-051-recycling-cleaners/DEVELOPMENT.md)。沿原案051容量与再利用版本，保留二维俯视原稿与工作簿位置；不恢复元素战斗方案。

本轮助手实施建议：一个离散网格房间、三类污物、两类回收料、两刷头、共享桶容量和一个有限滤芯；三维斜俯视房间只表现网格状态，不增加物理吸尘、流体、角色自由漫游或地摊投圈。通过同布局的小/大桶、同容量的两布局、滤芯开/关和两刷头对照验证取舍。没有成长、商店、员工、敌人或多房间解锁。

## 2. 有限题材与规则权威

包装为“清晨回收小队：把废料留给下一次清洁”。一名清洁员在开门前整理活动室，普通回收料可出售腾桶，可转化料可留给本轮后续顽渍；“下一次”不指带资源跨新轮。只用开场/目标/结算短句，无人物分支、配音要求或局外剧情系统。

- 开场建议：“晨班开始。先看桶容量，再决定这堆碎料留给谁。”
- 滤芯说明：“留下一份可转化料，换下一处顽渍的清洁剂。”
- 无滤芯说明：“不开滤芯也能清完；你要多花几次基础擦洗。”
- 结算建议：“房间清好了。看看哪些材料卖了，哪些变成了下一次清洁。”

Core独占地图/初始污物、材料标签、位置/可达目标、桶容量、刷头覆盖/稳定顺序、滤芯配方/额度/清洁剂槽、动作/耐久/财务、完成与失败、事件和快照。已只读核对 [Rules.cs](../../../prototypes/proto-051-recycling-cleaners/game/RecyclingCleaners/Assets/RecyclingCleaners/Core/Rules.cs) / [Session.cs](../../../prototypes/proto-051-recycling-cleaners/game/RecyclingCleaners/Assets/RecyclingCleaners/Core/Session.cs)，规则 `0.2.0`、快照格式 `1`；[Core README](../../../prototypes/proto-051-recycling-cleaners/game/RecyclingCleaners/Assets/RecyclingCleaners/Core/README.md) 维护逐步黄金输入。UI、场景、存档、测试和本摘要只读同一版本，不另建近似配置。

规则负责代理给出的冻结初值已与代码核对，均为v0.2助手实施建议，不是平衡结论。下面只作摘要，不建立另一份可编辑配置，不把032金额/步限或013成绩当051参数。

- 房间6×6，补给/出售/腾桶点 `(0,0)`，障碍 `(4,2)` / `(4,3)`。`Compact`：普通碎屑 `(1,0)`4、`(2,1)`4；可转化碎屑 `(2,0)`4；水渍 `(1,1)`2、`(3,2)`2；顽渍 `(3,1)`3，共19单位。`Separated` 污格按 `(5-x,5-y)` 镜像，固定障碍与补给点，仍19单位。
- 桶容量小6/大12；初始行动80、耐久48、资金6。两类材料共享桶容量，普通料总8、可转化料总4；水/顽渍不凭空成为第三类料。
- 每次移动正交一格，花1行动/0耐久，不穿障碍；作用目标为角色自身或正交邻格（曼哈顿距离≤1）。窄头只覆盖目标；广头以目标为中心的含中心十字，排除障碍，按离角色距离再格ID `y×6+x` 排序，不把宽覆盖当额外自由距离。
- 窄头吸取至多2、水渍至多2、顽渍基础至多1，花1行动/1耐久；广头十字覆盖、每格至多1，花2行动/2耐久。换头仅补给点，花1行动/1耐久。
- 出售/弃料仅补给点，花1行动/1耐久；出售一次清空桶中两类料，普通每单位卖1、可转化每单位卖2。弃料指定一类/正数量且足额，无收益；无料/超额/无变化拒绝不扣费。
- 滤芯可任意位置开关，花1行动/0耐久；每2单位旧可转化料→1剂，整轮最多3次、剂槽容量2。手动转换任意位置，须滤芯开启，花1行动/1耐久；吸取前自动至多一次，附加1耐久、不额外加行动，本步新料不递归转换。清洁剂单目标清顽渍至多3（不随广头扩范围），耗1剂/1行动/1耐久。
- `Restock` 仅补给点，花资金3/行动2，将耐久恢复到48；不补滤芯、不增加行动。耐久0仍可按合法移动返回补给，不立即判失败。19污物全清即成功并结束；有效末次清洁先判完成，再判剩余行动耗尽，有残污且行动耗尽才失败。结束后未售桶料不自动变现，所有领域动作停止，新轮不带入库存/现金。

Core README已冻结两布局的无滤芯窄头完整黄金路线，两种桶容量都可执行各自同一序列。以下是独立推导的预期，对应生产命令用例已在本次真实EditMode28项中通过，不是平衡或真人体验结论：

- Compact：先普通/水，回供给出售普通6；再收可转化4/剩普通2，回供给出售；最后邻格擦顽三次/水一次。累计29行动/13耐久，余51/35，钱包22、桶0、剂0/滤芯额度3，已售普通8/可转化4。
- Separated：经x=3列到远区，收普通4/可转化2并擦水，回供给出售；再到远区收剩普通4/可转化2，擦顽三次/水一次即完成。累计38行动/12耐久，余42/36，钱包14、末桶普通4/可转化2，剂0/滤芯额度3。末桶未售不是免费结算收入；两路线现金差同时含材料去向差，不据此断言布局单独降低单位售价。

逐步移动格/作用目标以及最后有效动作的生产输入以Core README为权威。后面的最小容量样本刻意从邻格吸取，不是黄金29路线前缀；两样本预算不可混账。

API读取与所有权：`Session.CreatePrototype(LayoutKind, bucketCapacity, filterEnabled)` 建立独立初态，默认Compact/小桶/滤芯关闭/窄头；`Retry()` 使用该轮初始布局、容量和初始滤芯开关，不把后来开关当初态。`State` / `ExportSnapshot()` 返回深拷贝，`PreviewCoverage(x,y)` 返回按规则排序的格ID。`Move(dx,dy)`、`SetBrush`、`Vacuum(x,y)`、`Scrub(x,y)`、`UseDetergent(x,y)`、`Convert`、`Sell`、`Discard(material,amount)`、`SetFilter`、`Restock` 返回 `CommandResult` 并可带幂等命令ID；失败不提交，重复成功ID返回AlreadyApplied且无新事件。

## 3. 从进入到重试的循环

1. 选择固定布局与桶容量，读取剩余清洁量、预算、两类材料/共享空间、刷头、滤芯和出售/腾桶点。
2. 按合法网格移动、选择真实作用目标与刷头，预览覆盖和动作成本；选择本轮将出售还是留作转换的材料。
3. 吸取、基础擦洗或使用有限清洁剂；按规则确认的实际污物减少更新画面，显示入桶/残余/阻塞与成本。
4. 容量不够时选择合法出售/丢弃/有限转换，工具状态和位置限制公开；不得在菜单里免费腾桶或补给。
5. 每次有效动作完成后先更新清洁完成，再检查剩余预算/耐久。最后有效动作能完成目标时成功优先；失败给原因和本轮材料去向。
6. 可重试同一配置，或更换一个条件独立对照；新轮从该配置初态开始，不带上轮材料/清洁剂/现金。读取检查点只继续已存的一轮。

一次吸取先校验目标/刷头/成本及可发生的效果，再按Core稳定覆盖顺序处理。滤芯开启、旧可转化料/配方/额度/产物槽合法且付得起附加耐久时，先转换已有材料腾空间，再接本步新料；本步刚入桶的材料不递归再转。附加耐久不足时退回普通容量吸取，不拒绝原本付得起的基础吸取；若普通桶仍满才阻塞。装得下多少才减多少，装不下的碎屑仍在格内。空目标、非法位置和整体失败不先减污物/钱/预算再撤销。

出售、丢弃、转换、清洁剂使用的物料去向互斥；已出售/丢弃材料不能合成，已消耗清洁剂不能重新卖为原料。宽刷的多个格按同一容量顺序提交，不复制新料；顽渍有公开基础擦洗路径，滤芯不能成为唯一钥匙。实际规则次序以Core合同为准。

## 4. 可直接执行的对照与黄金输入

每轮记录配置/规则版本、初态、逐条合法命令、位置/目标、事件、剩余污物、两料/共享容量、清洁剂/滤芯额度、行动/耐久及现金。一次对照只改变一个条件；黄金输入从公开规则独立推导，实际XML/终态另验，截图不是路线证明。

- **CLN-A01容量**：同布局、同刷头/滤芯关闭，分别初始化小桶/大桶；使用相同吸取覆盖序列直到小桶满，比较实际入桶与场内残量。满桶无空间时碎屑不继续消失；大桶仅改变可存量，不能凭容量提升单位收益。
- **布局对照**：固定桶容量/刷头/滤芯，分别初始化布局A/B；污物总量和种类匹配，目标坐标/路线按各图重新记录。比较回收点往返/主动避料/留料，而非把地图坐标差异当随机噪声。若总量不同先归一或标明不同，不能宣称仅改布局。
- **CLN-A02滤芯**：先用关闭滤芯的基础工具完成公开普通/顽渍样本；再在同配置开启滤芯，收同批可转化料，检查配方扣料、剂量/额度上限及后续顽渍效率。无合法配方/无槽/额度零时回普通容量规则。
- **CLN-A03用途**：从同一合法已收材料安全点开两个隔离样本：一份出售，另一份转换再使用。核对现金/原料/清洁剂/场内污物各自去向；不能先卖再用同料合成，两分支只用于QA不写回实际主档。
- **CLN-A04刷头**：同初态、同目标分别窄/广刷，比较覆盖格/稳定顺序、行动/耐久、装料和残余；换头、出售/丢弃也计成本。保留容量刚够一部分宽覆盖的样本。
- **CLN-A05末动作**：使用公开配置下的生产输入让最后有效清洁恰好完成目标，成功应先于预算耗尽；相同初态/命令序列复现终态，不追加一次免费动作。

三组可直接输入的独立推导补充；本次测试已覆盖对应容量/刷头/用途规则，以下给定序列逐步验收仍应单独记录，不能用汇总通过数替代：

1. 容量最小样本：Compact、无滤芯、窄头，`Vacuum(1,0)`两次 → `Move(1,0)` → `Vacuum(2,0)`。两容量此时普通4/可转化2、已用6、余行动76/耐久45、残污13、现金6；再 `Vacuum(2,0)`，小桶整体拒绝且不扣费/不减污，大桶收可转化2，已用8、余行动75/耐久44、残污11。
2. 同目标刷头样本：从初态目标 `(1,0)`，窄头一次Vacuum收普通2；广头先在供给 `SetBrush(Wide)` 再Vacuum，覆盖十字收普通1/可转化1，连换头花3行动/3耐久。区别是覆盖/材料构成与成本，不把单纯数量相同说成没有差异。
3. 互斥用途样本：Compact小桶初态 `Move(1,0)` → `Vacuum(2,0)`两次，得到可转化4；由该合法检查点分别独立恢复。出售分支回 `(0,0)` 后Sell得现金8/桶清空；转换分支先 `SetFilter(true)` 再Convert，得到可转化2/剂1/额度2、现金仍6。出售后Convert不能重复用旧料；转换后不得出售消耗的那2单位，两分支都计自身移动/开关/动作成本。

以上是验收程序；具体坐标、每步预期值及成功路线由Core README的黄金动作补足，不使用任意修改快照绕过生产路径来证明可达。玩家是否主动换路线/留料、没有升级是否想继续，分别属于CLN-H01–H03，不用上述测试数量代替。

## 5. 三维样件、反馈与操作

建议房间为暖晨光、蓝白工具车、奶油地砖/暖木边、有限生活道具和带桶/工具的清洁员。普通碎屑灰方片/可转化料灰圆环，水渍蓝色不规则浅片，顽渍暖色刮痕；这些形状是助手包装建议，三类污物/两材料身份仍归Core。模型负责代理用原创C#程序网格/材质制作，作者源、尺寸、资源映射和哈希独立登记；未生成/未导图不称美术通过，不假称已做Blender/FBX。

## 6. 完整安全点保存

只保存已提交动作完整状态：规则/格式/布局/配置身份、初始与残余污物及材料标签、清洁员位置/刷头、共享桶两料、清洁剂/滤芯开关与额度、行动/耐久、清洁完成/阶段、财务/分类成本、事件/命令序号与幂等记录。不得只保存完成百分比或桶容量。

Core `ExportSnapshot()` → `RoundSnapshot`；静态 `TryRestore(snapshot,out Session,out string)` / `ValidateSnapshot` 校验状态范围、材料互斥去向、滤芯/剂量、现金、耐久和阶段，再从同布局/容量/初始滤芯初态生产命令重放，全字段比较状态及事件。恢复不重复清洁、出售/转换、不回预算/耐久、不重抽地图或带新轮资产；`LastEvents` 为空，历史可看但不重播收益声。表现重建已提交状态，不以动画当存档真值。
