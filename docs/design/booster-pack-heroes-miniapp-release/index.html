06完整计划书

Booster Pack Heroes 小游戏移植、广告变现与发行计划书

版本：v1.0｜归档日期：2026-11-18｜目标市场：中国大陆｜首发：微信小游戏；抖音随后验证。

本计划依据用户“后续改成小程序版本上线，上线前接入广告，包含发行推广，调研并制定计划书归档提交”的要求制定。用户已明确确认微信先行、抖音随后，并说明已取得商业改编授权，授权范围后续补充。执行按授权移植路线筹备，授权合同原件、结算比例和账号信息在私有材料中登记。

当前交付是调研与执行计划。 现有还原工程尚不能凭编译和托管检查宣称完整可玩；本轮未接入真实广告、未申请账号、未提交备案、未购买流量或发布游戏。工作量、预算、指标均为本项目建议，除注明官方来源的条件外，不是平台承诺或已实测成绩。

1. 建议采用的总路线

先用既有 Unity 2022.3 工程恢复一个可独立验收的完整循环，再用微信官方 Unity/WebAssembly 适配方案验证移动设备。首版建议纯广告变现，先实现两类自愿激励视频权益，插屏保留实验开关，Banner 默认关闭。完成资质、小游戏备案与小程序备案、隐私和平台健康系统检查，真实广告验收后小流量发行。微信数据成立后，再接抖音平台 SDK、视频分发与独立商业配置。

在一个版本里同时追求完整 PC 复刻、全部长期内容、两平台首发和多种付费，会使未知问题相互叠加。首个可发行版本应交付一个有完整成长目标、完整结束与恢复、足够验证七日留存的独立内容单元。完整移植仍在后续路线图内，缩小首版不是永久删减承诺。

必须先解决四件事：

  1. 玩法审核路径：现有“金币购买随机卡包”应先按微信运营规范 §3.2.5.2 核对；不能因为金币不是人民币，就自行认定允许。默认提审候选改为明示内容的固定包或自选包，随机付费、广告换随机抽取、虚拟币间接抽取暂不进入候选。[S09]
  2. 备案路径：微信区分有虚拟支付和“当前及未来均不需要虚拟支付”的路径。只说首版不付费不足以替用户作后一种长期声明。正式填表前确认产品支付策略及本作授权改编、境外权利链的适用材料。[S07][S10]
  3. 技术闭环：可玩循环、WebGL 真机、存档恢复、移动 Shader 与字体、暂停/恢复分别通过；不能由 Windows 构建推出小游戏可用。[L01][S01][S02]
  4. 现金闭环：真实广告完成回调和奖励只证明功能；平台账单、结算与发行/版权分成才决定可用现金。广告金单独记账。[S06][S08]

2. 已有基础、差距与证据边界

现有项目位于 prototypes/re-booster-pack-heroes。2026-11-18 读取的项目合同 v1.2、顺序还原报告和证据记载：本地静态资料已整理，Unity 2022.3.62f3c1 的还原候选曾编译并构建 Windows Player；另一个还原批次完成 27 批、47 个源文件的联合编译及 162 项纯托管检查。GameManager、现场依赖切换、完整流程、真实输入、存档 I/O、听感和移动端性能仍需整合与验收。旧报告中“三库待授权”的描述已被合同中的后续授权覆盖，不能照旧重复询问。

上述是现有记录的快照，本轮没有重跑这些游戏检查，也没有读取真实用户存档。单独可编译的方法、结构一致或 Shader 字节码对应不等于完整游戏可玩。开始执行前重新冻结源码、依赖和规则版本，登记实际可玩状态；本地来源摘要见 L01。

归档期间另一个倒序还原任务仍在推进，已只读核对其独立进度报告。27批/47文件是原顺序协作批次的快照，不是还原项目的实时全局总量；本计划不修改正在还原的源码、队列或测试，后续工期以执行时冻结的最新基线重新估算。

本轮只读确认本机 D:/Program files/2022.3.62f3c1/Editor/Data/PlaybackEngines/WebGLSupport 存在；这是模块目录检查，不是 WebGL 编译、插件兼容或真机通过。原 Windows 安装约 542 MB，不能直接作为首屏下载包；首场景、字体、贴图、音频和章节必须分层装载。

本作可迁移的体验骨架为：开包/收集反馈 → 组队与自动战斗 → 战败结算或胜利 → 升级与再挑战。静态配置中的战斗段约 36–98 秒，只能用来形成移动节奏的初始假设，实际时长要用可玩版本测量。保底、图鉴、技能树和多货币经济可作设计输入，不能把 PC 配置不经修改整体搬入广告经济。

3. 产品定位与首版范围

目标用户假设：喜欢收集成长、短战斗和可反复尝试的轻中度玩家。传播卖点优先展示“打开一个明确奖励包后，阵容如何变化”“换一个英雄能否守住下一波”，避免用赌博、财富兑现或虚假稀有率作为吸引点。中文名、图标与原英文商标的关系，以授权文件和平台核名结果为准。

首版内容候选为：一个完整主线章节、约 10–15 分钟首次体验、可支持七日重复游玩的成长目标、8–12 个有清晰定位的英雄、3 类明示内容的奖励包、有限升级分支、图鉴、任务与设置、正常胜负、重试、退出恢复、客服与隐私入口。它是工作量估算单元，正式数量在可玩审计后冻结。保留后续章节、转生和旁支的扩展位置，不提前承诺未制作的内容。

移动设计按横屏优先进行真机验证：保留战场读图空间，主操作区适配拇指触达和安全区；用点击确认、短按/长按反馈替代鼠标悬停说明。竖屏先做纸面/布局样件对比，只有启动转化或可读性明显更好且改造成本可接受时再改方向，不同时维护两套正式布局。

建议体验目标：60 秒内完成一次有意义的开包/选英雄与战斗反馈，前三分钟不展示广告请求入口；教程可跳过并可复看；拒绝非必要隐私授权、无广告库存或主动跳过广告时，仍能完成正常成长循环。时间目标是内部验收建议，不能为了满足平台激励的累计时长要求人为拖延流程。

本轮没有取得本品类的实时市场规模、竞争排名、竞品后台收入、买量报价或真实玩家偏好。因此不作“蓝海”“必然高 eCPM”判断。执行期先选微信 2 款、抖音 2 款现存同类产品，以真实平台身份和试玩日期记录首屏、教程、首个广告、七日目标、广告频次、失败恢复与创意一致性；没有体验的产品不得填入已测竞品结论。官方 Unity 转换案例只证明技术采用情况，不用于推断本作市场表现。[S01][S03]

4. 平台与技术决策

微信：主交付平台

官方适配文档覆盖 Unity 2018–2022 及团结引擎，通过 WebAssembly 转换并提供 C# 平台 SDK。现阶段保留已安装 Unity 2022.3.62f3c1 做验证，不先升级或迁移引擎。[S01]

当前官方安装入口为 wechat-miniprogram/minigame-tuanjie-transform-sdk，以及文档给出的 UnityPackage；旧 minigame-unity-webgl-transform GitHub 页面本轮显示已停用。后续通过官方入口选择稳定版、固定版本与 SHA，并核对许可，不从未核实镜像取二进制。微信后台需开通“能力地图—生产提效包—快适配”。Stable 开发者工具、真实 AppID、资源 CDN 与小游戏项目配置均需准备。[S01][S02]

官方快速开始建议只放 Loading 场景，其余场景通过 AssetBundle/Addressables 按需加载；它所称包内首资源“总上限 20MB”属于该适配路径描述，不能推广为所有普通小游戏、所有分包的统一限制。上传时重新核对当前工具与后台校验。[S02]

抖音：微信验证后的第二平台

官方方案同时有仅 Android 的原生 APK 沙盒和覆盖 Android/iOS 的 WebGL 路径。为复用微信优化结果，优先验证 WebGL；若 Android 性能不足，再比较原生方案，保留独立目标配置。两者都需要完整测试，不把原生 Android 方案写成支持 iOS。[S03]

抖音官方指南要求去掉其它平台商业化 SDK，注册游戏时“Unity 引擎”选择不能与普通小游戏方案任意互换。建号选型要在验证报告之后。官方该指南的首包约束和参考包体只适用于该方案，不能代替微信限制，也不是本项目已达到的性能结果。[S03]

适配工作包

  • 规则与流程：冻结可玩核心，广告奖励经应用层事务处理；场景、动画与 SDK 回调不直接加金币或改存档。保留旧 PC 规则与新商业规则的独立版本及迁移说明。
  • 平台隔离：建立登录、广告、存储、配置、遥测、分享与客服适配边界；PC 原 Steam/AppID、成就、UGS 和 Cloud 路径不进入小游戏构建。平台凭据仅留安全配置，服务端密钥不随包发布。
  • WebGL/AOT：验证反射/泛型裁剪、序列化、UniTask、DOTween、计时与协程；逐项替换注册表、原生 DLL、文件系统假设、阻塞同步 I/O、不可用线程/API。原 DX11 Shader 需要移动/WebGL 实际重建和视觉对比。
  • 资源：按启动、首局、章节、图鉴分组；裁剪未使用语言与字体、审核商业字体，贴图压缩分 Android/iOS 验证，限制透明叠层与特效。首次加载成功后再预下载后续内容，失败可重试，缓存必须有版本与容量策略。
  • 输入与视听：刘海/挖孔/手势安全区、不同长宽比、大字和色觉辅助、静音/来电/蓝牙切换、广告后音频恢复。实际播放与听感单独记录。
  • 生命周期与保存：onShow/onHide、广告覆盖、网络变化、进程被杀统一经过暂停/恢复。独立产品存档命名空间、schemaVersion、检查点与迁移，不访问 PC 真实存档。
  • 轻量服务端：登录 code 换取平台身份、配置签名、广告奖励票据/去重、匿名事件与可选云档。先单区域部署，限流、备份、权限与监控齐备；不为首版搭建跨服、实时 PvP 或复杂中台。

建议内部性能预算：约定中低端 Android/iPhone 机型和受控 4G 条件下，首次可操作 P95 ≤ 8 秒、缓存后二次启动 P95 ≤ 4 秒；首场景必要网络下载 ≤ 12 MiB；低档设备战斗帧率 P95 帧时间 ≤ 33.3ms；30 分钟压力运行无持续内存增长与系统杀进程。设备内存预算在原型测量后设定，暂以总占用 P95 ≤ 350 MiB 作为探索目标。以上不是官方限额，失败应优化或下调支持范围，而非删掉失败样本。

5. 广告变现设计与接入

5.1 广告开通和发行前验证

微信官方 2026-04-09 页面给出三条可选开通路径：[S04][S05]

  • 累计独立访客 UV 大于 500，无刷粉且无严重违规记录；资格通常次日刷新。
  • 开通内置游戏圈并有真实有效活跃，发布官方帖 5 篇。
  • 同公司主体名下已有满足条件的小程序：已开通流量主、从昨日开始持续一个季度有变现、无违规记录；迁移主体还有建议等待时间。

它们是路径条件，不代表本账号已经符合。不能购买虚假用户、组织刷广告或自动点击来达标。本轮没有访问登录后台或核实主体已有资质。

把“上线前接广告”定义为正式发行和买量前，真实广告组件与奖励闭环必须通过。先完成模拟广告和接口测试，同时核对能否用既有主体或其它合法路径获得真实广告单元。若后台必须先产生发布后的真实访问，先记录平台条件并制定单独的合规低流量验证发布方案；当前计划任务不授权执行发布。若用户要求任何公开访问前都必须有真广告，则条件未满足时继续内部测试，不自行先发无广告版本。

5.2 广告位候选与经济边界

首版建议仅开两个激励位，其余保持关闭待数据与审核：

  1. 结算额外固定收益：正常结算先完成并保存，再由玩家自愿观看领取明确数量的额外资源。奖励参数记录为确定值，不抽取，不奖励解锁章节所必需的唯一道具。
  2. 明确内容的补给/试用：展示固定材料、自选英雄或限时试用的完整权益。不得出现“看广告抽稀有”“用广告币买随机包”的间接链路；即使是固定权益，也需按最终界面和整体经济参加审核。
  3. 离线收益加成：后续有真实离线收益系统后再实验，保存时间以服务端校正和封顶处理；当前不能为了增加广告位虚构离线收益。
  4. 失败复活：仅作为后续实验，先证明失败—升级—重试循环本身成立；不改变付费/非广告玩家公平边界，复活次数和战斗状态可恢复。

建议起始频控：前三分钟与教程内不提示激励广告；两次激励入口至少间隔 120 秒；每日最多 6 次完成奖励。频控和奖励量是实验初值，不是行业标准。插屏仅在结算后的自然转场、小流量且通过审核时实验，建议间隔至少 180 秒、日上限 3 次；不在开包、战斗、登录或广告刚结束时弹出。Banner 默认关闭，避免遮挡和误触。通过远程开关关闭广告后，核心循环仍应可继续。

建立正常产出、广告额外产出、资源消耗和内容进度的统一账本。用无广告、每日 2 次与每日 6 次三组策略模拟七日，检查成长速度、难度、货币库存和卡点；建议广告额外资源不超过正常活跃日可得主要资源的 30%，若造成强制观看感，即使收益更高也下调。确定奖励不得被随机包装或广告文案重新解释。

5.3 SDK、回调与奖励事务

微信使用官方激励视频组件及 Unity SDK 桥接，先核对基础库兼容与事件行为；API 文档写明基础支持版本、默认单例和可选多例设置，不能按普通小程序的页面生命周期直接套用到小游戏。[S06]

建议广告流程为：有资格的玩家点击 → 冻结本次确定奖励和事务号 → 加载/展示 → 平台明确完成事件 → 校验/去重 → 提交存档 → 展示奖励结果。取消、提前关闭、无填充、加载失败、展示失败和超时分别处理，不把 onShow、页面返回、计时到期或一个 Promise 成功当作完整观看。

事务号至少关联匿名用户、平台、广告位、奖励规则版本与本次机会；服务端对同一事务只接受一次提交，客户端落盘记录已领取状态。广告播放前保存正常游戏进度；奖励确认和领取记录在同一次检查点内提交，重复回调、重复点击、重连补发与重启不重复发奖。未知结果保持待核实并提供恢复入口，不自行补成“已完成”。

防作弊边界：本轮没有核实当前 SDK/广告位是否提供服务端观看验证。执行时优先接入官方提供的验证能力；若无可用验证，服务端票据只证明去重、限频和会话一致性，不能证明用户真实看完视频。此时按客户端可伪造的风险设计低价值、不可交易奖励和封顶，保留日志核对，不宣称服务端已完成观看鉴真。具体 onClose/isEnded 等字段按届时官方 Unity SDK 与广告事件文档逐项复核。

抖音使用抖音独立广告单元与官方 SDK，不把微信 SDK、广告位 ID、收入或身份映射直接复用。先确认 Unity C# 接口和实际 Android/iOS 支持，再实现同一业务接口。[S03][S14]

5.4 广告验收清单

覆盖正常完成、提前关闭、无库存、加载/展示失败、弱网超时、切后台、来电、重复点击、回调乱序、重复回调、场景退出、奖励提交前被杀进程、提交后未展示奖励时被杀进程、跨日频控、配置更新、撤销非必要同意、静音恢复和存档失败。真广告用平台允许的测试路径验证，禁止开发人员点击自己的正式广告以制造收入。

建议放行条件：确定性故障注入的取消/失败零误奖、同事务零重复奖；完整观看的真实回调和奖励账本可追溯；首批人工受控案例零丢奖，扩大后故障率低于 0.1% 的业务目标需按实际样本给出置信边界；P0 丢档、越权发奖和无法退出均为零。后台广告单元状态、真实展示、平台收益报表与最终到账分开登记。

6. 资质、版权、内容与合规路径

6.1 主体与授权留档

优先采用可持续运营的企业主体作为计划假设，真实主体由用户现有账号决定；不假定用户已有某公司或可代签。本轮用户已确认商业授权，接下来做范围留档与平台材料核对：权利人法定名称、完整授权链、地域、微信/抖音小游戏、广告/IAP、代码与媒体改编、中文名/商标、推广素材、发行商转授权、独占性、授权期限、撤销与停运、数据责任、分成基数和审计。第三方字体、音乐、插件仍需逐项核对，原作授权未必涵盖第三方的再次分发。

小游戏名称、权利主体、营业执照、软著/授权书和提交截图保持一致。微信规范对多主体提交同一授权游戏和唯一上线主体有明确约束，不能把有授权推成可以任意多包、套壳或无限主体上线。[S09]

6.2 微信 IAA / IAP 分路

官方接入资料区分 IAP 和 IAA，小程序备案页面分别引导情况一/情况二；小游戏备案是 IAA 前置审批的一部分。小游戏备案页说明：已有对应版号批复文件的游戏走相应路径，无需再提交该项小游戏备案；未有对应版号且确认“当前及未来均不需要虚拟支付”的情形按情况二指引办理。[S07][S10]

因此：建议纯 IAA 是商业方案，实际填报哪条路仍是待确认决策。 不承诺未来永久免费后又通过外部充值变相开 IAP。若未来需要内购、去广告购买或其它平台支付能力，先重新核对产品承诺、版号、实名、平台支付和备案变更路径，再立项。不得把广告方案等同于所有类别均免版号。

Booster Pack Heroes 为既有作品的授权改编，仍需核对权利来源地、改编程度、主体与出版/备案要求。由发行/法务准备完整事实说明向平台或主管部门确认适用路径；不能通过改中文名、重画美术或注册国内软著自行改变作品属性。没有收到适用结论前，做技术和内部测试，保留对应公开发行检查点。

官方小游戏备案页称平台初审一般 1–2 个工作日，主管部门一般 10–20 个工作日，修改/驳回后可能重算；小程序备案指南的 IAA 情况二约 10–30 个工作日。它们不是本作保证时限，也不要机械相加为一个固定工期。[S07][S10]

官方区分单机、联机的备案放行时机。本计划为便于发行与买量核验，建议正式发行前两类备案均闭合，这是项目自身更保守的放行条件，不把它写成官方对所有单机小游戏的统一规定。广告、云档和埋点是否影响具体分类，以后台和主管部门定义为准，不凭“没有 PvP”自行认定单机。[S07]

6.3 健康系统、隐私与内容

微信官方说明：不开通虚拟支付时，平台已统一协助接入中宣实名系统；开通虚拟支付的企业另按系统注册、添加游戏、渠道绑定与同步流程完成。执行任务以核实平台配置、健康系统表现和适龄提示为主，不另建不必要的身份证收集系统。抖音须单独核对，不把微信渠道完成结果复制为其它渠道已完成。[S11]

梳理平台身份、设备/崩溃信息、进度、广告事件、渠道归因等数据的目的、接收方、保存期限、撤回/删除入口。微信文档要求非 wx API 的个人信息处理也披露，在处理前完成相应告知/授权，并兼容拒绝；不能因为改成自有 HTTP 埋点就绕过声明。[S12]

仅按法律义务和实际服务需要处理数据，非必要分析和营销用途在同意前不启动；平台必要调用与法定处理依据分别核对。用户拒绝非必要处理时保留基础游戏路径。不要向分析平台发送手机号、身份证、广告内容截图或完整存档；平台标识按最小权限访问，公开报告只放聚合结果。保存期限、删除响应目标和备份清理在执行期经法务确认，不凭计划书代替正式隐私政策。

本作需逐项审查随机包、商店、原配置中的老虎机/赌运表现、骷髅/血腥、任务文案和所有语言残留。被排除的涉赌候选不只隐藏按钮，还要清理可达逻辑、资源、图鉴和营销素材。概率披露不能自动使被禁止的抽取形式合法；若保留不涉及投入的随机掉落，也需说明来源、概率/保底和公平规则并核对适用政策。[S09]

准备版权与健康忠告、适龄提示、备案/批准信息展示、真实客服、投诉/删除通道、授权声明与内容自审。抖音自审页可作辅助清单，其具体资质及适用豁免仍须读相应平台正文和账号要求，不能把一张通用自审表当作本游戏全部准入结论。[S13]

6.4 本轮规则覆盖

本轮以中国大陆微信/抖音为用户确认范围，未把其它国家法规作为首发准入任务。官方 IAA 激励页有 2026-10-23 变更记录，属于本次过去 30 天观察窗口 2026-10-20 至 2026-11-18；其余较早页面作为现行页面/历史基线分别登记，不写成近期新规。监管机关原文、境外授权游戏的具体路径、抖音资质细则和后台实际权限有覆盖缺口，详见来源登记。上线前由法务或主管平台作适用确认，本计划不构成法律意见。

7. 数据、归因与实验

先建立漏斗：素材曝光 → 点击/入口 → 启动 → 首次可操作 → 教程完成 → 首场战斗 → 首次结算 → 首次成长 → 次日/七日回访。广告漏斗独立为：符合展示资格 → 入口曝光 → 自愿点击 → 请求 → 填充/加载成功 → 展示 → 完成 → 奖励提交。两者用合法的匿名身份与会话关联，不能只看展示量。

埋点至少包含平台、客户端/规则/奖励配置版本、匿名用户、会话、来源场景、合法渠道参数、事件时间、事务号与结果码。关键事件为 launch、first_interactive、tutorial_complete、battle_start/end、pack_open、upgrade_commit、save_commit/recover、ad_offer/request/load/show/close、reward_commit、privacy_choice、support_issue。收集范围与隐私声明保持一致；事件中不记录原始敏感资料。精确字段和去重键见结构化执行数据。

留存按北京时间自然日定义：D1 为注册/首次有效进入当日的独立新用户中，次日再次有效进入的比例；D7 同理。排除测试/异常用户，保留剔除规则；按平台、操作系统、付费渠道/自然量和版本分组，不能把便宜自然量与昂贵买量混成一个均值。收入按该用户 cohort 累计可归属的现金收入核算。

建议探索门槛为教程完成 ≥ 75%、首场结算 ≥ 70%、D1 ≥ 30%、D7 ≥ 10%；稳健体验目标为无崩溃会话 ≥ 99.5%、受支持设备核心流程无 P0。它们是内部起始决策线，不是查得的行业平均。首轮至少 500 名独立新用户只用于暴露大问题；判断留存最好获得 1,000–2,000 名同口径新用户并等待完整七日，低于样本门槛标为方向信号。

实验先选一项：确定奖励形式、广告入口时机或频控；固定版本、随机分组、预定分析窗口。A/B 判断样本由基线、最小有意义差异和检验功效计算，不能因为每组几十人就认定提升。广告组 D1 相对无广告对照下降超过 3 个百分点或投诉明显增加先停查；广告参与不是强制达成的 KPI，不为提高参与率损伤主流程。

8. 收益模型、预算与现金安全

8.1 统一口径

广告收入先使用平台分成后的可结算现金 eCPM，单位元/千次有效广告展示。平台页面的流水口径与后台结算口径可能不同，必须用实际账单映射。采用该净口径后，不再重复扣微信基础分成；若拿到的是平台前流水 eCPM，则先换算再代入。

日展示/DAU = 每日可选机会 × 主动选择率 × 填充率 × 展示成功率。

现金 ARPDAU = 日展示/DAU × 现金 eCPM ÷ 1000。

贡献 LTV90 = 90 日内人均活跃天数 × [现金 ARPDAU ×（1 − 合同追加分成占比）− 每活跃日可变服务成本]。

完成率用于检查奖励和体验，不在按有效展示定义的 eCPM 收入上重复相乘。发行与版权分成按真实合同的基数和扣除顺序计算；模型中的统一占比只是示例。贡献 LTV 还未覆盖固定开发成本、税费和资金成本，不能称净利润。

附带计算器提供保守/基准/乐观三个假设场景，没有使用本游戏真实收益或竞品报价。基准示例：5 次机会 × 55% 选择 × 90% 填充 × 90% 展示 = 2.2275 次展示/DAU；净现金 eCPM 40 元时 ARPDAU 为 0.0891 元；再假设合同追加分成 20%、每活跃日服务成本 0.006 元、90 日内活跃 7 天，贡献 LTV90 为 0.45696 元。它说明买量价格稍高就可能无法回本，不代表预计就能赚到这个数。

放量条件建议为：以可追溯真实收入计算的 D30 已实现贡献回收率 ≥ 70%，且保守 LTV90/CPA ≥ 1.3；同时用留存和后续收入区间验证推算。CPA 是每个去重有效新用户的现金获取成本，包含创意/代理变动成本。未满 30 日时只能在预先限定的实验预算内学习，不能宣称回本达成。不能用当日 ROAS、预估总流水或一次高 eCPM 判断长期盈利。

8.2 现金与广告金分账

微信现行概要给普通 IAA 现金激励基线 50%，特殊类型和 CPS 有不同规则。广告变现激励页说明，自 2026-08-20 起的部分适格获客用户可选择 1–30 天广告流水 40% 或 1–180 天 35% 的广告金激励，并有累计活跃、渠道、回流与重新归因条件。[S08][S15]

这些数不能相加为保证到账的 90%/85% 现金。广告金有用途、主体、期限与结算限制，创意/优选等也有专属规则；本作未获得特殊资格。预算基础场景不计任何未核实补贴。实际后台确认后，广告金只进入“可抵未来投放成本”的独立台账，不当提现、不能与现金花费重复报销。

现行概要写 IAA 现金半月发起结算、约 13 天到账；广告金另按 T+2 发放，通常有 365 天有效期。全部以本主体合同与当前后台账单为准，计划按 6–8 周可支付运营与测试支出保留流动资金，不把激励到账时间视作无条件保证。[S08][S15]

8.3 分阶段预算建议

预算按现金支出预留，单位人民币。结构化数据提供三种档位并自动加 10% 预备金：精简约 2.2 万元、基准约 5.72 万元、扩展约 11.33 万元。包括法务/材料外部支持、测试设备/真人测试、服务/CDN、推广样片及创作者样测、微信买量实验、后续抖音验证。

这些是预算假设，不是供应商报价或已批准支出；不含商业授权保底金/版权预付款、可能另行发生的出版申报服务、公司设立、员工薪酬和税费。助手承担的开发和制作仍需计入工时与机会成本，不能把这些工作记为零成本利润。正式版号路径如适用，单独询价和重排期，不能塞进材料整理小额预算。

先验证技术与准入再解锁推广费用。建议首轮微信探索买量封顶 5,000 元，单日上限 500 元；达到质量与归因检查点后再启下一档。不得因为流量没有跑满就自动追加预算。连续三天同口径数据明显低于探索门槛、重大广告/存档故障或归因无法解释时停止新增投放，保护原用户服务。

9. 发行组织与合作方式

建议先由助手完成产品、SDK、素材和数据准备，保留自发行能力；在可玩真机与首轮数据形成后，再比较联合发行。 若既有发行商能提供已核实的主体、合规、渠道和买量资源，可提前纳入，不假设已有合作或免费资源。

自发行需要自己掌握 AppID、广告账户、域名/CDN、素材、数据、客服与结算，操作和资金责任更集中。联合发行可以提供买量与商务能力，但需核对独占期、收益基数、成本回收、数据透明度、素材及游戏改编权、服务 SLA、最低投放承诺和退出迁移。不能只比较一个分成比例。

发行合作尽调清单：

  • 确认微信/抖音是否分平台授权、是否与原作授权的转授权和独占条款相容；真实主体不一致时补齐平台材料。
  • AppID、广告位、用户身份和存档归属写清，域名/CDN 与代码仓访问最小化；不直接交付账号密码或无限期管理员权限。
  • 明确收入是平台前流水、平台后现金还是扣除买量后的利润；创作者 CPS、代理费、税费、版权费和坏账/退款的顺序可复算。
  • 每月提供后台账单、投放消耗与归因报表，有审计、争议、停止新增投放及存量服务条款；设置预算上限和不达标退出机制。
  • 合同到期的存档/数据迁移、用户告知、素材下架、结算尾款与服务交接有具体时限。

准备发行资料包：中文一页产品介绍、定位与差异、真实真机短片、可试玩版本和版本摘要、授权材料目录、准入清单、设备性能、留存/广告漏斗/收入数据、内容更新节奏、所需资源和预算。未有真实数据的栏目写“未测”；不把现在的还原截图、概念图或模拟点击当正式实机素材。本轮仅准备方案，不联系发行商或创作者、不发送文件。

10. 推广与内容计划

10.1 微信首发

围绕三个低成本触达方向准备：微信游戏圈内容与真实反馈、视频号/其它已授权内容渠道的实机短视频、平台可申请的自然推荐或适格合作能力。用户分享和订阅均为自愿，不用奖励诱导朋友圈分享，不用“分享成功”回调发资源，避免频繁拉群或客服骚扰。[S09]

付费测试优先腾讯广告中适配小游戏的可用场景，具体版位、定向、回传接口、出价目标和预算由广告账户权限与现行政策确认。本轮未获得可执行账户报价，不填写伪造 CPM/CPC/CPA。初期以合法的新用户进入和有效首局为优化信号，收入数据足够且归因一致后再评估价值优化。上报事件须与平台文档、隐私声明及实际触发一致。

10.2 素材生产清单

先做 12 条样片：3 个真实玩法主题 × 2 种开头 × 2 种时长。主题为“明确奖励让阵容发生什么变化”“一波失败后做出哪项升级”“两种英雄搭配的差异”。建议 15 秒与 30 秒版，前 3 秒给出可见目标，中段保留实际操作，结尾使用真实进入方式。

每条记录素材 ID、构建/规则版本、脚本、源录屏、配音/音乐许可、字幕、画幅、投放平台、审核状态和效果。微信与抖音各按后台实际规格输出竖版、横版或方版裁切，不把某个画幅当全部版位统一规格。中文名、图标、简介、加载页、商店截图与落地玩法一致；不使用虚假按钮、无依据的“爆率”“稳赚”“官方唯一”、原作销量或未经确认的背书。

优胜素材按点击到首局、次日留存、有效广告与现金回收共同评价；高点击但进入后流失的素材先查内容误导，不只放大点击率。每周淘汰差创意、保留完整原稿和投放结果，每个迭代周期只改一个主要假设。

10.3 抖音随后验证

官方 Unity 指南强调视频入口、锚点与分发能力；这说明需要独立的视频内容与归因规划，不是“微信包换个图标即可发行”。[S03]

抖音先安排技术回归和官方账号内容样测，再核对当时可用的游戏锚点、游戏发行人/达人合作、直播与投流资格。拿到可用权限后给每个创作者独立素材与追踪参数，声明广告合作关系，防刷量并按有效结果结算。具体佣金、计划入口、保证金或开放门槛目前未实核，不写成已具备的渠道。

两个平台分别计算素材、获客成本、留存与现金 LTV；微信的 ROAS 不能直接当抖音收益预测。若微信不过体验或收益检查点，抖音的新增买量保持关闭，但可继续低成本技术准备。

10.4 上线后 90 天

前 7 天每天检查启动、首局、广告/奖励、崩溃、客服和资源供应，优先修复，不频繁改全套经济。第 2–4 周每周一个可回滚版本，围绕教程、确定奖励与频控开展受控实验。第 2–3 月根据完整 D30/D60 数据决定内容扩张、抖音验证或缩减投入；新增章节、旁支和长线活动先有制作成本与可达性验证，不以日历活动制造无限内容负担。

准备客服知识库和处理记录，覆盖广告没奖励、丢档/换机、隐私删除、未成年人反馈、加载失败与内容投诉。建议工作时段 24 小时内首次回应，严重丢档或越权问题当日升级；这是服务目标，正式客服能力在发行前落实。节假日投放前安排值守，不能无人值守扩量。

停运也是发行计划的一部分。微信现行用户运营规范要求如确需停运，至少提前 60 天告知，并对未消耗资源妥善处理；执行时按当时政策和本产品实际支付情况处理，保留安全漏洞紧急处置与正常商业停运的区别。[S09]

11. 排期、资源与检查点

以执行启动日 T0 为相对时间，不承诺现在已经开工。建议安排 12 周的工作窗口：

  • W1–W2：路线与风险验证。 冻结授权材料目录和支付策略，确认备案及随机包路径，审计核心循环，建立最小微信真机样件，启动资料筹备。
  • W2–W5：核心可玩与手机化。 完成关键流程整合、输入/布局、资源分层、移动渲染和保存恢复；产出可独立游玩的首版内容单元。
  • W4–W7：广告、数据与服务。 并行筹备平台能力，集成模拟及真实广告、奖励事务、隐私、健康系统检查、遥测与归因；投放账户只做准备。
  • W6–W8：候选验收和素材。 设备矩阵、故障、内容审核、素材生产、客服和回滚演练，完成官方要求的材料和审核整改。
  • W9–W10：合规小流量验证。 仅在准入、审核、真广告、隐私和质量检查点通过后进行；收集完整七日数据，决定修改还是进入下一档实验。
  • W11–W12：数据复盘与第二平台。 微信优化、发行合作评估、抖音技术与内容样测；若数据成熟，再申请阶段预算。D30/90 收益观察会自然延伸到此窗口之后。

结构化工作分解为计划单一任务清单，包含依赖、负责人角色、工作量、产物、验收和拟保存证据：执行数据；任务清单与 HTML 由它生成。总人日和各角色分布以该数据汇总为准。估算是职责工作量，并不意味着当前有多个人或已启动子代理。

12 周估算需要约 2–3 个等效角色容量穿插推进。按每周5个工作日，145人日÷60工作日约为2.42个等效容量；单一容量串行至少29周，建议预留30–36周并单列外部等待。人日是角色任务量的人工等效估算，不是助手实际运行小时的换算，须在W1按实际吞吐重估。助手承担协调、研发、设计、素材、QA、运营准备与归档；身份核验、签署、付款、账号最终权限和主管部门审核只能由有资格主体完成，助手准备全部可检查材料和操作清单，不虚构外部条件。

资质与技术两条路径并行，发行时间取两者的较晚值：正式发行时间 ≥ max（核心内容与真机广告验收完成，主体/授权/适用备案及平台审核完成）。若需另走出版审批、版权补充或大规模重做，重排期，不用 12 周窗口承诺审核结果。第 1 周结束必须用已发现缺陷重新估算。

六个检查点：G0 路线材料可执行；G1 完整可玩且微信真机成立；G2 广告与数据可核对；G3 准入、内容与发行质量齐备；G4 有效七日数据允许继续实验；G5 真实现金回收支持放量/第二平台。只有本计划归档已完成；这些生产检查点当前均未通过。

12. 发布、回滚与运营技术清单

发布候选固定客户端提交、规则/奖励配置、内容与资源清单、SDK、平台 AppID 和隐私版本。开发、体验、审核与正式环境分开，服务端密钥、调试菜单、作弊入口和测试广告位不得进入正式配置。版权原件、授权附件和账号敏感数据私有存储，不提交公开 Git。

审核包与上线包一致，记录真实页面、功能说明、隐私、适龄、备案信息及审核反馈；不通过远程配置向审核和普通用户展示两套违规内容。配置更新只能在已审核能力范围内调整，不能通过热更新规避代码/内容审核。[S09]

拟定滚动发布：内部体验 → 受控真机 → 正式小流量 → 质量观察 → 阶段扩量。平台是否支持百分比灰度、测试广告和审核预览，以实际后台为准；不能假定任意百分比可控。用户下达执行和发布授权后，才完成相应实际外部动作。

回滚准备包含上一可用代码包和 CDN 不可变版本、兼容当前存档 schema 的配置、广告/投放/功能紧急开关、资源回源和维护公告。不能只回滚客户端而留下不兼容存档。建议每个候选演练一次关闭广告、停止新增投放、恢复正常结算和从隔离备份恢复；紧急开关目标 15 分钟内生效是内部 SLA，先验证缓存和离线行为。

监控覆盖启动失败、资源下载/CDN流量、崩溃/内存、会话中断、广告填充/展示、奖励提交、存档失败、异常发奖与客服投诉。预算和服务可用性有告警，异常时停新增投放并保留核心游戏服务；不通过删除真实用户数据或停止全部服务代替修复。

13. 风险、待决策与第一步

最高优先级风险是：随机包设计不适配审核；已获商业授权的范围与平台材料不一致；完整核心循环仍未整合；Unity 6 来源在 2022/WebGL 的差异；真广告开通存在前置条件；低端设备启动/内存；广告奖励或存档不一致；现金 LTV 不足覆盖获客。完整风险清单、触发条件和处置责任在执行数据中。

已经确定：微信先行、抖音随后；商业改编授权已取得，范围后续补充；本轮仅制定并归档提交计划。尚待执行前确认：最终主体及发行账户、授权文件的具体覆盖、长期支付策略、随机机制保留范围、支持设备、可投入现金/工时与自发行或联合发行条款。这些待决策不会阻断本计划交付。

建议执行的第一批工作为：准备私有授权/主体材料目录；核对纯 IAA 长期承诺和授权作品准入；冻结核心循环与缺陷清单；做一条“进入—确定开包奖励—战斗—结算—保存—退出恢复”的微信真机纵切；同时验证广告能力开通路径。G1 之前不量产全部内容或花大额推广预算。

14. 来源、更新和验收记录

来源登记与覆盖边界：调研来源。S01–S18 为官方平台页，S19/S20 为仅定位原文的监管背景，L01 为本地工程记录；其中有完整正文、有正文摘录、有仅导航/摘要，读取等级逐项标明。法律原文未完整复核的部分不冒称本轮法律结论。
