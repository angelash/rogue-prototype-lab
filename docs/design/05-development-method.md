# 原型研发方法

版本：2026-10-09 v1  
归属：助手最终修订建议；本次归档未实施原型。

## 每次试验的步骤

1. 写一句可证伪假设。
2. 限定能检验这句话的最小规则集。
3. 先验证基础动作与反馈。
4. 改变约束，并用删除规则做对照。
5. 基础选择成立后，再测试随机、补救和成长。
6. 记录实际行为和玩家解释。
7. 根据证据决定继续、转向或停止。

首批三个方向的具体范围与停止条件见 [原型验证计划](03-prototype-validation-plan.md)。

## 需要留下的证据

| 观察项 | 记录内容 |
| --- | --- |
| 误解 | 玩家误解了哪个物件、动作或规则，误解发生在何时 |
| 主动转型 | 玩家何时换一种做法，当时出现了什么局面 |
| 普通组件使用 | 普通组件是否有实际用途，用途是否随局面变化 |
| 失败归因 | 玩家怎样解释失败，解释是否符合规则因果 |
| 下次尝试计划 | 玩家下一次想改什么做法 |

用可复现种子与输入复现辅助复盘。结果判断同时看实际行为和解释；记录有助于区分规则失败、反馈误解与基础动作问题。

## 随试验逐渐复用

逐渐沉淀有序结算、输入复现、组件配置、容量反馈、回放和 UI 规范。每项复用应来自实际试验中的共同需求。

本版建议先完成具体试验，再积累这些能力；不先建适配全部方案的通用肉鸽引擎。31 个候选不等于 31 个并行开发项目。

设计游戏时，让有限规则持续产生值得处理的新局面。开发游戏时，让每次试验持续产生可以复用的新认识。
