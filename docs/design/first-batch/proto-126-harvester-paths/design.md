## 状态与三类地块

- `Field`：10×10 格，作物格、收割后地面、泥地；仓库作为普通地面上的功能标记，不新增第四类地块。
- `Harvester`：位置、四向朝向、基础切幅、燃料、载货上限及已装模块。
- `Cargo`：粮食和秸秆数量、各自单位占用，共享同一载货空间。
- `Order`：本轮需求、已交数量、总行动预算、剩余行动、截止结算状态。
- `Module`：滚轮、切割头、箱体三种候选的公开利益与代价。

建议作物格先收割再成为普通通路；泥地在基础机器下代价较高，但存在基础可行路线；铺秸秆后泥地变成临时可通行的普通地面。首版铺路在三轮内保持，避免另加耐久修路系统。

## 三种模块建议

首版每轮选择一种改装，不叠加全部优点。基础车始终有窄切幅、有限粮箱与基本通行能力。

- 滚轮：降低泥地通过成本，同时占用部分载货空间。
- 宽切头：一次覆盖更多前方作物格，同时增加转弯/操作成本，容易受到一次产物装不下的限制。
- 大箱体：增加粮与秸秆总容量，同时提高行驶燃料负担。

这些具体代价是建议，不是源文已验证的参数。比较模块时，除待检验因素外保持同地图、同订单和同基础资源；不能通过同时改变大量数值宣称某模块产生路线差异。

## 行动、燃料与截止

移动、转向、收割、转燃料、铺路、卸货、补给各自花公开行动。建议基础动作成本为一个行动，泥地/宽切头等额外成本由场景配置明确。返回仓库的路程由实际移动累计，卸货和补给另扣，不能把“回仓”记成免费按钮。

燃料与行动分别记账：燃料决定机器能否执行驾驶/收割，行动决定订单何时截止。转燃料消耗秸秆及行动，仅增加油量；仓库加油消耗行动和公开资源，也不改变总行动预算。

一次操作先检查行动、燃料、材料和容量 → 执行全部状态变化 → 扣成本 → 更新交付进度 → 检查目标 → 最后检查截止。最后一个行动完成的交付计入本轮。成本不足时整个动作拒绝，不先移车或先扣粮食。

## 收割与容量

收割范围由当前位置、朝向和模块决定。执行前预览每个目标格、粮食与秸秆产出和空间需求；首版建议所有产物能装下才执行本次收割。容量不足不收割任何格，提示玩家先转燃料、铺路或回仓卸货。

作物格收割后只产生一次粮食/秸秆并变为普通地面。转燃料和铺路分别消耗真实秸秆，不能重复花同一份材料。铺路指定相邻泥地，预览材料与行动成本，成功后显示通行改变。

宽切头的范围不可在同一动作中免费切成窄模式；若后续允许切换，必须公开代价并重新验证 H03。玩家可以选朝向或更稀疏的区域，处理容量压力。

## 仓库与三轮订单

仓库允许卸货、部分交货和补给。只有从货箱实际移出的粮食才能增加订单进度；同一份交付后不再留在车上。未完成订单按公开的部分收益和失败规则结算，不隐藏惩罚。

建议三轮使用同一地图并保留收割后的通路与铺路；每轮进入新订单时设置新的固定行动预算，不在轮内追加时间。初始作物总量与订单需求应保证至少存在基础可行方案，先用固定场景检验，之后再考虑随机生成。

## 反馈、场景与验证

主画面同时显示车辆朝向、切幅、地块变化和粮箱填充；侧栏把燃料、载货与剩余行动分开。路径回放标记每次停靠、装卸、铺路、转燃料及行动消耗，避免只看到一条移动线。

建议用一片靠近仓库的普通作物和一片被泥地绕行的远处作物，设置不同数量/截止要求。滚轮、铺路或大箱体可能改变返回与卸货安排；场景不预设某改装必胜。

先验证基本移动、收割、容量和固定截止，再加入秸秆两用与模块，最后跑三轮订单。检查 HRV-A01 至 A05，观察 H01 至 H03；与删除铺路、取消燃料转化的版本做对照。记录路线改变理由、装满时处置、主动部分交货及未达标归因。

未来规则层维护地块状态、车辆动作、产物事务、两类预算和订单；所有预览使用同一费用计算。首版用离散规则，不用真实机械模拟掩盖目标与路线问题。

待验证：铺路是否创造有效捷径，固定行动是否足够紧而仍可补救，宽切幅是否增加选择而非纯惩罚，三轮持续地图是否造成后一轮无资源。若存在固定逐行全清路线，先改订单与容量，再扩地块种类。
