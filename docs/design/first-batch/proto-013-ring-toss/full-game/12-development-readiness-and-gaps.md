# 开发准备度、缺口与补齐计划

版本：v0.4；日期：2026-10-09（Asia/Shanghai）。依据：用户明确要求后续开发由助手处理，并现在检查、整理内容和能力不足。主审计对象为 013 套圈改造摊；第一批其他五项的边界见第 7 节。

**结论：现有设计和本机工具足够开始基础原型，尚不足以宣称能交付完整游戏。** 最大缺口是实际 Unity 工程/测试/内容/资产尚未建立，以及真实 Player、玩家和发行条件尚未验证；不是缺一套必须先购买的制作软件。本轮补内容生产契约、缺失界面、音频/视频路线和可运行准备检查，并实际验证隔离工具探针。

当前用户决定是 Unity 本机版本、PC 单机、Steam 目标及助手承担开发。题材、参数、2.5D、生产预算和下列实施排队仍是助手建议；未因审计写成用户已经逐项定案，也不宣布本轮开始正式游戏实现。

## 1. 谁负责与怎样继续

助手负责需求细化、程序、数据与关卡、剧情全文、模型/图片/UI、音乐音效、字体与来源、测试、修复、桌面构建、商店资料和仓库备份。不能把“缺正式素材”“缺脚本”“缺故事正文”默认转换为让用户提供文件、作曲或操作编辑器。

后续实际开发任务开始后，沿该任务及已有授权完成必要实现、素材、检查和备份，日常参数/接口/文件组织自行判断并留下证据；阶段转换不额外增加确认手续。新的付费服务、安装、账户/签署和对外发行仍按实际任务授权判断。用户承担发行主体的真实身份和最终商业决定，不表示必须承担技术操作。

未验证项先执行最小验证；真实失败才记录阻塞。已完成设计、工具存在、工具样件通过、工程编译、玩家验收和平台上线使用不同状态。依据与原始版本见 [能力证据登记](../../../../../sources/references/development-capability-audit-2026-10-09.md)。

## 2. 当前能力的准确边界

- **能编写与执行本地代码**：Git/rg/PowerShell/Python/Node/.NET 可用，Unity 内置编译器/Mono 文件存在。独立 .NET 9 测试不得引入 Unity 不支持的 API/语言；建议规则兼容 Unity 的 .NET Standard 2.1，并以 Unity 编译和测试为最终证据。[Unity 2022.3 API 配置](https://docs.unity3d.com/2022.3/Documentation/Manual/dotnetProfileSupport.html)
- **Blender 基础链已实跑**：建模、保存源、FBX/GLB 与透明离线渲染通过；一个已登记码头候选加载通过。未完成 Unity 往返、功能模型、受控材质或正式美术验收。
- **图片通道可用**：内置 ImageGen 能生成/编辑二维图，当前 schema 不暴露 model 选择；六角色的一致性与透明边缘仍须实际样件。没有假设付费 image-to-3D 服务。
- **音视频编码已实跑**：WAV→OGG 与合成帧→H.264 MP4 通过。可自行合成与编排音频、剪辑字幕；音乐质量、循环和真实 Player 捕获尚未验收。
- **桌面操作有可见通道，但未走通 Player**：Windows MCP 命令服务成功并确认同工作区。Computer Use 的 Node REPL 初始化两次在 kernel 启动阶段失败；Windows MCP 截图/输入尚未实测。没有据此认定整个桌面或 Unity 无法控制。
- **准备检查已有可运行入口**：[脚本说明](../../../../../scripts/README.md) 中的环境清单与文档/源哈希检查已建立。Unity 构建、规则回放、资产导入和存档故障脚本仍需随工程实现，不把两项技能的格式通过当生产工具已完成。

## 3. 缺口登记：基础原型与一章纵切

每项记录“现状 → 补齐动作 → 完成证据”；负责人均为助手。P0 指进入基础原型时先做，P1 指一章纵切前后完成，不代表其余内容必须现在量产。

### GAP-01／P0：Unity 首次可运行工程

安装文件已有；工程、启动/许可、包解析、测试入口和 Windows 构建未验证。按 [08](08-unity-pc-technical-plan.md) 创建独立工程，先锁最小包、纯规则程序集及构建方法，记录实际日志。完成标准：本游戏编译、一个 EditMode 检查和最小 Windows x64 Mono 包成功，退出码与报告一致，参考工程未被修改。许可或包解析若实际失败，再按具体原因处理。

### GAP-02／P0：真正的规则与复现工具

闭式例账存在，真实接触/事件模拟和测试不存在。实现同一个 Core，接普通圈/风扇/反弹板，记录真实量化输入、事件和终态；测试覆盖接受边界、首个接触、重复处置与最后一圈顺序。完成标准：规则测试能识别错误结果，重复输入事件/金额一致，界面使用同一结果；测试资料与 [13 内容验证合同](13-content-authoring-and-validation.md) 对接。

### GAP-03／P0样本、P2全量：关卡数据及可达证据

03 是设计意图与基线，尚无正式标准/变体数据、每项风况/方向/候选映射及逐投证明。先做原型样本，再生产一章、最后十二模板；作者预览复用 Core。覆盖机关解锁 16 子集、特殊圈解锁的独立组合与合法预装，不用“初始/部分/全解锁”三组样例冒充全覆盖。在扩关卡/资产前计算组合数量、连续状态等价依据、求解成本与失败比例；全量穷举过大时建立可检查的结构/等价证明。若合法状态实际无解，显式修订 03/04 并回归，不能静默删状态或只替换成功样例。完成标准：每份发行布局关联配置摘要和足够普通圈达到冻结目标的逐投证据；连续状态按有限定义或等价证明处理，未证实组合不能静默发布。具体数据与覆盖合同在 13。

### GAP-04／P0首个Player：桌面输入与画面验证入口

目前有命令通道和一条启动失败的 Computer Use 路线，尚未操作本游戏窗口。首次 Player 建立固定测试场景、详细日志和截图导出；同时复验可用 Windows 控制通道，对唯一游戏窗口验证键鼠、焦点、暂停、返回和退出。完成标准：实际界面输入完成一摊并有窗口截图/事件记录，不能只调用领域命令绕过 UI。场景驱动辅助复现，不用于代替全部真实操作。

### GAP-05／P1：局外解锁与存档错误界面

原 05 缺工坊笔记页面，06 的异常合同尚无具体交互流程。本轮已在 [05](05-art-audio-ux.md) 补入口、成本/余额/生效时机、去重与恢复/写失败操作。后续实现验证所有六项解锁和冻结快照、备份恢复、无有效档、写失败重试；不增加金币互兑或当前摊重抽。

### GAP-06／P1：事务、恢复和故障注入

06/08 有协议，尚无实现。建立隔离存档路径、代次/清单与幂等提交；在写入、校验、清单提交边界模拟失败和进程中断。完成标准：恢复完整 Run/Profile，不重复发奖、还圈或改变资格，坏档和唯一有效备份保留。用模拟接口/隔离文件注入失败，不破坏真实存档或填满系统盘。Cloud 等本地协议通过后再做。

### GAP-07／P1：美术方向与 Unity 往返样件

工具链已通过，六角色/功能模型/正式背景未生产。先做一头像两表情、一分层背景、普通圈/风扇/板和字体测试页；选择受控材质与渲染小版本，再扩族。完成标准：单位/轴/枢轴、身份一致性、真实分层、功能轮廓、720p和低档画面均可读；替换素材后事件与现金相同。若三维导入/材质总成本过高，复用 Blender 源转精灵，采用一套发行路线。

### GAP-08／P1：音频生产及混音

五音乐/三环境/26事件已列数量，正式音色、循环、逐资产 seed、总线和生成/编码/测量脚本未生产。本轮 [09](09-art-and-asset-production.md) 补原创合成/编排路线与检查。先做章节循环、环境与代表性事件，随后全量。完成标准：编码和 Unity 播放一致，循环接缝/高频疲劳/同时触发不失控，静音仍保留信息；不是把合成测试音当成成品。

## 4. 缺口登记：完整内容与发行

### GAP-09／P1章文本、P2全文：可交付剧情与中文内容

01 的134行是预算和关键样稿，不是锁定全文；奖励/失败/替代提示、图鉴及稳定文本键未齐。助手按 13 编写全文、条件与文本资源，校对姓名/机关/变量，测试跳过、复看和奖励去重。完成标准：实际清单无丢键/变量，三章/成功/失败可走通；文档样稿和发行文本版本分别记录。

### GAP-10／P1首项资源、P2全量：正式资产和来源清单

候选来源不等于已审核发行文件。助手逐项建立 ID、作者/包、原文件名、实际许可/版权声明、参考谱系、源与成品 hash、修改/导入记录和审核状态。完成标准：所有 Player 引用都指向通过项，缺证据的候选不打包；不能靠“放进这个文件夹”自动填通过。字体需实际字形测试，OFL 通用条款不能代替字体版权信息。

### GAP-11／P1本机、P3目标环境：性能与设备覆盖

当前是高配置 Insider Windows 机器；最低配置、稳定版系统、物理手柄和第二台机器未确认。助手建立固定负载、帧时间/内存/加载、720p/1080p/宽屏与辅助截图；先在本机和实际可用核显路径测量，再用取得的目标环境复验。完成标准：每个承诺有注明 GPU/系统/质量/输入的 Player 记录。虚拟输入能测动作映射，但不能替代真实断连、Steam Input和真实低配性能。

### GAP-12／P1诊断、P2决策：真实新玩家验证

AI 自测可找规则和界面缺陷，不能证明首次玩家能理解、动作好玩或愿意重玩。助手制作测试包、说明、问卷和匿名记录，并分析反馈；真实参与者/接触渠道是尚未具备证据的外部条件，联系和招募按届时实际授权开展。完成标准按 04/07 的样本和理解门槛，未完成前写“缺玩家证据”，不以代理扮演玩家代替。

### GAP-13／P2候选包、P3Steam：打包和安装验证

暂无 BuildReport、版本清单/哈希、Development/Release 隔离、资源/许可证检查或真实 Steam 安装结果。助手随工程建立统一构建与打包入口，完整保存 Player目录和可回退记录。完成标准：干净目录与 Steam 下载所得包均可启动、离线完整、存档/输入通过，商店支持项与实包一致。

### GAP-14／P2：主视觉、真实视频和商店文案

没有最终游戏名/主视觉、实机截图、视频、商店介绍、支持入口或系统需求实测。本轮 09 补捕获和剪辑路线；助手制作原创包装、真实 Player演示、字幕/音乐与不同裁切。完成标准：演示展示真实机制、音画同步、来源可追溯；系统需求和功能标签依据实测，概念图不冒充截图。

### GAP-15／P3：发行主体与平台后台

Steam客户端存在，AppID/DepotID、发行主体、付款/银行税务和后台权限未确认。助手准备所需资料清单、文案、构建、调查表和可授权操作；真实身份、签署、付款及平台审核属于外部条件。完成标准是实际后台和审核记录；当前不声称存在账号资格或已上架。成就/Cloud是可选增强，声明前分别补对应证据。

### GAP-16／P2起：持续修复与发布后维护

设计有版本/回退概念，尚无真实缺陷、兼容升级、补丁包和支持记录。助手维护复现资料、存档迁移、修复回归、发布说明和版本备份；准备可用支持入口与恢复说明。完成标准：新包能处理上个已发布格式，已修复缺陷不复发，回退不会静默破坏进度。CI可在重复本地入口成熟后接入，不先要求云端 Unity 授权或平台密钥。

## 5. 现在已补齐什么、没有补成什么

已补：本缺口清单、13 的内容/验证合同、05 的解锁/异常界面、09 的音视频生产规格、开发责任和技能路由，以及实际可运行的准备检查脚本。Blender、音频/视频编码的隔离探针已有成功证据。

尚未补成：Unity 游戏、测试程序集、正式关卡/剧情文本、人物模型/图片、完整音乐音效、来源发行清单、玩家报告或 Steam包。这些按依赖逐步制作；其缺失不阻止先做 P0，也不能仅靠继续扩写文档消除。

Unity/Blender 专用 MCP、付费生图转模型、额外音频工作站、在线服务器与全局 NUnit CLI没有被列为开工必须安装项。现有命令/引擎测试与可见桌面工具先验证实际能力；确有功能问题再引入最小依赖。

## 6. 助手的下一批开发工作包

实施顺序建议如下，实际工期由首轮编译、模型往返和可玩验证校准：

1. **DEV-01 工程与命令入口**：Unity首次启动/编译、包锁、最小场景、测试/构建方法，得到最小 Windows包；关闭 GAP-01 的实际缺口并验证 GAP-04 通道。
2. **DEV-02 基础动作**：普通圈、六槽、真值与反馈、黄金输入/边界；接风扇和板，关闭 GAP-02 样本。
3. **DEV-03 一摊完整事务**：准备、投掷、互斥处置、冻结目标、末圈清算、失败与恢复，输出真实样本关卡和故障报告。
4. **DEV-04 一章纵切**：四摊、携带/商店/笔记、输入、剧情与代表性音画、实际 Player验证，完成 GAP-05 至08第一组及 GAP-09章文本。
5. **DEV-05 内容和玩家验证**：按 13 扩十二模板与全量文本/资产，逐项关闭覆盖、来源和可读性，开展真实玩家诊断后再校准数值。
6. **DEV-06 候选发行包**：性能/设备、宣传、版本/支持、Steam安装/后台与声明，按11放行。

每包交付可检查的实际产物和失败原因；没有把未具备的外部条件排成“明天一定完成”，也不要求用户写代码或制作素材。
