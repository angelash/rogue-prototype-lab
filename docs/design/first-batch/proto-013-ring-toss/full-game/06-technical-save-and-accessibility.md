# 套圈改造摊：技术合同、存档与非功能需求

版本：v0.2；日期：2026-10-09（Asia/Shanghai）。归属：实现前的技术设计建议，不包含引擎代码、工具安装或平台接入。

## 技术边界

游戏规则见 [02](02-gameplay-systems.md)，参数见 [04](04-economy-and-balance.md)，界面、输入及无障碍表现见 [05](05-art-audio-ux.md)。本文件定义这些系统如何保持同一结果，补齐存档、数据、性能、异常恢复和发布所需的行为合同。

引擎尚未指定。后续选择时检验二维碰撞、固定模拟步、键鼠/手柄、文本本地化、资源打包和可测试的存档接口；不因本设计先安装软件或创建通用框架。

## 系统责任与数据流

建议划分为内容配置、局流程、投掷模拟、经济事务、剧情状态、存档及展示七个职责。规则层给出事件和最终状态，画面与音效订阅事件；界面不另算金额、碰撞或耐久。练习、回放与正式局共用模拟，经济写入权限不同。

数据流为：读取版本化模板 → 生成候选 → 记录准备结果与冻结目标 → 接收发射输入 → 模拟有序事件 → 原子提交物体/耐久变化 → 处置事务 → 保存阶段边界 → 展示结算。

内容单位、圈型、机关和角色用稳定编号。参数变更产生新的配置版本，不用同一版本号悄悄改力、价格或命中容差。

## 最低数据定义

- `ContentManifest`：内容版本、参数版本、模板与资产编号、摘要校验。
- `Profile`：格式版本、设置、解锁编号、工坊笔记余额、已见故事/图鉴、教程状态及局外奖励领取记录。
- `Run`：局唯一编号、种子、章/摊进度、钱包、携带物、固定候选预览、已结算摊记录、局状态。
- `Stage`：stageId、templateId、unlockSnapshot、6 槽固定候选与实际新奖品、冻结目标、stageReceipts、基础剩余圈、补救普通圈余额、重圈/宽轻圈各已用额度、调整与补救次数、阶段、事件序号。剩余总圈只是派生显示；读档不得恢复特殊圈额度或丢失本摊解锁快照。
- `OwnedItem`：itemId、机关类型、sourceStage、prizePriceSnapshot、receiptEligible、剩余耐久、位置/携带状态、是否已处分。字段含义和资格使用 04 的同一名称；商店物件 sourceStage=null、receiptEligible=false，不按支付价抬高残值。
- `Throw`：本投唯一编号、圈型、角度、速度、开始配置摘要、输入序列、按序事件、最终状态摘要。
- `Transaction`：唯一事务编号、原因、钱包增减、合格收入增减、物件去向、所属摊与提交状态。
- `StoryState`：已见对白编号、章结算状态和结局状态；不直接改规则参数。

金币、圈数、耐久、笔记及调整次数使用整数；世界坐标、角度、力和时间写明单位。金额取整只在 04 指定的交易步骤发生，不让展示四舍五入反向影响余额。

## 剧情事件与领取边界

所有剧情事件带 eventId、runId、内容版本和已提交的事件序号；涉及摊位时加 stageId/templateId，涉及章节时加 chapterId。剧情系统消费事件后确定对白键和图鉴见闻，不自行更改圈数、金币、配额或耐久。

- `STORY_INTRO`：局流程创建新局成功或正式进入摊位后发出，以 introKind=run_opening / stage_entry 区分；带 storyId，摊位开场另带 stageId/templateId。摊位数据和配额可读后才排入该摊短开场，已见开场可略过。
- `STAGE_SETTLED`：局流程在摊处置、收存及经济事务提交后发出，带 settlementId、success、receipts、target 和已处分物件摘要；不在命中动画结束时提前发布。
- `CHAPTER_CLEARED`：局流程确认本章第四摊成功后发出，带 chapterId 和最后摊结算编号。笔记奖励属于经济/局外账本；事件只引用已领取事务编号，故事重复播放不再次领取。
- `RUN_FINISHED`：局流程提交第十二摊成功和最终物件清算后发出，带 finalSettlementId、结局对白键和局记录摘要。
- `RUN_FAILED`：局流程按 04 的最后一圈与补救顺序提交失败后发出，带失败摊、实际收据、目标及原因键；未结束的补救窗口不能触发。
- `STORY_SEEN`：剧情系统在一段对白实际展示完或玩家明确跳过后登记，带 storyId、结束/跳过状态；这是阅览状态，不能推进玩法关卡或领奖。跳过仍开放该段复看；尚未到达的段落保持未解锁。

同一 eventId 重复消费只返回已有状态。章奖励和通关笔记在局外账本中以 runId + settlementId + rewardType 唯一登记；自动续局档引用该记录，局内/局外档写入中断时通过同一事务日志补全，不能分别更新两份文件后把部分成功当成全部成功。

## 确定模拟与回放

04 的固定时间步是模拟步长；渲染帧率和播放速度独立。暂停不消耗圈或耐久，慢放不改变接触次数。一次跨越多个碰撞体需要计算首次有效接触与剩余子步，不能按渲染帧漏掉细板。

同一构建、同一配置和输入应得到相同事件序列与结果。仅有固定 dt 不能证明跨平台浮点完全一致；后续实现需选择可控数值精度、稳定排序和输入量化，再验证目标平台。首版只承诺已验证构建内复现，跨版本回放按版本处理。

随机来自显式种子，并按布局、奖励候选等用途分开记录。菜单开关、回放次数和画面帧数不消耗随机序列。发现配置摘要不同，回放显示“不兼容版本”，不在错误物理参数下静默播放并发奖励。

失败复盘包含输入、首件接触、机关方向、消耗、接受区拒绝原因和最终落点。保存近投完整轨迹和整局关键事件；长局历史需有明确容量上限和可删除入口，不无限占磁盘。

## 保存时机与防重复

主线建议设 1 个自动续局槽及独立局外档，允许导出/备份；手动“保存退出”落在最近的安全边界。安全边界为准备冻结后、投掷结果已提交后、奖品处置后、商店事务后及摊结算后。

确认发射时先保存该投编号与输入、剩余圈扣除记录，再开始展示。若飞行中断，恢复时从已保存的本投初态重放到相同结果，再进入待处置；不返还已扣圈，也不让重放触发第二次耐久或奖金提交。恢复界面说明当前继续的是哪一投。

每笔奖励、处置和商店交易只提交一次，提交记录随状态共同保存。先写临时档并校验，成功后替换当前档、保留上一份备份；失败保持旧档和待恢复提示。具体写入实现待引擎选择，不以先改内存余额、晚些再保存的方式制造重复兑奖。

清算完成前不能重复领同一件现金；摊已经结算不能回退再清算。局外笔记采用 `runId + settlementId` 去重；阅览已见剧情不会重新发笔记或金币。练习/回放模式永远不能提交正式经济事务。

## 版本迁移与损坏恢复

存档同时记录格式、内容和参数版本。升级时先复制原档再迁移，保留来源；不覆盖无法理解的同名存档。未知机关编号不能静默变成新奖品或高价物，提示兼容问题并提供备份恢复。

局外档可迁移已知字段。进行中局若与新参数不兼容，优先保留旧版本续局数据并说明可用处理，而非把旧局按新配额结算；新局采用新配置。错误选择恢复备份前明确显示版本与时间。

磁盘写失败、权限不足、空间不足和文件损坏分别给出可操作信息；尽可能保留当前会话和旧档。错误日志只保留版本、事务编号和原因，不记录用户私有路径之外的无关信息。首版无账户、网络登录或遥测上传。

## 输入、可访问性与设置

05 定义全部操作的键鼠/手柄路径、焦点和提示。本文件要求输入以“动作”而非固定键码保存映射；重映射不得让必要动作完全失去入口。切换设备刷新提示，不中断当前投掷事务。

可访问性配置包括文字尺寸、对比与色形冗余、减弱闪烁/镜头晃动、音量分类、字幕、按住/切换替代、瞄准慢调、暂停观察、轨迹辅助和教程重复。其作用按 05 实现，不能暗中改命中概率。

主线使用辅助不会扣经济奖励；本地挑战记录显式保存辅助配置以便自行比较。无声模式仍用视觉指出机关触发，色觉差异仍用形状/文字区分现金和留场。屏幕朗读支持若目标平台不能实现，应在后续范围决定中明确验证结果，不能仅因写了选项就宣称完成。

## 性能与质量预算

建议首发桌面目标为常见 1080p 布局下稳定 60 帧展示，物理按 04 固定步运行；低展示帧率也不能改变判定。最低硬件需以后续实机验证确定，当前不捏造配置。

单摊仅 6 槽与有限活动圈，资产按章节加载；短动作不必触发整屏高成本特效。建议安全边界保存以玩家不感到中断为目标，写入失败不阻塞已提交结果。具体帧时间、加载与档案大小在纵切阶段测量后定预算。

需要验证不同分辨率、窗口缩放、手柄断连、失焦、长暂停、低帧率、重复输入、非 ASCII 路径与坏档。游戏内所有文案以资源键管理，首版简体中文，后续语言扩展预留字长空间；不要把数字规则写死在文本图片里。

## 验收合同

- **TECH-A01**：同版本同输入重放，事件顺序、命中、耐久与钱包一致；不同帧率展示不改变结果。
- **TECH-A02**：确认发射后中断，恢复继续同一投且只扣一个圈；在兑奖前后中断都不重复得钱。
- **TECH-A03**：商店/清算提交后重复载入或确认，事务只生效一次；旧物来源与获取价格不被重新标记。
- **TECH-A04**：损坏当前档能恢复已校验备份，原损坏文件保留；版本不兼容有明确提示，不自动结算错误数据。
- **TECH-A05**：无鼠标、无音效、减弱特效及放大文字下，仍可从开局走到结算；设备断连可暂停并恢复输入。
- **TECH-A06**：练习、回放和剧情阅览不改变正式钱包、圈库存或领取记录。

以上为未来验证要求，尚无通过结果。完整制作门槛见 [07](07-production-and-validation.md)。
