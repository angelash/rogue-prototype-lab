## 1. 当前三维主路线与首组范围

1. **主路线：真实三维固定斜视地摊。** 场地、奖品、机关、圈和近处投掷手采用三维模型；六奖品在地面两排三列排列。相机固定在玩家后上方，投掷向前；规则三维位置、接受体、作用体与视图取同一锚点。轻覆盖 UI 显示状态与三个独立投掷输入。
2. **范围取舍**：只制作一个场地、普通圈、台扇、反弹板、棚、帆布、灯与少量支撑。无自由漫游，不新增实时对手、角色战斗或可探索街区；桑禾近处手/前臂用短投掷动作即可，六角色二维头像保留为可选对白/UI 的完整计划。
3. **生产理由**：低模的分部件转动能保持板面、朝向与规则一致，功能结构和皮肤可复用枢轴。固定镜头控制遮挡和小团队场景成本，同时保留地面纵深和实际前抛感。
4. **历史路线**：原二维占位和固定正交 2.5D 的结果保留作历史；不再把“全二维 fallback”作为当前主场景替换方案。模型可离线渲染 UI 缩略图，不能因此把真实三维玩法改回平面。
5. **先样件后全量**：首组通过实际三维视角的形体、输入、命中/机关锚点和帧时间核对，再扩十二皮肤、六机关与三章场景。方向成立不等于正式美术完成；已执行与待做项目由开发记录区分。

## 2. 与世界包装一致的美术规范

1. 首组采用暖色实体低模旧物、木/金属/帆布材质、条纹棚和河港夜市暖灯。三维道具使用清晰切面、稍夸张的关键部件、有限色板与少量补丁贴纸；纸片纹理可用于 UI/贴纸，不把主场景画成平面卡片。避免照搬参考工程的中世纪魔法装饰。
2. 桥脚暖黄/赭红、货站灰蓝/米白、江心冷水面/暖灯；功能标记沿用统一形状与线型。颜色变化只包装章节与皮肤，不改变价格、作用、碰撞或接受区。
3. 扇叶、反弹板面、罩区、滑槽入口出口、拨片正面和缓冲垫有效面必须在标准镜头可辨。铆钉、纹理和破损优先围绕这些部件安排，不用细节填满所有表面。
4. 统一固定斜视透视镜头、曝光和主灯方向。可选远景图片的光照不得与三维功能道具冲突；使用稳定色板、少量接触阴影和不干扰接受体的暖灯。远近透视不能靠隐藏接受区补偿。
5. 执行“背景低对比、功能物中对比、圈/接受区/输入焦点最高对比”。主圈轮廓、轨迹与作用区不受景深、雾、强 bloom、屏幕空间遮蔽或背景粒子影响。低画质能去掉装饰，不能去掉奖品、板面或命中标记。

## 5. Blender 路线：建模、输出与 Unity 接入

1. **输入规格**：每个道具先有资产 ID、功能、关键轮廓、三维场景/规则锚点与单位、04 的标量引用、运动部件、枢轴、材质数、三角面预算、标准屏幕尺寸和权利来源。普通圈、风扇、板面先以灰盒核对两排纵深和接触位置，之后再上色与旧物纹理。
2. **分层结构**：根节点 `VisualRoot` 不承担判定；下分主体、运动部件和贴纸。关键挂点如 `Pivot_Fan`、`Pivot_Board`、`EntryMarker`、`ExitMarker` 使用稳定名称。机关改变朝向时，视觉与规则朝向取同一配置，不从当前动画骨骼猜方向。
3. **建议预算**：功能道具目标 `600–1800` 三角面、上限 `3000`，每件优先一至二材质、最多三；圈目标 `128–512` 三角面、一材质。单摊最多六槽，功能道具几何上限因此为 `18000` 三角面。以上是助手初始预算，须用实际镜头截图与 Unity Profiler 校准，不能宣称已经达到 60 帧。
4. **材质**：优先共用木/金属/布三族色板和一张 `512–1024` 的可复用纹理图集。用顶点色时，Unity 显示材质必须确实读取该属性，不假定普通 Lit 材质自动还原 Blender 节点；可在选定管线用 Shader Graph 的 [Vertex Color 节点](https://docs.unity3d.com/Packages/com.unity.shadergraph@14.0/manual/Vertex-Color-Node.html) 接入。不要为每个 A/B 皮肤复制一整套不同着色器。
5. **主导出格式**：保存 `.blend` 制作源，向 Unity 提交显式导出的 `.fbx` 与所需 PNG 纹理；可保留未压缩 `.glb` 用于交换/预览。Unity 2022.3 官方建议生产使用 FBX，直接导入 `.blend` 会依赖每个构建环境中的 DCC；因此源文件与 runtime 导出分开管理。[Unity 模型格式文档](https://docs.unity3d.com/2022.3/Documentation/Manual/3D-formats.html)
6. **导出检查**：应用非必要缩放、清楚区分 Blender 到 Unity 的轴向转换；用一米标尺、左右标记和单个转轴先做往返验证，最终规则单位保持 1 Unity unit = 1 内部标定 m。清除额外相机、灯光、隐藏高模和无用骨骼；需要的枢轴不能被统一“居中”破坏。
7. **导入检查**：正常/切线、硬边、材质槽、透明模式、贴图色空间、UV、枢轴、尺寸及动画 clip 都要核对。FBX 材质转成项目的受控材质，不能依赖 Blender 复杂节点网络自动迁移；原始导出、Unity 导入和最终构建各留一张标准镜头截图。
8. **运行时**：低模网格与功能几何分工明确。功能接受/接触由登记的三维规则体计算并从同锚点展示；不因导入自动生成 `MeshCollider` 或更换皮肤而改变命中。动画只响应规则事件，背景装饰不注册功能接触；低画质停掉装饰动画仍得到同一回放结果。
9. **GLB 借用风险**：WoC 检查的七个候选模型均要求 `EXT_meshopt_compression` 与 `KHR_mesh_quantization`，部分还要求 `EXT_texture_webp`。v0.4 的隔离探针已成功将 `dock_platform.glb` 载入本机 Blender（1 Mesh、616 顶点、1 材质，原文件未变）；只证明该文件加载，不推广至所有候选或材质/外观正确性。Unity 导入尚未验证。优先从已获许可的作者原始 FBX/普通 glTF取得源，再导出本项目 FBX；具体来源与派生步骤逐项记录。

## 6. 图像生成路线：职责、输出与检查

1. **适合生成的资产**：六人基础头像及表情、可选远景底图、旧物的造型草图、补丁/无文字贴纸、少量装饰插画。主场景与功能道具保持真实三维；生成图不承担精确槽位、功能箭头、碰撞范围、真实数值、菜单按钮或文本字形。
2. **先锁风格基准**：从首组三维场景的暖灯、木金属帆布色板、旧物质感和实际镜头建立基准，再按 01 的服装、工具与轮廓建立六份角色卡。后续表情以已接受基础头像为编辑参考，锁住脸、发型、服装、视角和构图，只改需要的表情。
3. **道具概念图规格**：单物件、正面/侧面、完整外轮廓、无背景污染、无悬浮文字、不过度透视；用功能部件清单补齐图里看不到的背面与转轴。单图不能证明真实三维深度，Blender 建模仍须检查侧面和低视角。
4. **人物交付**：透明 RGBA PNG，源图达到 05 的至少 `768×768` 建议，导入前检查 alpha 边缘、工具袋/手指、表情一致性和角色区分。内置工具的实际输出尺寸以结果为准，再按源尺寸和导入质量确认，不能假设工具接受某个隐藏尺寸参数。
5. **远景交付**：只有三维场景确实需要图片远景时才制作，构图与斜视镜头匹配；它不代替地面、棚、实体奖品或投掷手。需分层时分别生成或编辑得到独立层，不把一张图宣称已经分层。远景不画六槽目标、接受区、数字或会被误认为可交互机关的高对比道具。
6. **贴纸与纹理**：图片可给补丁、布纹或旧纸的视觉素材；纹理用于稳定表面时要检查平铺、光照污染、边界与缩小效果。实际价签、中文与编号由原生文本叠加，避免生成乱码和字体不可控。
7. **单次记录**：资产 ID、任务类型、最终提示词、参考来源/权利、所用工具、实际输出信息、日期、SHA256、接受/拒绝理由、保留约束、编辑历史。模型 ID 只有工具实际返回才记录；未返回写“工具未暴露”，不能补填“image2”。
8. **成本控制**：一个资产或变体使用独立的目的明确请求，先小范围定风格、再扩同族。保留接受稿与必要来源，丢弃稿只留低成本联系图/原因。此处没有已核实的 API 单价、调用额度或生成时长，工时预算不能写成费用承诺。

## 13. 音频生产合同

用户随后要求优先选用 WoC 可用 BGM/音效，并参考 live-avatar；逐项审核优先于自制。当前选中的十四项均为项目限定、非商业或未清理许可，没有转用到本游戏，详见 [WoC 审核与七个原创原型音](../../../../../sources/references/woc-audio-reuse-register.md)。因此本轮先接原创短音，BGM/环境暂缺，继续由助手按合成/编排或有商业使用依据的素材补齐；不要求用户作曲或交音频。完整角色配音继续不纳入。

1. **作者源**：每资产有稳定 ID、所属事件/场景、音乐节奏/段落/音色或音效包络、逐资产 seed、采样率/声道、生成脚本/参数版本、WAV源、发行OGG及哈希。随机源按资产分离，生成顺序或新增一个音不会改变其他文件。
2. **音乐**：三章遵守 05 的60–90秒建议，标题/回顾另记录实际长度；先写有起伏的段落和可复用动机，不把短振荡器片段机械重复当成完整曲目。音乐总线独立，切章采用可听但不突兀的切换；淡入淡出不能替代首尾循环验证。
3. **环境循环**：三章的水、棚风、绳索/金属采用原创噪声与包络合成或有来源的单项素材，建立真实首尾拼接；不在未经登记风况变化时制造误导性阵风。检查短周期重复、首尾跳变及多次循环后的疲劳。
4. **事件音**：26个逻辑事件由提交事件映射到声音；相同功能用稳定音色/时值，区别命中与三种失手、兑现与留场。每圈/机关去重与并发限声只减少装饰声负载，不能丢失必需视觉文字反馈。优先保留命中/失手/状态/确认，重复贴面和背景装饰不压住操作。
5. **制作规格建议**：源为48kHz PCM WAV，音乐/环境可用双声道、事件音优先单声道；原始样件用16-bit已验证，正式精度按音色/噪声和工具统一选择。用现有FFmpeg编码Vorbis OGG，保存编码设置并解码复查；Unity的Load Type、压缩和循环设置按实际长度/并发测量锁定。
6. **混音**：Master下分音乐、环境、事件/UI，与05音量设置一致；暂停/回放的调整不触发新事件。记录峰值、响度与动态范围，代表性最大并发场景无数字削波，命中和操作可辨，耳机/扬声器试听并有静音替代信息。初期不编造游戏音量的已测统一LUFS目标。
7. **验收**：一条章节曲、环境循环与代表事件先在Player连续循环、暂停/恢复、跨场景和重复接触；再按05清点全量。波形/编码检查只能发现技术问题，不能替代听感及真实混音；实际记录试听方式与结果。

只读参考 highschool 的 [音频生成脚本](F:/workspace/highschool/tools/generate_audio.py) 思路。其旧项目路径/目录清理、短曲时长、循环处理和全局随机源不直接采用；由助手为本项目重写，不运行旧脚本或借旧曲目。09第11节的98–162人时不含这组音频，也不含下节商店视频，首组实作后分别校准。

3. 默认录制本游戏唯一窗口，再用FFmpeg剪辑、字幕和已审核音频混合；只核对实际游戏窗口，不录整个桌面或其他应用。[FFmpeg gdigrab](https://ffmpeg.org/ffmpeg-devices.html#gdigrab) 支持按窗口标题/句柄捕获，实际捕获权限、帧率与音频路径仍需本机验证。
4. 备用为开发Player从真实渲染导出帧序列，并记录时间/事件，再编码成视频；截图可用 [Unity ScreenCapture](https://docs.unity3d.com/2022.3/Documentation/ScriptReference/ScreenCapture.CaptureScreenshot.html) 的PNG接口。输出使用明确的隔离绝对路径；帧序列不是把Blender宣传动画称为实机录像，也不替代真实输入验收。
5. 验收包括录制版本与来源、掉帧/重复帧、音画同步、字幕校对/安全区、缩小可读、编码/播放和素材许可。发行主视觉与录像的实际采用文件进入来源记录；没有Player前不制作冒充截图的成品。

## 15. 本轮音频能力接入

用户指定的 [live-avatar 实读登记](../../../../../sources/references/live-avatar-audio-capability-register.md) 确认其能力是 MiniMax/Windows/Qwen3 TTS 接入、实时 PCM 分块、取消与错误处理，未发现 BGM/游戏音效生产入口或可归属成品。只借鉴方法，不迁入数字人和四服务部署。已有全局 MiniMax 文件技能可在未来可选短句任务中使用，届时核对区域、声音及输出许可；本轮没有读取密钥、调用付费服务或增加完整配音要求。

原型的七个 WAV 由 [本仓脚本](../../../../../scripts/generate-prototype-audio.py) 独立制作并按资产固定种子，可复现，原制作源保存在 assets/proto-013-ring-toss/audio/original/，Unity 采用副本放 Resources/Audio。它们提供投掷、命中、反弹、兑现、留场、失手和操作反馈，不能冒充完整五曲/三环境/二十六事件音或正式听感验收。游戏阶段与接入结果由 [开发记录](../../../../development/proto-013/2026-10-09-p0.md) 更新，三维画面转向不改变音频许可与完整配音范围。
