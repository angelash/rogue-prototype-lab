## 2. 关卡作者要交付的记录

以下是未来记录格式合同，不是本轮已创建的数据文件。工程建立后，运行内容按 08 放入 `Assets/RingToss/Content/`；作者源与派生产物须可追溯，运行、练习、回放和作者预览读取同一份已校验内容。

### 2.1 内容清单

`ContentManifest` 至少包含：

- `contentVersion`、`parameterVersion`、`simulationVersion`、`schemaVersion`，以及各份实际文件的摘要。
- 模板、布局变体、圈型、机关、皮肤、风况、文本、角色、资产与挑战预设的注册索引。
- 每份内容的状态：`draft`、`readyForValidation`、`validated` 或 `retired`，并引用实际审核记录。只有 `validated` 可进入正式候选；字段存在不等于验收通过。
- 参数引用指向 04 对应版本的同一份数据。展示价签、作者工具和回放不能维护另一组价格、接受区或作用参数。
- 已废弃稳定 ID 的记录。旧 ID 不得复用为另一件物品、另一段文字或另一份布局。

### 2.2 标准模板与有限变体

每个 `TemplateRecord` 至少包含：

- `templateId`、章序、摊序、名称文本键、教学标签、参数版本引用。
- 一个必需的标准 `variantId`；最多两个额外变体引用，沿用 03 的上限。初期可以只有标准布局，不必凑满三十六套。
- 六槽 S1–S6 的固定候选皮肤编号与槽位引用。实际三维坐标、接受体、接触体从同一版本化规则/场景配置取得；当前两排三列基线在 Core 三维入口登记。旧03/04单排XY标尺不得静默映射为新布局，本篇不新编坐标。
- 确定的 `windPresetId`，引用 04 本章允许的公开恒风值；“轻顺风/轻逆风”文字不能成为运行期自行选值的依据。
- 每槽留场转换所需的机关初始预设：类型、合法朝向与开关状态。04 已指定初始值的项目沿用该值；其他项目在允许集合中明确记录，不能由模型朝向、当前摄像机或上次 UI 状态猜出。
- 章节回款配置引用、剧情触发键、接受区/作用区显示引用、镜头安全区及必需资产集合。
- 标准布局及各变体对应的可达证据索引、输入窗口报告和发布状态。

一个变体是完整、固定的六槽候选与风况记录。种子只按版本化选择规则指向允许的变体；所选结果被保存。本合同不增加逐槽权重抽奖、临投随机或通过预装刷新奖品的机制。作者不得把“以后可以审核的变化”提前放进正式候选。

种子选择记录须包含实际使用的种子、选择算法版本、用途分流标识及选出的 `variantId`。当前没有给十二摊编造已经验证的种子；算法和记录在实现时由助手建立，并用同输入重复选择检查。

### 2.3 生成与冻结的顺序

1. 在本摊合法准备点取得并保存 `unlockSnapshot`，选择本模板的已审核变体，读取固定六槽候选。
2. 对未解锁机关对应的奖品执行 03 的确定性替换：奇数槽使用 PRZ-01，偶数槽使用 PRZ-02；皮肤主题按 03。替换使用实际品类的价格与功能，不保留被替换品类的价钱。
3. 接收 0–2 件合法自有机关预装，只覆盖所占槽的候选，其余槽不重排。取消预装恢复该槽原候选；包内未预装物不能在开摊后补装。
4. 预览根据剩余实际新奖品计算价值、04 的目标和基础圈数；旧钱包、旧残值和补救均不作为可行性收入或圈数。
5. 点击“开摊”才建立本摊正式新奖品实例并冻结目标、候选覆盖、初始布置、风况和圈额度。实例身份沿用 03 的局/摊/槽/出生序号。
6. 后续解锁按 04 的下一摊/下一局合法准备点生效；已保存的当前摊快照和候选保持不变。恢复读取保存结果，不用当前全局解锁重做映射。

未通过校验的配置在发行前不能进入候选。正式游戏已经开始准备时发现无效配置，按 03 保留候选并引导恢复合法布置；不得利用报错重新抽奖、临时加容差、降低目标或补圈。

## 3. 解锁与合法预装的有限覆盖

### 3.1 覆盖空间

初始风扇、反弹板始终开放。挡风罩、滑槽、拨片、缓冲垫四个机关解锁位有 16 种子集；这是由既有四项独立选项推得的有限审核空间，不是新解锁机制。每个模板的实际候选先经过该子集的替换，再检查预装。

重圈和宽轻圈的四种解锁组合单独验证 UI、额度、保存及教学资格。普通圈可达证据不依赖这些选项；若它们不改变候选、价格和普通圈物理，可共享同一可达报告，但必须记录共享依据，不能漏掉特殊圈未解锁时的完整基础圈数。

每个允许布局的预装覆盖包括：

- 不预装；一件在 S1–S6 任一槽；两件位于两个不同槽，并检查实例到槽的具体对应。
- 机关类型取当前解锁集合；朝向取 04 的离散允许集合；初始开关取允许状态；耐久取 1 至本机关最大值。
- 两件的 `itemId` 必须不同。现有规则没有禁止同类型的不同实例，审核不能自行增加“类型不得重复”的限制。
- 0 耐久是非法预装用例，检查拒绝且不占槽、不扣资源；可以收存或拆卖的资格保持 04 的定义。
- 包内另一件、旧价快照与旧钱包不改变实际新奖品或目标。证明普通圈回款时不使用它们筹钱补圈。

所有集合都来自现有规则，尺寸有限。审核工具应输出总组合数、已验证数、失败数、共享证明数及缺失索引；“抽几组看起来没问题”不能作为全部合法组合已通过的证据。

### 3.2 怎样减少重复验证而不漏组合

可以对经过证明的等价类共享证据，例如只改 A/B 外观、只改旧物价格快照，或已关闭且实体完全相同的耐久状态。必须证明这些变化不影响真实事件、实体、回款资格或调整预算，并列出该证据适用的全部成员。

开启机关的朝向、触发次数和耐久可能改变路径，不能仅凭皮肤相同合并。挡风罩稳定编号优先及本圈已付保护、两件实例的排列、有效/耗尽状态会影响事件时，也不得省略。

边界测试覆盖最大/最小朝向、最低/最高合法耐久、开/关、邻槽作用区相交、最坏公开风况及零耐久拒绝。它们用于验证求解和等价分类；发行可达性仍须覆盖全部允许组合，或有完整的等价证明。

### 3.3 每份可达证据的必需内容

`ReachabilityWitness` 至少保存：

- 三维布局及参数/几何/内核版本、种子选择结果、机关解锁子集、`unlockSnapshot`、六槽候选和替换结果；二维历史证据标其原版本，不混入三维索引。
- 具体预装实例、槽位、朝向、开关、耐久、稳定排序身份；实际新奖品集合、兑现总值、冻结目标及基础圈数。
- 从准备到达标的真实动作序列：量化左右方位/仰角/速度、普通圈、合法调整、命中与直接兑现；每步三维事件位置、耐久、圈数和双账结果。
- 使用调整时不超过 04 的两次预算；无需补救、未解锁圈型、新留场稀有机关或旧物收入。关闭机关后仍须避开其实体，不能把关机视为移除。
- 达标输入附近的量化输入窗口与报告。只给一个未量化闭式中心值或一张轨迹截图不能完成关卡审核。
- 证据摘要、复算入口、实际验证环境和结果；共享证据时附等价类成员。

必须由与正式局共用的规则内核复算，并与独立边界/数学基准对照。所有动作后实际新回款达到冻结目标，使用圈数不超过基础预算，才构成通过。无障碍闭式弹道只可作为输入来源，不能替代带实体、预装和机关的验证。

可达证据不承诺玩家失手或主动留场之后一定还能通关，不将它做成自动瞄准、局内隐蔽纠错或强制答案。

## 4. 规则内核接入前须锁定的工程展开

本节不改变04经济/标量参数；三维几何依当前共同配置独立登记版本。助手在 `simulationVersion` 对应说明中写清：

- 圈中心对三维奖品接受圆盘/体、实体圆柱、有限板面、作用体积和未来机关入口怎样求首次事件；区间内使用同一恒定加速度模型，避免一处插值、一处忽略步内接触。旧二维矩形/线段算法的通过结果不自动放行三维求交。
- 接受区保留下降、公开内径容差和边界包含的共同原则，但水平/纵深范围、高度和实体必须取当前三维几何版本；求解误差不成为额外兑奖带。关键位置误差仍按已登记验证门槛检查。
- 同一奖品顶部的合法接受先于它的实体侧撞；其他同刻事件按时间及稳定对象编号裁决，排序不能受集合遍历或系统语言设置影响。
- 事件恰在步起点/终点、板面边缘、正切或反射后零剩余时间时，如何保证同一接触只消费一次。重新触发须满足04离面距离、每件限次、耐久和圈级上限。
- 关闭、0 耐久或作用次数已满后的实体处理必须由共同规则给出；模板、UI 和模型不能各自选择穿透、反弹或失手。
- 滑槽的实体及内部位置路径只能使用 04 的入口、出口、方向和时长，外部机关作用暂停及出槽恢复均进入事件记录；不能从装饰网格或动画曲线读规则路径。缺少这一展开时不得给滑槽关卡盖可达通过章。
- 全局飞行时限、越界、地面与有效机关承接共同适用；被引导或暂停展示不能延长实际模拟飞行上限。

这些是同一规则怎样被可靠计算的工程决策。可在已有规则内作出并验证的选择由助手处理；若需要增加外半径、修改作用、碰撞面或终止条件，应先更新权威规则并重新审核，不能藏在作者数据里。

## 5. 命中与事件黄金样本

### 5.1 样本格式与来源

未来 `GoldenCase` 记录必须有：案例 ID、规则/内容版本、初态与布局引用、模式、种子及固定选择结果、量化输入/命令序列、预期事件顺序、位置/时间的比较依据、最终物件/圈/耐久/双账状态、来源与实际执行结果。

预期值须来自公开规则、独立数学推导或已复核参考输入，不把实现输出原封不动录成正确答案。04旧二维闭式中心速度只作历史推导，三维量化左右方位/仰角/速度后需独立计算穿越时间和空间位置。当前48项EditMode有部分解析/边界/事务结果，以下仍是完整样本目录，不因数量宣称十二目录全部覆盖。

- **GOLD-P01 基础轨迹**：普通圈、无机关/无风、两排三列六槽；覆盖左右/近远目标、基准弧和替代高弧。检查下降命中、落地、越界和飞行上限，且展示帧率不影响事件。旧45°二维样本保留原版本，不等于三维目标已覆盖。
- **GOLD-P02 接受边界**：04 要求的边界内/外 0.001 m、恰在边界、下降速度门槛两侧、向上穿越、侧撞；有效接受与同奖品顶部实体同时出现时只领奖一次。
- **GOLD-P03 顺序与子步**：一个模拟步跨细线段、先触发后接受、先接受后潜在触发、同刻作用和首次有效奖品；确认后发生的事件不能倒改中奖。
- **GOLD-P04 风扇与反弹板**：同输入的无机关/风扇/板对照；同扇单次、同板限次、离面重触发、双面法线、关闭/耗尽实体、机关作用上限及速度上限。每次合法触发只扣一次耐久。
- **GOLD-P05 风与罩**：本章允许的恒风、罩内/外边界、多罩优先、非零实际衰减才扣点、最后一点保护保持到本圈结束、再次入罩不重复扣点、下一圈完全失效。
- **GOLD-P06 滑槽**：入口方向/速度边界、背面与无效实体接触、引导开始/结束、出口速度范围、引导期间不叠加外部机关、每圈单次和全局终止。
- **GOLD-P07 拨片与垫**：正/背面、正切、向上/向下、线段端点、触发限次、各圈型响应。动画和模型厚度不得加入触发。
- **GOLD-P08 候选与冻结**：未解锁替换、取消预装恢复候选、免费准备截止、零耐久拒绝、开摊后卖空不补奖品、不重算目标；重复进入菜单及恢复不重抽。
- **GOLD-P09 调整与处置**：移动/交换/转向/开关、取消与非法操作、两次预算用完、新奖品留场原槽、同物兑现/拆卖/弃用终态、旧物及商店物收据资格。
- **GOLD-P10 最后一圈**：命中后兑现达标、留场未达标、新残值补齐、旧残值只筹钱包、合法补救、补救无资格、主动结束与已达标继续。失败事件必须排在处置和补救窗口完成后。
- **GOLD-P11 一局经济**：04 的十二摊例账与实际动作对应，验证新收入 2336、旧残值 190、总收入 2526、支出 151、末钱包 2375；此账本回归不作为玩家命中率证据。
- **GOLD-P12 模式隔离**：练习、回放、剧情阅览、挑战记录与正式经济写入权限；复现正式快照不得改变进行中正式局或重复奖励。

基础原型先生产 P01–P04 及两机关所需的 P09/P10；一章纵切接完整的准备、处置、经济和恢复；完整内容再补 P05–P07、全部解锁/变体和模式。后续新增用例应来自实际缺陷或尚未覆盖的合同，避免只重复实现分支数量。

### 5.2 输入窗口和手感的界线

自动报告记录可成功的量化左右方位/仰角/速度点、三维输入邻域连通性、可用档位数及对机关/风况的敏感性；尚未测量不填“已可学习”。03输入窗口不能只引用旧04二维无障碍最远槽的速度范围。

可命中的有限窗口是机器审核结果；键鼠/手柄能否看懂、是否需要反复微调和是否愿意再投属于试玩。窗口放行阈值需由基础原型校准并记录版本，不能把尚无体验依据的数字当作定稿，或用隐藏吸附满足阈值。

## 6. 保存故障与重复事务样本

使用 06 的单次事务及 08 的完整代次/提交清单候选。每个故障样本保存中断点、前后已提交状态、应恢复的代次/输入、再次执行命令及预期差值；不能只检查“文件能解析”。

- **SAVE-C01 发射前后**：在扣圈输入提交前、提交后且飞行未显示、飞行途中中断。恢复只有旧的未发射状态或新的同一投已扣圈状态，不返圈、不重扣、不另抽候选。
- **SAVE-C02 结果与处置**：机关变化提交后、处置尚未选；兑现/留场提交过程中及之后。恢复同一结果与合法待处置，不让双选都成功，不重复耐久和奖金。
- **SAVE-C03 残值与商店**：新/旧物拆卸、弃用、购买、修理和补救各在提交前后中断；恢复快照价、来源资格、容量和次数，重复请求净变化为零。
- **SAVE-C04 章末与失败**：章笔记、通过记录、携带整理及失败后局外记录提交前后中断。恢复完整 Run/Profile，不混用两代；失败保留已经获得的笔记和已见资料，不把局内物件带进新局。
- **SAVE-C05 写入异常**：临时快照写不全、代次写完但清单未提交、清单替换失败、当前清单/文件损坏、磁盘/权限/空间问题。旧完整状态及校验备份保持可用，未提交代次不成为领奖来源。
- **SAVE-C06 迁移和隔离**：未知格式/机关、内容或参数摘要不兼容、恢复上一完整备份、练习/回放退出、设备设置独立保存。不得静默重算旧局、恢复特殊圈额度或根据当前解锁改旧陈列。

完成标准是每次恢复取得一个自洽的完整状态，原物件终态、钱包、收据、笔记、圈额度、事件序号与去重记录一致；同一命令重试不重复奖励。实际故障注入记录和保存失败 UI 可操作路径共同通过，才标记保存完成。

Steam Cloud 如被采用，另按 11 验证整体云检查点、双机与冲突；本地样本不能替代 Cloud 验收，也不能把代次清单单独同步当作完整存档。

## 7. 完整文案草案的生产与校验

### 7.1 先交付什么

由助手依据 01 的六人物、三章节拍和语言约束生产全文草案；不要求用户补台词。

- 一章纵切先交付开场、前四摊开场/成功/失败、第一章章末、风扇/板的首次说明、通用失败与重试、该章已见物件图鉴和必要帮助。
- 完整版补齐十二摊、三章衔接、通关/失败及条件替代句、六机关说明、采用的可选角色交流和十二皮肤图鉴。01 的约 134 行是预算，不是每组必须凑行数，更不是已完成数量。
- 未解锁机关、未发生留场、未触发机关、只有兑现通关、覆盖了教学奖品等状态都必须有事实适配的通用版本。不得因缺台词强迫获得某件机关或执行指定投法。

### 7.2 文本和条件记录

每个文本段记录 `storyId`、稳定行 ID、说话人 ID、正文、条件、通用替代键、表情/姿态、首次/已见策略、占位字段及触发事件。编号沿用 01 的 `story.opening.*`、`story.stage.01.*` 至 `story.stage.12.*` 等家族；实际编号清单由助手创建。同一语义的校字/措辞修订保留行 ID，以文本版本/摘要区分；更换内容身份才创建新 ID，作废 ID 永不赋给另一段。段拆分、合并或替换时显式登记已见记录和中断续播的迁移：安全映射到仍对应的行，无法对应则回该段安全起点，不误把新剧情标已见，也不重放奖励。

条件只读取已提交的正式事实：模板/章/摊身份、处置结果、机关实际作用、合法完成/失败、已见记录和本摊解锁快照。可使用有限的布尔组合，不运行任意脚本，更不能给钱、改耐久、推进关卡或写第二份奖励账本。

“机关实际帮助了后续投掷”等叙事条件还需要可复核的事实定义，不能把装备或单次触发自动等同于帮助。助手在文本接入时记录采用的事件谓词和对应样本；若无法从真实事件证明，使用不编造因果的通用句。此选择只改变表现，不改变奖励或资格。

`storyId`、行 ID 与 `STORY_SEEN` 的归属关系必须统一登记，不能一处按整段、另一处把同名键当作单行。中断续播保留当前段和行；跳过/阅览只更新 01/06 允许的阅览状态，不生成正式奖励。

金额、圈数、耐久、钱包和回款占位字段从同一权威状态读取。渲染层验证字段类型和缺失值，不能把 `{target}`、空姓名、资源键或未替换花括号显示给玩家。

### 7.3 文本 lint 与可达审核

未来校验至少检查：

- 键唯一，角色属于 01 六人，模板/机关/皮肤引用存在，作废键未复用；触发与通用替代不存在断链或循环。
- 占位符属于登记字段，动态金额不在故事正文写死；核心术语与 01/04/05 一致。
- 每个正式可达的剧情状态有合法文本或明确不播；未到达/未解锁内容不提前出现，跳过不会使关卡无规则可读。
- 仅兑现完成与使用机关完成均能到同一主结局；失败、取消处置、预览、回放不播未提交的到账或资格台词。
- 章末/结局/教程同一安全点按 01 优先级合并；对白不在飞行抢焦点，基础规则卡独立可用。
- 一章和全局分别提供文本遍历报告、动态占位样本、最小分辨率/大字号截图及内容校对记录。文案 lint 通过不等于故事情绪已被玩家认可。

缺少必需全文或触发分支是内容缺失。角色是否能记住、对白是否打断重玩、失败语气是否合适是观察问题，需用实际文案和可玩版本验证。

## 8. 缺失资源的发布阻断

作者内容清单建立“模板/文本/皮肤/机关 → 必需资源 ID → 实际文件与来源”的闭合引用。模型、二维图片、字体、声音、功能标记和状态叠层按 05/09 交付；Unity 运行美术路径统一为 `Assets/RingToss/Art/`，音频/字体在同级目录。

P0 暂用 `Assets/RingToss/Resources/Models/`、`Resources/Audio/` 与 `Resources/Fonts/` 载入首组原创三维模型、七个原创短音效和中文字体；这是当前真实引用位置，不是完整发行清单。模型源/FBX与采用项见 [原创三维登记](../../../../../sources/art/proto-013-ring-toss/3d-p0/README.md)，音频按 [音频登记](../../../../../sources/references/woc-audio-reuse-register.md) 与工程声明复核。正式路径整理须保留引用并重构建检查。WoC十四项未复制，live-avatar的TTS参考不填BGM/环境缺口。

以下情况阻断相应发行内容：

- 必需 ID 或文件不存在、大小写/导入格式错误、引用落到外部参考工程、正式清单仍指向未制作占位。
- 模型锚点、圈中心、板面、入口/出口与规则配置不一致，作用区或接受区被遮住；仅有漂亮预览图而没有 Unity 实际标准镜头检查。
- 当前必需文字缺字、占位替换失败、表情/状态引用不存在，或者退回资源键仍继续显示。
- 来源、许可、实际采用版本或哈希缺失；代码仓库许可不能代替媒体授权。
- 导出版本与作者源不匹配、依赖不进入 Player、材质/纹理在选定管线缺失；仅编辑器可见不能放行。

原型允许明确标记的占位资源；纵切只完成其采用的代表样件；发行要求最终采用清单闭合。刻意复用已审核的中性表情、状态叠层或静态低动态反馈应登记为合法映射，不把缺文件临时吞错伪装成复用。未进入正式候选的草稿内容不打包，避免用大量未完成资源掩盖完成度。

## 10. 需要实验的假设，单独记录

- **EXP-C01 可学习投掷**：量化输入窗口实际可用，玩家能根据上一投只改一项。用实际键鼠/手柄输入、偏移和解释记录；有数学命中解不能替代 04/07 的首次体验者验证。
- **EXP-C02 机关与兑现的价值**：风扇/板确实开出不同投法，现金压力改变处置理由；0/1/2 预装降低货量是否压倒机关能力。用匹配场景和逐笔事件比较，当前不改 04 的正式参数或编造成功率。
- **EXP-C03 调整与耐久负担**：两次调整能否完成一次修正、耗尽是否可理解。观察实际错误与动作，不以增加说明文字代替可读作用。
- **EXP-C04 节奏和重玩**：十二摊、三章、短对白及解锁节奏是否支持 00 的目标局长。记录真实时长与选择；预算和故事行数不构成已测时长。
- **EXP-C05 叙事与读图**：玩家能理解受托取用、回款/钱包与失败原因，跳过故事仍可玩；真实三维的近远透视、手/棚遮挡和接受/接触锚点不误导套入位置。按01/05观察条件修正表现，装饰模型和相机仍无独立判定权。

这些实验由助手准备可玩构建、输入记录与观察材料，再按实际授权组织验证。缺少测试结果是经验未知；缺少具体模板、文本或资源是生产未完成，两者在完成报告中分别列出。
