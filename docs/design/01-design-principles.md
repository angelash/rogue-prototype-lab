## “建立系统”谈的是哪一层

原文“建立系统，而不是定一个目标”首先谈开发者持续创作、学习、反馈的方式。游戏仍然需要清楚的目标。

| 层次 | 本版含义 |
| --- | --- |
| 开发者创作系统 | 持续试验、获取反馈、整理认识，让下一次试验有依据 |
| 游戏规则系统 | 用有限规则产生值得处理的新局面 |
| 玩家阶段目标 | 给玩家当前行动的方向，与规则中的取舍相连 |
| 原型验证目标 | 用可证伪的问题判断某条规则是否成立 |

本版保留两条原则：

> 设计游戏时，让有限规则持续产生值得处理的新局面。  
> 开发游戏时，让每次试验持续产生可以复用的新认识。

选题标准：概念既让人愿意试，也让试过的玩家有理由换种做法再来一次。

## 十二条原则

| 序号 | 原则 | 后续验证要看什么 |
| --- | --- | --- |
| 1 | 熟悉＋意外负责首次吸引 | 分别验证首次吸引、继续游玩和重玩 |
| 2 | 区分认识物件、会做动作、理解规则 | 熟悉文化不代表玩家理解条件程序；分别观察三层理解 |
| 3 | 超级概念要支撑规则 | 是否支持自然因果、视觉一致和长期内容变化 |
| 4 | 简化结果验证 | 玩家能否看懂结果，把复杂度放在核心选择上 |
| 5 | 构筑深度来自组件用途变化 | 同一组件在不同局面中的价值和用途是否改变 |
| 6 | 经济要制造真实机会成本 | 兑现当前收益与保留未来能力是否互斥 |
| 7 | 随机要有明确的处理方式 | 随机对象、可见信息、干预时机和坏结果补救是否清楚，能否避免只等关键件 |
| 8 | 先让早期体验成立 | 基础循环、第一次改造、第一次协同成立后，再扩展质变 |
| 9 | 反馈要说明因果 | 清楚显示触发来源、顺序、消耗和因果 |
| 10 | 用有限范围验证 | 先用二维、离散、小地图、有限组件验证，严格限制范围 |
| 11 | 玩家能解释自己的行动 | 能否说明“我做了什么，因此发生什么”；用可复现种子辅助复盘 |
| 12 | 让外部反馈决定去留 | 优先看实际反馈和停止条件，不靠自我感觉、组合数量或无依据的市场判断 |

这些原则不是实测结果。每个原型仍需用行为记录和删除规则对照，检验其中的具体假设。
