# 游戏文案校对

先读根 DEVELOPMENT_STANDARD.md、目标项目 DEVELOPMENT.md 和当前规则/数据入口。来源及取舍见 [references/sources.md](references/sources.md)，具体规范见 [references/copy-standard.md](references/copy-standard.md)。

1. 看实际 Player 截图，列出读不清、装不下、重复、术语不一致及文图不符之处。区分弹窗遮罩和常态对比度。仅看原图或提示词不能验收。
2. 从生产数据核对目标、数量、时机、限制、失败原因。效果说明先写清这些事实；台词可以写角色性格，但不能暗示不存在的技能、收益或剧情。
3. 在制作源中修改，再生成实际运行数据。保留 ID、逻辑参数、引用、触发条件和来源记录；避免只改一份文档。翻译表的查找键与显示值分别处理。
4. 按角色、物件和当前处境写具体句子。删掉通用祝愿、抽象人生格言、同一句式批量换名及无信息的收尾。不要机械加入俚语、口头禅或故意写错字来模拟人。
5. 自查重复和字数；长效果说明按实际容器换行。多语言各自自然，但表达相同规则。缩短文本时不能丢掉限定。
6. 用实际 Player 检查改过的文字，覆盖目标项目支持的宽高比与展开/折叠/提示状态。视觉调整保持项目约定的布局与交互；图片创作使用 imagegen，保留旧稿、提示词与尺寸记录。
7. 汇报改了什么、代表性前后例子、实际检查范围和未验项。更新项目合同、生产入口和 Git 备份。只展示最终文字，内部草稿和自查不进入玩家界面。

不把风格判断当成错误证据：有用途的诗意、重复提示和必要的不确定性可以保留。不要引入参考 skill 的人物模仿、教育建议、攻击性或编造事实。
