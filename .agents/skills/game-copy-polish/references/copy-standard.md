# 本仓游戏文案规范

2026-10-13，按用户要求从 open-share 提取适用原则，并结合 humanizer 整理。

按钮写动作或结果，状态写当前情况，失败提示写实际原因。玩家应能看懂下一步；如果实现只有一个通用失败码，不能伪装成已经精确识别的原因。

规则说明使用固定术语，保留谁、多少、何时、能否选择以及例外。把内部名如“同号”“匹配事件”“推进一次”换成玩家能理解的说法时，先核对代码。短句服务理解，不以极短为目标。

角色台词要能看出谁在说话、正在做什么。同一类牌不能全部复用一句格言。优先写手边的锅、筐、灯、绳和具体动作；不要求每句都是笑话或口语词。委托说明对应本份委托的场景，不能用七句模板轮换整套内容。

避免“夜市的麻烦，也要一件件收拾”式泛句、“把来处看清，才知道从哪补起”式抽象结论、“你守火，我守心”式无情境金句。避免宣传词、万能排比、强行拔高和“综上所述”“值得注意的是”等论文过渡语。禁止按黑名单机械删除有实际意义的词。

文案的文字区必须平静、对比足够，装饰不能压住字。查看 Unity 的实际乘色、字体、换行和遮罩状态，不能用原图颜色推断成品。保持已约定的 UI 结构、字号与点击范围；需要改变这些时按项目合同记录。

中文标点与称呼一致；中英各自校对。数字、岗位、目标选择与计时窗口不能在翻译中漂移。效果说明与风味台词分开承担作用，风味不能使效果模糊。

可提交文字源、提示词、修订资产和测试用例；截图、检查结果和构建报告按仓库输出规则保存。事实状态以实际检查为准，不写“100% 去 AI 味”或“全部完美”。
