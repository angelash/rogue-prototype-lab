# 夜市美术与原规格导入

日期 2026-10-12。有限清单 [image-specs.json](image-specs.json)，任务 [jobs.json](art/jobs.json)，提示词 art/prompts/，独立生成原图 art/generated/，谱系 [generation-register](art/generation-register.json)。实际尺寸/hash 由静态验证登记。

## 制作范围和规格

原 82 张游戏非内置 Texture2D 一对一换图。包括 28 张插画（13 人物、15 事件）、2 桌面、4 印章、两画幅标题与一个操作提示底板、45 功能/UI 纹理。共享原图仍共享夜市图；没有给 95 卡另配 95 张插画。引擎内置纹理和动态字体 atlas 不冒称生成素材。

插画 1174×718；印章 1024×1024；16:9 桌面/标题 1920×1080，4:3 桌面/标题 2048×1536；主体牌框多为 1240×924，详情 1232×920，顶部 1240×831；成绩 1550×1000，副标题 628×174。2×2、32×21、32×32 等微型纹理也有独立生成输入，并技术缩放成源规格。逐项尺寸不靠本页代表值替代清单。

AI 工具实际输出可能大于或不同于目标。原图保留真实像素，C# 导出做双线性技术缩放；不能把生成服务原尺寸写成已精确输出原规格。所有 82 张最终 PNG 与 Unity 工作副本同字节，导入 metadata 不重建。

## 视觉和生成规范

二维手绘民俗奇幻，木刻轮廓和纸纹；成人妖怪比例圆润，工具与动作清楚。低饱和靛蓝/纸白/蜜金/陶红/鼠尾草绿/灰紫，左上暖灯与轻冷边光。桌面低对比，只在外围放灯、果篮或布料；工作区不烘焙卡牌、按钮、人物或正文。人物与事件构图要在原插画窗内缩小可辨。

每份实际提示写资产键、原目标尺寸、具体主体、构图、透明要求、画风和禁止烘焙文字。中文、数字、名单、效果说明由 Unity TextMesh 输出；标题中文使用本机 Noto CJK 在 Unity 离屏排版，合成到自己的标题原图。印章用打开摊位、结绳、交叉绳、折伞表示开张/完成/受阻/收摊。

初次生成不提供原作图片。成绩底板与共享标题底板各作一次 imagegen 修订，分别只引用自己生成的原图：成绩与商号均沿原深色字，纸底提亮保证对比度；其它字色与节点保持。两份旧原图和旧提示保存在 revisions/，新旧 hash 与引用链登记。工具发生失败的生成不算完成项。

## 功能几何与技术导出

Sprite rect、pixels-per-unit、枢轴、网格和 UV 用源数值，不随生图构图重算。功能/UI 使用本机原 alpha stencil 保留边界；只有牌框和详情等功能面板保留必要的中性亮度分区。牌背、选牌背、成绩板和点数标记只使用生成图颜色，避免带回原水印或旧字。

透明生成器的小孔和边缘噪点不能改变点击/进度反馈：统一白的微型功能 mask 在导出中归一，实际 RGB 色调仍由源 Sprite tint 决定。印章按生成 alpha 包围盒技术缩放到原紧网格可见区域的 90%，避免 source pivot/mesh 把新图截掉。两画幅大标题原生排字；操作提示底板没有烘焙文字。原文字像素不充当字形模板。

最终 PNG、stencil 与场景 UV 派生留在 local/，AI 原始新图公开备份。派生不说明原作媒体可发行。13 处字体引用均用 Noto Sans CJK SC 相同字节，除 v2.5 声明的委托副说明 characterSize=0.85 外字号配置沿原资产，包内保留完整 OFL 和版权声明。

## 实际视觉检查

逐件查看生成原图，尺寸/alpha/hash 全量检查。Player 检查教程、中文/English 选项、95 张展开牌、28 张委托、16:9 与 4:3，并从整局结算发现与修正牌背/成绩板水印、标记旧字及成绩/商号标题对比度。自动摆放调查属于渲染验收，不冒称真实选牌动作或 95 种效果全部实玩。

原作 91 音频保留本机事件引用，626.75 秒；当前没有夜市原创音轨、听感及跨引擎混音等价证据。详细当前状态以交付记录为准。

## v2.4 文案与可读性修订

2026-10-13 按用户要求检查实际画面。发现同类台词成批重复、委托说明与摊位场景不符、岗位名和说明字色接近底板。改写全部 95 条双语台词、28 份双语委托说明，术语改为招客、备餐、备货、挂灯、布符。效果文字按原数值核对，英文修补说明列出中文牌名，与牌面名称一致。英文台词按 40 字符以内的单词边界换行，保留原 WordWrap 行为。

CARD_03_DetailsTop 与 PRJ_CARD_01_Base_Project 使用 imagegen 编辑自己生成的原图，分别提亮标题带与摊名区域；原图、旧提示和 hash 留在 revisions/。最终仍为源规格。八处 TextMesh 字色与八份卡牌标签材质 _Color 在 presentation.json 声明并同步恢复输入，场景、prefab 和素材；不改变节点、布局、字体尺寸、引用、着色器或点击范围。

早期颜色检查工具误读 Unity JSON 的外层 TextMesh 节点，未通过即停止；修正内部字段核对后再构建。第一次英文画面中一条台词超宽，以及修补/调停标签对比度低，均已追加修订。每轮截图保留在 local/QAResults；本轮最终范围以交付记录为准。

英文效果说明及委托副标题按 36 字符单词边界换行，混合中文牌名的修补列表显式分行。视觉驱动显式刷新隔离模板，逐张确认语言值，并比较文字与牌框的实际 Renderer 宽度；较早调查没有验证模板语言，只作为修订记录。v2.4-r4 英文 16:9 调查正确发现 SubTitle4 超宽，失败截图和报告保留；修正换行后以 r5 重新验证。

r5 的牌框检查通过，但人工查看发现英文教程第二页说明和操作提示在 4:3 下越过右边界；早期 passed 没有覆盖教程屏幕边界，不能当最终视觉验收。r6 缩短这几句，将调停时机另写入末行，保留效果分类和操作键；新增实际教程文字 Renderer 到屏幕的边界检查，布局和字号不变。

r6 四组边界与语言检查通过后，人工查看中文教程发现灯芽、纸鸢示例牌的深色标签缩小后对比度不足。r7 将这两处已声明的 TextMesh 改为浅色；生产牌的岗位材质仍按各自底条选择字色，避免根据未乘色的原图推断教程字色。

## v2.5 操作提示与委托标题修正

用户截图中的金色字挤在提示上，原因是把名为 SubTitle 的纹理误当游戏副标题。查原作场景和实际窗口确认，它是两种画幅下的 Continue.Background，用于教程、逐牌暂停和调停提示。原 628×174 PNG 的 RGB 为黑色，alpha 提供提示背板轮廓；Sprite 为 sharedassets0.assets:276。保留原 alpha、紧网格、枢轴、位置、引用与点击流程，把 RGB 统一为 (0.02,0.025,0.04)，移除金色 logo、图案和烘焙文字。NightAssetExport 的 prompt_backplate 分支程序导出，不依赖生图结果，并拒绝将 SubTitle 作为标题。运行共 81 张生成美术加 1 张程序提示底板；旧 SubTitle 生图和旧提示保留为被弃用的历史源。

TextMesh 分别显示“点击继续”/Continue、“关闭逐步暂停”/Disable step pauses、“点击调停”/Click to mediate；沿原绿色主提示、白色次提示和闪烁。28 条英文委托副说明缩为单行。替换字体在原折叠状态下的标题与副说明还有约 1 像素贴边，故只将 13 Subtitle（mainData:1315）的 characterSize 从 1 改为 0.85，在 presentation.json、恢复输入、场景和对应 prefab 一致登记；其它 TextMesh 尺寸与全部节点变换不变。

NightPromptProbe 在实际 QA Player 中分别渲染标题/副说明的亮色字形到黑底，比较可见字形像素间距；不把字体空白包围盒或透明通道当可见字形。标题临时按原折叠偏移下移 0.1 本地单位，四种画幅/语言组合都检查这个更紧的间距。该摆放只在 QA 驱动内进行，不进入正式包。最终四组各 33 图通过，人工复核中英文提示、调停和委托样本；原始图与报告保存在 local/QAResults/prompts-*-v2.5-r9*。

## v2.6 干预牌分类色条

用户指出第 64 牌“铃诱跳槽”的大片黑色区域。原作 Type 6 闹场和 Type 7 挖角共用 00_NEG_Detail，原 _Color=(0,0,0,1)；InitProperties 将它赋给 03 Details Top、03 Details Lines 和存在轮数时的 Base Mask，所以标题带、两条斜切分隔条和底部分类带全部纯黑。这是原作的分类配色，并非缺纹理、遮罩错误或 shader 丢失；但在夜市深色底板上难辨用途。

只将这一个材质的 _Color 改为 (0.72,0.24,0.18,1)，以陶红色标识 20 张闹场牌和 6 张挖角牌。presentation.json、恢复 manifest 和 Resources/00_neg_detail.asset 一致登记。共享该材质的原粒子反馈也沿同分类色变化；触发、动画、计时和判定不变。所有 82 PNG、alpha、Sprite 紧网格、节点、引用、点击范围、文字与业务脚本字节本轮未变。不新增生图，功能轮数槽、进度轨道和字形黑色轮廓保留。

NightVisualProbe 扩展实际像素检查：26 张牌的两层色条分别在黑底上孤立渲染，每层须有足够的有色像素，避免只检查材质参数就误报成功。两画幅与两语言继续调查完整 95 卡、28 委托、教程与设置；最终数量、人工样本和适用范围见交付记录。
