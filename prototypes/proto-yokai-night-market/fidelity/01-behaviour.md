# 行为合同 v2

日期 2026-10-12。原作恢复代码和有效配置决定行为；本文解释已核实的有限范围。全参数在 [theme.json](data/theme.json)，逐条查阅在 [content-guide](data/content-guide.md)。

## 对局和胜负

玩家与一个原 AI 对摊竞赛，各自独立牌库包含同样 95 张卡，抽不同委托。95 卡沿原 ID、Type、Turns、Target、Function、Num、Repair、Picture 引用装载。没有行动点、关卡解锁、购买经济、客人模拟或局内保存。

五工作内部顺序为 Sound→招客、Programming→备餐、Design→备货、Art→挂灯、Testing→布符。XML 中 Animation 不被原 Loader 识别，因此 28 委托布符实际需求均为 2；不根据旧 XML Animation 字段“修正”。其它有效目标保持原数值。

任一方五类已完成工作均不少于当前需求立即进入原胜负回调。允许超过需求。出牌 500 分、完成工作 1,250 分；撤销成果不倒扣此前累计分数。成绩是排行榜数值，不用于消费。

## 回合与出牌

双方各抽五张。每轮按原回调先处理修补、在岗工作和事件，再补至五张；已有五张或更多仍至少抽一张，没有硬手牌上限。牌库用随机索引取牌并移除，原作不做一次初始洗牌。弃牌、返还和挖角沿原列表/排序/引用处理。

自己的五个帮工位和对方五个闹场位均有容量约束。首个上岗帮工锁定本轮岗位，开放岗位牌解除该轮限制。对面正在使用同 ID 帮工时不能同时使用该帮工。两轮/四轮工作完成一项任务后离岗；受阻的帮工不推进。不同 Function 的开放、推进、完工、修补、目标选择和巡街作用分别沿原方法。

42 帮工：招客 6、备餐 12、备货 6、挂灯 12、布符 6。20 闹场、6 瞬时帮工干预、13 搭把手、5 修补、2 调停、7 巡街合计 95。63–68 作用于对方**在岗帮工**：挖到自己空位、退回对方手牌或送入弃牌，不偷两张手牌。82–84 修补与天气卡 44/45/49/50 匹配；85–86 与灯故障 47/48 匹配。调停在原 5.99 秒窗口反制巡街，双方对应牌离场。

原不可用原因覆盖非己方回合、容量、岗位限制、对方无人、没有成果、同 ID 在对面、没有可推进员工、手中无帮工和无匹配事件/窗口。相同原因 ID 保留，展示文案换为夜市。

## 原 AI 与节奏

AI 不重写为新的策略。沿巡街→修补→干预→帮工→搭把手→闹场优先级及原遍历、可用性、目标选择和随机调用。全局 Unity Random 调用位置相同；Unity 4/2022 内部随机实现尚未做同 seed 序列比较，不承诺回放逐帧等同。

保留原 ActionManager 动画序列、插值、回调、逐牌停顿、约四秒无牌自动交班及状态转换。原快进仅提高适用动画倍率至 1.5，不能写成新规则速度。自动整局 QA 会额外设置 timeScale=3，限定在隔离 QA 包，不能作为原速或 5.99 秒真人可操作性的证明。

## 输入、界面和保存

使用原 InputManager；鼠标在原 3D 射线与 2D 菜单命中逻辑上工作。选择手牌、展开、再次点击使用和需要的目标选择保留。Space / 右键交班，Tab 快进，Esc 按住三秒退出、松开取消。项目自定义商号编辑使用原输入路径。

原 SpriteRenderer / TextMesh 结构、碰撞框、排序、世界坐标、锚点、16:9/4:3 两套位置及源模板节点保留。字体和文字改变会改变字形像素，包装换图也会改变画面；几何/流程相同与逐像素相等分别验收。

四选项为逐牌停顿、快进、声音和教学；默认前三项中的逐牌停顿/声音/教学为开，快进为关。两个原语言槽改为中文/English，原 ENG/SPA XML 字段保留。角色/委托中文名作为专名在两语言槽一致，解释与界面为双语。两页教程保留结构和推进方式，不采用旧 14 步教程。

六项 PlayerPrefs 配置含以上四项、Language、Company；成绩十条各包含姓名/分数/委托 ID，共 30 字段。保存身份独立，保持原 PlayerPrefs 行为，不增加局内存档、Cloud、存档迁移或原作不具备的恢复机制。
