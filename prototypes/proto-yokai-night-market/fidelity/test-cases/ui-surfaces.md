# UI 功能层回归用例

2026-10-13，针对设置、左侧委托框和中央阶段底图的实际截图问题。

制作规范为 [ui-surfaces.json](../data/ui-surfaces.json)。26 个功能层包含 24 个底色/描边/渐变/高光/进度标记及两枚原生语言图标。保留原尺寸、alpha、Sprite rect/枢轴/紧网格/UV、节点、材质、数值和点击区域。历史生图不删除，不将这些层继续当整张装饰框使用。

1. 静态全像素比较：各层与本机原参考 PNG 的尺寸、alpha 完全一致；24 层 RGB 应符合声明的 flat 或 luminance 角色，8 位通道舍入误差至多 1。两枚语言图标含足够的原生亮色字形像素，实际 Player 人工确认“中 / EN”。此检查会拒绝此前透明区域补成深蓝且夹着完整画框的结果。
2. 启动独立 QA Player，沿原开局到玩家行动阶段 26，再冻结 Loader。捕获实际整桌左侧委托、商号、轮数、进度、按钮；不以孤立 PNG 推断实际分层。
3. 调用原设置按钮暂停到状态 80，捕获当前设置、四项全关、四项全开，再调用原按钮恢复状态 26。分别比较四盏灯与 Resources 原实际状态资源引用，共 10 项断言。按钮/语言图标/高光必须没有额外装饰矩形；数字与文字读得清。
4. 在原桌面上通过 TitleManager.PlayTitle 驱动 Recruiting、SelectingProjects、YourTurn、AITurn、YouWin、YouLose、NewRecord。每项捕获进入、显示、退出共三图；校验查表文字、显示资格、标题宽度不超底板、原淡出完成及左右底板移回 ±27。放大的淡文字是原第二标题动画，不作为故障移除。
5. 中文和英文分别运行 1920×1080 与 1440×1080，每组应 26 图、7 个阶段检查、10 个设置检查、0 脚本错误。四组合计 104 图。人工查看底板与描边配合、全部左侧信息及语言图标缩小识别。
6. 共享顶部层同时用于卡牌，故重新运行两语言两画幅的完整 95 卡、28 委托、两页教程/选项调查，各 128 图；同时重跑 Continue 状态与 28 委托折叠标题间距，各 33 图。保留失败夹具记录。

这些检查使用实际 Player 渲染和原回调，测试驱动受 NIGHT_MARKET_VALIDATION 限制。正式包应排除 NightSurfaceProbe 与其它五个 QA 驱动。冻结 Loader、直接修改 QA 设置及调用阶段回调只证明展示/回调契约，不能写成原生鼠标切换语言、整局七阶段实玩或逐像素复刻原作。

正式窗口补验：打开设置、点击各项、悬停查看高光、点击“中 / EN”、恢复桌面，检查语言/灯状态/输入资格及阶段背景。当前若 Windows 锁屏，停止发送输入，记录未执行，独立渲染、构建、备份继续完成。
