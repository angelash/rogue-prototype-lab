## 1. 现状与处理结论

本轮读取了当前工程、原作导出快照、恢复引用、素材谱系和已有 Release 的编译符号清单，重新计算全部工程输入哈希。**967 个输入保持原样**，摘要为 `a618d666e4b63a5d1332602426436aca2f6b92ebcd75532ad11604eebe5cd84a`。编译符号来源是此前 Release 提取，尚未为这份方案重编译或重跑游戏。

当前 Assets 有 465 个非 meta 文件，另有 479 个 `.meta`；不能把“82 张换图”当成全部资产已独立。

- **91 个 WAV 全部仍与原作导出字节一致**：21 段音乐、2 段环境/计时氛围、68 个音效。恢复引用能定位全部 91 项，共 92 个序列化引用槽。全部要制作替代，不用调速、变调、重新编码冒充新素材。
- **82 张非内置纹理**：28 插画、37 功能 UI、8 接口/遮罩层、4 印记、2 标题、2 桌面、1 提示底板。已有夜市 RGB/AI 原图并不证明运行图完全独立，当前制作链读取过原 alpha、Sprite rect/网格与恢复引用。每张重新检查谱系，从合格自有原图或新图制作新版本。
- **42 张额外 PNG 和 13 个 OBJ** 与恢复导出一致，来源属于 Unity 内置纹理/几何。不能误记成 55 份原作独占美术；新工程不带这些导出副本，使用合规引擎资源或独立制作的图元。程序生成的基础几何与引擎默认材质不需要 AI 生图。

- **30 份恢复业务脚本与 2 份适配脚本** 是结构迁移主体。Assets 共 41 份 C#，还包括 Editor 和 6 份 QA 驱动，不能漏改工具/测试中的绑定。

## 2. “不能改变”的范围与合同更新

用户前一轮要求锁定原尺寸/规格、防变形、防穿帮，继续执行。此次“不得复用原作资产”优先于旧版逐字节锁定原 alpha/网格/meta 的要求：**旧文件保留为基线；新文件保持尺寸和功能规格，但独立制作透明轮廓、网格和导入信息。** 新旧 alpha 哈希不再作为“必须相等”的验收项。

新资源必须保持每个原槽位的宽高、比例、显示区域、枢轴对应的世界锚点、Pixels Per Unit 的有效尺度、点击区域、遮挡顺序和动画轨迹。透明边缘采用新轮廓，不照抄原 stencil；必要的技术裁切通过新定义的矩形/遮罩层完成。相同尺寸不等于可以非等比拉伸；一律等比缩放、明确裁切或留白。新边缘、印记和纸框产生的审美差异要登记，不承诺独立资产仍与旧图逐像素相同。

逻辑参照为**当前已运行的 Unity 2022 v2.8**，不是未证明的 Unity 4 位级等价。冻结以下行为：

1. 双方各 95 张牌，28 委托，420 双语键；开局 5 张，每轮补至 5 张且至少抽 1 张，无手牌上限/行动点。逐次随机取索引再移除，不能改为先洗牌。
2. 五帮工位、五闹场位、首个帮工锁岗位、对手不能同时持有相同 ID 的在岗帮工、空位与目标条件；帮工按 2/4 轮工作，受阻不推进。
3. 岗位与有效数字固定：招客、备餐、备货、挂灯、布符。原 Loader 忽略 `Animation`，布符默认 2 的有效结果要显式写入新数据，不能在“修 schema”时意外启用旧字段。
4. 卡 63–68 作用于对方**在岗帮工**；82–84/85–86 的修补配对、5.99 秒调停窗口、两张牌弃置、目标合法性和回调顺序不变。
5. 出牌 +500、完成工作 +1250、移除已完成任务不追回得分；五工作达到目标立即胜利；成绩严格大于才插入榜单。
6. AI 优先级为巡查→修补→即时干预→帮工→助力→闹场；遍历、同分选择、目标顺序和随机调用位置保留。不要在重构时优化策略。
7. 同帧回调与队列阻塞、约 4 秒无合法牌自动结束、快进适用段倍率 1.5、逐牌暂停与恢复、标题和动画先后关系不变。
8. 点击展开/再次使用/目标选择、Space 与右键的上下文行为、Tab 快进、长按 Esc 3 秒退出与松开取消，均保留。不能把原 3D 射线改成 uGUI 事件系统后默认认为体验一致。
9. 两套画幅 16:9/4:3、中文索引 0/英文索引 1、四开关默认 true/false/true/true、十条成绩、重开与设置持久化保留。不加入局内存档或 Steam Cloud 等新功能。

透明图需实际请求透明背景，不能以黑底代透明。独立 alpha 与网格应一起生成；检查黑边、预乘 alpha、过滤采样和压缩后像素，尤其是牌中三条横带、底部分类色、设置纸签、左侧面板、阶段条幅。不能只看原始 PNG。

## 4. 代码、签名和配置迁移

### 4.1 新工程边界与职责

保留 `local/UnityProject` 不动。实施阶段另建 `local/CommercialUnityProject`，先加入 Git 输入白名单，再制作；Library、Logs、Builds 和报告继续忽略。建议制作分支 `codex/yokai-commercial-v3`，在合适的隔离工作树工作，避免共享 checkout 上直接切换分支。当前轮未创建它。

命名空间为 `YokaiNightMarket`，六个职责域：

- **Domain**：牌、委托、五岗位、合法性、计分和 AI。纯状态与规则，不查场景对象、不触发声音。
- **Flow**：会话主循环、回合、结算步骤与回调队列。仍只有一个状态推进权威，不新建异步并发调度。
- **Presentation**：SpriteRenderer/TextMesh、卡牌展开、目标提示、阶段纸幅、印记、设置与教程。继续消费同一套规则结果。
- **Content**：夜市目录、稳定 ID、双语查表、图和声音目录。
- **Platform**：本产品的设置/成绩持久化、场景重载与平台边界。
- **Authoring/Editor/Tests**：新资产生成、依赖检查和 QA；恢复迁移工具只在私有 Editor 工具链，不进入发行源码/包。

32 个主类型的一对一建议映射已完整列入 `symbol-plan.json`，含内嵌类型共 39 项。例如 `CardManager→MarketTableController`、`hGameState→MarketSessionFlow`、`hGameVars→MarketSessionContext`、`PlayCard→MarketCardView`、`ProjectCard→StallCommissionView`、`TitleManager→MarketPhaseBanner`。第一步只迁移职责和绑定；第二步才把三大混合类中的规则、状态、视图拆开，每次拆分做行为对照，不能同时换算法。

先保留程序集编译边界，类名/命名空间/序列化迁移通过后才拆 asmdef，避免一次改变类型身份、编译依赖与执行顺序。新视图用强类型序列化绑定/注册表替换隐式按名查找；运行对象名按 `MarketTable/PlayerStall/RivalStall/...` 组织，原场景根名称留在私有映射，最终产品中不保留。

### 4.2 成员、属性、参数与字面量

已有 Release 共 47 类型、667 方法、957 字段；其中作者可处理的 39 类型覆盖 664 方法、946 字段、62 个属性、285 个已记录参数。剩余是编译器/Unity 自动生成类型。符号表列出了每个 token、签名 blob 和新名草案，防止遗漏重载；这不是已经完成的语义重命名，所有草案仍待实施时按调用关系复核。blob 包含旧类型 token，后续不能要求新程序集原 blob 完全相同，应比较经类型映射的参数/返回类型、顺序、可见性及调用语义。

自动去前缀曾暴露同名风险，例如可用帮工数量数组和布尔标记、节点名数组和对象数组、调停常量与当前计时、委托索引与对象引用。本轮为这些冲突给出独立候选名，仍要用 C# 语义模型确认全部引用，不能执行全局字符串替换。局部变量、参数、委托、构造器、属性 getter/setter、注释、路径和 XML/资源字面量同批纳入检查。

代表性命名：`m_aiDevelopersAvailable→_availableHelperCounts`，`m_bDevelopersAvailable→_hasAvailableHelper`，`m_asObjects→_objectNames`，`m_aoObjects→_boundObjects`，`DECISION_TIME→MediationWindowSeconds`，`m_fDecisionTime→_mediationElapsedSeconds`。`Company→Stall`、`Project→Commission`、开发岗位→夜市岗位，声音系统中的 `Sound` 则仍表示音频，**不能盲目全部替成招客**。

Unity 生命周期函数 `Awake/Start/Update/OnEnable/...`、引擎 API、必要 shader 属性 `_MainTex/_Color`、序列化协议固定字段等必须保留；它们不是原游戏设定。普通业务方法也可能叫 Start/Update，需按实际基类区分。`System.Action` 与原自定义 Action、`UnityEngine.UI.Button` 与原自定义 Button 的同名情况也要按符号绑定。

### 4.3 已识别的绑定断点

扫描得到 **19 行字符串类型工厂、86 行对象名查找、18 行资源加载、28 行 PlayerPrefs、12 行随机调用、72 行颜色相关代码**；这些是代码行命中数，不是去重对象数或调用总量。

6. 回调队列目前以实际方法引用为主。字符串回调/反射扫描本轮没有命中，不代表其它 Editor/序列化入口不存在；实施时继续检查 AnimationEvent、UnityEvent、字段路径和 QA 反射，不能只以编译成功判定。

1. **M0 基线与隔离**：制作可恢复 source/build 快照；补当前欠缺的完整原生与音频行为基线；建隔离制作分支和新工程输入白名单，冻结所有规则/时序/布局参数。现有 14 项原生实测并非完整基线，不能直接冒称齐全。

4. **M3 自有图片和表现资产**：逐张从自有源导出，独立 alpha/网格/材质；重建 18 类 prefab 功能边界、新场景和新引用。先卡牌→设置/左栏→阶段/标题/桌面→教程/成绩，覆盖全部 82 槽位及其它资产。节点内部可重组，最终 anchor/点击/排序/时序必须通过。

## 6. 不改变体验的验证方法

### 行为对照

同 Unity 2022 版本、相同种子/输入/时间步驱动基线与新实现，记录抽取索引、牌库与手牌顺序、双方岗位/槽位、锁定、目标、分数、主状态、队列、随机调用和归一化事件。状态整数与 ID 用映射对齐，不按类名比较。迁移前先验证探针不消耗随机、不驱动流程、不改计时；不把“两个版本都通过同一份断言”冒称完整等价证明。

纯规则用固定 DeltaTime 序列，含 30/60/144 FPS 与波动序列、暂停/快进；离散结果和事件次序要求完全一致，计时边界按同一比较运算及帧步命中，不用大容差掩盖错一帧。真实键鼠另外验证实际节奏；Unity 4/2022 随机实现差异仍列已知边界。

### 图形与交互

每项尺寸、独立谱系、有效显示 bounds、锚点、碰撞、PPU 与导入属性可检查，GUID/alpha/拓扑不要求沿旧字节。相同机器/设置下，未批准视觉改动区要求无非预期差异；新轮廓区域逐项登记并在实际画面验收，不能只让“总像素差小于某比例”通过。

复用现有四组合驱动的 **748 个渲染场景**范围（512 卡/委托/教程 +104 表面/设置/阶段 +132 提示边界），作为新回归目标；这不是本轮已跑的成绩。95 张折叠/展开/目标态、28 委托、所有阶段、十行成绩、两页教程、所有设置与语言切换均要覆盖，并增补新资产边缘、背景泄露、网格遮挡、裁切、颜色状态、碰撞命中正反边界。原生完整交互用例另验，不用 QA 方法调用代替鼠标。

### 来源与包

不得只比较 hash。任何改像素、改 metadata、转格式、压缩或改名后的原素材仍属于原素材派生，不能过来源检查。每个发行素材须有自有源/生成记录/录音项目/代码定义/第三方许可及最终运行副本的闭合谱系；对旧素材派生输入做禁止项，对合法引擎/字体/SDK 做明确许可白名单。

检查新 Assets、Resources、StreamingAssets、场景依赖、插件导入范围和真实 Player 对象/字符串/文件；生产程序集、资源键与可见文本的旧设定命中必须为零或有明确通用/引擎/必要声明豁免。旧映射/研究报告不打进游戏，不要求抹去私有 Git 历史。
