# 027 离散规则权威

版本 `0.2.0`，快照格式 `1`，2026-10-10。首次单图纵切的助手初值建议，尚无平衡或趣味实测结论。原需求/设计 v0.1 保留，工程事实由项目开发记录登记。本目录拥有规则与动作状态，Unity 只发命令、显示快照和事件。

## 有限地图、预设与初值

- `Rules` 是唯一参数来源：8×6，坐标从 `(0,0)` 起，Up 增加 Y，Right 增加 X；`CellId=y*8+x`。边界不可通行，墙为 `(3,1)/(3,2)/(3,4)`，两采集区 `(2,3)/(6,3)` 各4货物，交付点 `(1,1)`，目标8。
- 80全局行动，成功移动、等待、采集、交付、分裂、回收、拾取库存模块、放下模块均1行动。非法选择/未知枚举/不合法回收/库存或载量已满的无效操作不耗行动；确认撞墙、边界或身体的移动是提交成功的失败动作，耗1且结束本轮，`CommandResult.Success=true`，必须保存失败终态。
- 最多2分身，主蛇至少保留2节（头计入）。蛇头基础货物容量2、每次采集1；每采集节加1采集速率，每货仓节加2货物容量；基础节只占身体空间。库存中的模块不提供能力。模块库存2格，与货物容量分开。
- 模块总7：ID1/2基础节、ID3采集节、ID4/5货仓节、ID6采集节、ID7货仓节。ID与类型不可重用或改变。货物总8，不生成额外货物或模块。
- Short：主蛇ID1 `(1,1)`、ID2 `(1,0)`、ID3 `(0,0)`；库存ID4/5。Long：相同前三节，再接ID4 `(0,1)`、ID5 `(0,2)`；库存空。两者起始方向Up，地面ID6 `(0,4)`、ID7 `(7,4)`一致；因此同地形、同货物、同总7模块，只改变身体/库存归属。初始能力Short容量2/速率2，Long容量6/速率2。

## 动作、成长和碰撞

`Move` 只移动身体并自动吞入目标格最低ID的一个地面模块；不自动取货。无成长时旧尾先腾位，身体依次跟随；成长时将新模块追加在真实旧尾格，旧尾本步不腾位。主蛇始终禁止直接反向进入紧邻前一节，即使长度2的该节也是尾格；其它不成长的旧尾格仍可进入。预览与执行共用判定。

`Collect` 是主蛇头所在格的原地明确采集，取 `min(地面货物,采集速率,剩余容量)`；余货留在原格，取不到则拒绝。`Deliver` 只在交付点将实际携货全部转成已交付。终态先看目标完成，再看行动截止；碰撞会立即结束，本步分身不再额外行动。

`CollectModule` 需地面模块与主蛇头同格或正交相邻且库存有格，只转库存；`DropModule` 将库存的实际ID放到主蛇头格，不在放下当步吞入。地面模块可多个ID同格，也可在身体格下共存，它们不阻挡移动；这种可见覆盖能形成“下一次进入旧尾时会成长”的真实边界。任何模块始终只归属主蛇、某分身、库存、地面之一。

## 分裂、有限任务与回收

- `Split(keepSegments,behavior,route)` 保留主蛇序列前N节，把其后实际节转为分身，尾段第一节即新头，不生成额外头模块。目标预览给出长度、能力损失、货物去向和1行动费用。主蛇货物先保留合法容量，溢出先放新分身容量，再落新头格；本初值合法切割的分身容量足够容纳溢出，但合同仍明确掉落分支。
- 新分身 `BornAction` 是创建行动索引，创建当步不行动；既有分身仍会行动。主蛇命令先完成，再按分身ID升序尝试一步。每个分身看到主蛇最终占位、已移动低ID实体及尚未移动实体的当前占位，不猜测另一条蛇会让路；受阻等待，不偷偷改道、损伤主蛇或增加预算。
- 路线是2–32个公开正交相邻格，首格必须为新头。越界/跳格路线拒绝；公开墙格允许在预览中标明，执行到墙前等待。分身不吞地面模块，移动到货物格按自身真实能力取货，满载后余量留地面。
- `PatrolCollect` 跑有限路线一次，到最后格后停，携货等待回收；不会自动交付。`Shuttle` 的路线须闭合并经过采集点与交付点，持续循环，在经过交付点时交付实际货物。
- `Rules.SuggestedRoute` 是作者固定环：`(0,0)→(1,0)→(1,1)→(2,1)→(2,2)→(2,3)→(1,3)→(0,3)→(0,2)→(0,1)→(0,0)`，按切下头所在环格旋转起点。两行为用同一路线对照；不在该环的切点返回空建议，预览拒绝空路线，需换可用切点或提供合法公开路线。这里没有全图自动寻路、实时蛇群、升级或敌人。
- `PreviewReclaim(id)` 检查头部相邻≤1，显示1行动、货物转移/头格掉落数、模块入库存/原格掉落数；确认才 `Reclaim`。实际节按原身体顺序先进模块库存，库存满的每个ID落在各自原节格；携货先转主蛇余容量，剩余落原分身头格。分身移除，模块不会免费接长主蛇；重复回收拒绝且不耗步。

## 公共接口与保存合同

命名空间 `SnakeHatchery`，程序集 `SnakeHatchery.Core` 无Unity引用；DTO为 `[Serializable]` 公开字段。入口为 `Session.CreatePrototype(PresetKind.Short/Long)`；`State`、`LastEvents` 和 `ExportSnapshot()` 均深拷贝。动作API为 `Move/Wait/Collect/Deliver/Split/Reclaim/CollectModule/DropModule`；移动、分裂、回收各有同条件预览。

`RoundSnapshot` 保存参数版本、预设、phase/outcome、剩余行动、已交付、NextCloneId、主蛇/分身实际节与货物、所有模块唯一归属、模块库存、全地图货物、路径/游标/新生行动/等待原因、成功命令和事件。事件的 `Sequence/ActionIndex/EntityId` 提供可读复盘，不调用奖励。

`ValidateSnapshot/TryRestore` 先校验有限范围、模块与货物守恒，再从同预设用记录的生产命令重放，并对所有序列化字段做稳定完整比较。未知版本、缺字段、假行动/货物/归属、改路线、错误终态都拒绝。恢复不追加动作、事件或货物，`LastEvents` 空，已提交命令ID保留；同ID重复返回 `AlreadyApplied=true` 且不发事件。该检查防不自洽的本地检查点，不声称是防作弊签名。实际文件提交/备份由独立 `CheckpointStore` 负责。

`Retry()` 以同Short/Long预设创建独立初始轮：80行动、所有模块和货物回初始合法归属、无旧事件/命令/分身；不是返还给当前轮。预览、取消和只读回放均不推进动作。

## 独立黄金输入与测试范围

`U/R/D/L` 为Up/Right/Down/Left。两预设可用相同无分身完整序列：

1. A采集往返执行两次：`U,U,R,Collect,D,D,L,Deliver`，每趟8行动、交2，共16行动/交4。
2. B采集往返执行两次：`U,U,R,R,R,R,R,Collect,U,L,L,D,L,L,D,D,L,Deliver`，每趟18行动、交2，共36行动/交4。
3. 总52行动，余28，已交8，主蛇携货0、地面货物0、分身0；模块归属与起始一致，两条地面模块均未吞入。完成状态来自这些生产命令，不是手写终态或当前输出自录期望。

Long利用仓容的对照：A一次往返但`Collect`执行两次，共9行动交4；B一次往返也`Collect`两次，共19行动交4。总28行动，余52，交8。上述预算从路线长度、明确采集次数和交付动作独立推导，不是实测命中率或趣味证明。

有分身样本：Short在原地Split保留2节，采用环路线；之后主蛇`R,U,U,L,U,R`停在 `(2,4)`，再等待8次。Patrol已完成一圈停在 `(0,0)` 携货2，主蛇仍2节。主蛇`D,L,D,D,L`到 `(0,1)` 后回收，满模块库存使ID3落 `(0,0)`，货物2转主蛇。若先从停车点`D,Collect,Collect,D,L,D,L`将主货仓也装满，回收会让分身货物2可见落 `(0,0)`。Shuttle用同前6次移动再等待10次，会已经真实交2并继续任务。
