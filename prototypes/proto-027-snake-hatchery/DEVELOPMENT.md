## 2. 开工准备

1. 先核对上述需求/设计、工作区和共同标准，为本项目独立建立任务包、工程目录与参数版本；不复制其他工程的缓存、产品标识或测试结果。
2. 固定一张有窄通道和两个采集区的地图，登记网格尺寸、目标、行动预算、节能力、切点、容量与回收成本；未测数值标建议。
3. 明确一步动作的意图/占位/分身冲突次序、直接反向限制与旧尾格成长例外、超容量货物去向和失败边界。预览与执行读取同一规则。
4. 首批只需网格、主蛇/身体节、两种分身标记、采集物、交付点、切点和阻塞反馈样件。先成立读图，再扩正式资产。

## 3. 玩法与技术重点

- 最小范围为一图、一条主蛇、主蛇外最多两分身、三类身体节、两种公开简单行为。无分身时仍能普通采集和交付；不增加敌群、复杂自主寻路或真实软体。
- 有序身体和占格是规则真值，能力从当前归属的实际节重算。切尾转移现有节，回收只改变合法归属；模块、货物不得复制、消失或同时属于多实体。
- 主蛇至少保留合法身体；达到两分身上限时拒绝再切。新分身下一步才行动，无效菜单选择不推进全局行动。
- 分身使用可见短路径，冲突按主蛇计划与稳定编号裁决；等待原因可查，不自动改道或无预告伤害主蛇。暂停、单步和复盘共用动作/事件序列。

本工程Rules/Session v0.2.0、格式1已只读核对：8×6图、80行动、总模块7/货物8；短身体3+库存2+地面2，长身体5+库存0+地面2，两预置同总量。身体能力按真实归属，模块库存不等于货物空间；Move吞地面最低ID模块成长，G式CollectModule只进库存。公开Patrol一圈停、Shuttle闭合循环并入Dock交付。每个新提交命令花1行动，碰撞/直接反向为已提交失败；最后有效交付完成优先预算。参数和地图是助手实施初值，不是平衡结论。

无分身黄金预期由独立推导与Core代理统一：两预置同输入52行动交8/余28；Long利用容量减少往返为28行动/余52。具体合法序列/终态见实施方案，实际生产路径Unity测试已通过；路线通过不代表体验成立。切尾/回收只读预告与四向安全提示已补源码，原生表现/确认取消仍待验证。

## 4. 美术、音频与交付

节类型、完整身体占位、能力归属、合法切点、切后损失、分身路径与货物去向必须同时可读。切尾/回收动画只能响应提交事件，不能让显示缩短逃避碰撞。

若采用三维低模，使用已有 Blender CLI，保留制作源与明确导出、核对单位/轴/枢轴；若采用二维，保留图像生成/绘制源和透明边界。视觉维度不改变网格占位。收集、切尾、阻塞、回收和交付音对应实际事件，静音有文字/形状反馈；不默认增加配音。每项素材清理许可、来源和哈希，正式UI文字由文本系统提供。

上述是通用生产选择。本轮实际先用原创C#参数网格/材质做生态孵化盘，源为SnakeSceneView.cs，基/采/仓形状+文字、主/分稳定ID、实线任务/虚线草案与真切点对齐Core，初态相机已目检，动态与完整HUD未验；没有Blender/FBX/生图产物声明。字体/七原创短音/独立原创BGM九副本来源登记已存在，同字节/听感等按本项目逐项验，不因复用文件就抄上项成绩。

## 5. 首次纵切与阶段顺序

顺序建议：无分身基础蛇 → 成长/能力与一次切尾 → 一个分身任务/回收 → 第二分身冲突 → 一图完整采集交付/失败重试 → 正式样件与Windows构建/真实输入 → 体验对照成立后扩内容。

首次纵切完成标准是单图完整循环，执行 [SNK-A01–A05](../../docs/design/first-batch/proto-027-snake-hatchery/requirements.md)，重点保留：成长前后占位、切尾模块守恒、两分身上限拒绝、容量不足去向、短/长/0–2分身同场景复现。测试用例需能识别错误归属或免费能力，数量不作为放行依据。

首次候选包含动作结束的完整安全保存/恢复：版本/地图身份、主蛇有序节/方向/能力来源、分身ID/有序节/行为/路径进度/阻塞/载货、地面模块/货物、携带模块库存、全局行动/交付/阶段、命令/事件与幂等身份。Core纯数据导出/领域校验及生产命令完整重放接口已落盘，与root磁盘payload/SHA/合法备份适配分开；恢复与复盘不重复采集/孵化/回收/交付，坏档不得覆盖唯一有效备份。本项目4项磁盘故障随32项Unity测试通过，原生恢复/退出仍未验；不借其它项目报告。

真实 Player 验证转向、切点选择、路径预告、回收与交付；记录版本、输入/事件、窗口画面和失败原因。通过规则后再观察 SNK-H01–H03：是否主动保持短体、切尾、回收，能否解释失去的能力。分身恒优或管理负担过重时先修规则，不扩科技树。
