## 2. 开工准备

1. 核对需求/设计和共同标准，为本项目独立建立任务包、工程/内容版本、单步验证与构建入口。
2. 固定六站位环、一组有限盘库存、六状态、四加工站和两类互斥订单；登记方向、固定步数、离席窗口、原料/改站/清洗/购置成本与补救条件。
3. 明确准备、圈边界标记窗口、改站窗口、单步/连续运行和最后一步结算；价格先标建议，不引入借款或升级框架。
4. 首批样件为环/站/盘、料理状态、整份/小份、可交付/保留、脏盘、订单与事件提示，先核对低分辨率读图。

## 3. 玩法与技术重点

- 同一盘沿单环变化，玩家决定交付或继续占位。只做六站位、六状态、四站、两类订单和固定运行上限；不加多环布线、员工、真实切菜或多品类餐厅。
- 每步按快照移动 → 稳定顺序加工 → 合法交付 → 等待/离席 → 边界/结束结算。新切盘本步不再移动加工；当步合法交付先于离席，最后一步事件完成后才结算。
- 切分先检查干净盘和入口容量，再原子分量；总食材量不增。条件不足时保留原料理，不吞材料、覆盖盘位或扣失败成本。
- 交付只消费匹配订单且标记可交付的盘，留下脏盘；清洗后才恢复投料容量。订单、盘归属、资金/成本和事件由同一规则层结算，预览和UI不另算收益。
- 关键站缺席仍有公开基础出售、弃单与转卖补救；固定订单/候选先可复现，再评估随机和局外成长。

## 4. 美术、音频与交付

环方向、盘位、料理状态、份量、标记和清洁状态优先于厨房装饰；文字/形状同时区分，不能只靠颜色或食物纹理。若以后使用三维道具，展示位置与环槽锚点一致，动画不触发第二次加工。

二维图或Blender低模按本项目视角决定，保留源与导出并清理来源/许可/哈希；生图不生成规则字形或按钮。加工、切分阻塞、交付、拒收、离席和清洗音只响应真实事件，静音可读。首轮不强加人物配音，音乐不掩盖节拍/提醒。

## 5. 首次纵切与阶段顺序

顺序建议：单步传送/基础出售 → 状态加工 → 切分/盘容量/清洗 → 两订单交付/保留 → 关键站缺席补救 → 同轮完整重试/复盘 → 正式样件与Windows真实操作 → 体验成立后扩内容。

首次纵切在同一环完成投入、加工、交付/保留、清洗、预算结束和重试，执行 [SUS-A01–A05](../../docs/design/first-batch/proto-032-sushi-workshop/requirements.md)。保留空盘/满盘切分、保留盘经过顾客、最后步交付/离席及资金不足的独立输入与结果；检查食材/实体盘守恒和失败交易不扣费。

按共同标准，首次纵切还要定义本项目单步结束的安全保存/恢复，核对盘位置/状态/份量/标记、订单、步数、资金与脏盘库存；恢复不重加工、重交付或免费清洗。当前尚无该实现或故障报告。

真实 Player 核对配置、盘标记、单步/连续运行、原因提示与重试；报告代码/内容版本、输入/事件、画面和结果。再用SUS-H01–H03比较两订单配置和删除切分的对照；收入更高不直接证明有取舍。出现恒优排列或无关键站只能重开时先改规则，不加新站掩盖问题。
