## 3. 玩法与技术重点

- 同一盘沿单环变化，玩家决定交付或继续占位。只做六站位、六状态、四站、两类订单和固定运行上限；不加多环布线、员工、真实切菜或多品类餐厅。
- 每步按快照移动 → 稳定顺序加工 → 合法交付/已安排基础出售 → 等待/离席 → 边界/结束结算。新切盘暂存待入口，本步不再移动加工；当步合法交付先于离席，最后一步事件完成后才结算。
- 切分先检查干净盘和入口容量，再原子分量；总食材量不增。条件不足时保留原料理，不吞材料、覆盖盘位或扣失败成本。
- 交付只消费匹配订单且标记可交付的盘，留下脏盘；清洗后才恢复投料容量。订单、盘归属、资金/成本和事件由同一规则层结算，预览和UI不另算收益。
- 关键站缺席仍有公开基础出售、弃单与转卖补救；固定订单/候选先可复现，再评估随机和局外成长。

## 4. 美术、音频与交付

首样采用暖木台、墨绿椭圆环轨、陶瓷盘、饭团/海苔卷六状态、四工站工具轮廓和克制店内装饰。环方向、盘位、料理状态、份量、标记和清洁状态优先于装饰；文字/形状同时区分，不能只靠颜色或食物纹理。三维样件从规则槽锚点/状态读数，动画不触发第二次加工，不新增自由漫游。

本轮原创C#网格/材质保留作者源与生成规则，并登记实际采用状态；后续Blender/二维生图按本项目视角选择，不伪称现有样件来自Blender。生图不生成规则字形或按钮。加工、切分阻塞、交付、拒收、离席和清洗音只响应真实事件，静音可读；可复用本仓已清理许可的程序音，但须记录本项目事件映射。首轮不强加人物配音或完整BGM。

本轮程序模型源见 [资产登记](../../sources/art/proto-032-sushi-workshop/README.md)，九份字体/原创音频运行副本与两份声明已按 [运行资源登记](../../sources/art/proto-032-sushi-workshop/runtime-resource-register.json) 核对哈希。真实相机文字尺寸已正常，最终包与初态相机图已归档；实际听感、完整HUD与原生操作仍待验。

## 5. 首次纵切与阶段顺序

顺序建议：单步传送/基础出售 → 状态加工 → 切分/盘容量/清洗 → 两订单交付/保留 → 关键站缺席补救 → 同轮完整重试/复盘 → 正式样件与Windows真实操作 → 体验成立后扩内容。

首次纵切候选在同一环实现投入、加工、交付/保留、清洗、预算结束和重试。[SUS-A01–A05](../../docs/design/first-batch/proto-032-sushi-workshop/requirements.md) 对应规则测试已通过，包括两订单黄金输入钱包整份30/Quick27、空盘/满盘切分、保留盘经过顾客、最后步交付/离席及资金不足的独立输入与结果；检查食材/实体盘守恒和失败交易不扣费。实际键鼠复现仍须另外完成。

首次纵切包含已提交单步安全点的完整保存/恢复，核对盘ID/位置/状态/份量/标记/归属、待入口、订单/等待、步数/阶段、工站/改站额度、资金/收入与事件/幂等记录；恢复不重加工、重交付或免费清洗。Core纯数据校验与磁盘CheckpointStore分离，坏档/写失败保留当前局及有效旧档，提交前故障注入使用隔离目录；实际故障结果见开发记录。

真实 Player 核对配置、盘标记、单步/连续运行、原因提示与重试；报告代码/内容版本、输入/事件、画面和结果。再用SUS-H01–H03比较两订单配置和删除切分的对照；收入更高不直接证明有取舍。出现恒优排列或无关键站只能重开时先改规则，不加新站掩盖问题。

H关键事件复盘显示最近十条加工、切分、切分阻塞、拒收、离席、交付的步骤/盘/槽和原因；打开暂停，H/Esc关闭，复盘不得提交玩法收益。保存验收还覆盖损坏主档再保存不覆写唯一有效备份、新Save领域校验，以及自动保存/退出保存失败的错误优先与留窗口重试。
