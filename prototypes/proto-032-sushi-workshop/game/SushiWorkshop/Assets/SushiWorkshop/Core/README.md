# 032 纯规则接口与首轮参数

实施版本：`Rules.Version=0.2.0`；快照格式：1；实施日期：2026-10-10（Asia/Shanghai）。依据为 [原需求 v0.1](../../../../../../../docs/design/first-batch/proto-032-sushi-workshop/requirements.md) 与 [原设计 v0.1](../../../../../../../docs/design/first-batch/proto-032-sushi-workshop/design.md)。以下补足未定义初值和时序，均为助手初始建议，不是实测平衡；原案保持六槽、六状态、四站与两类互斥订单。

## 固定内容与经济

- 单环六槽 S0–S5，顺时针每步 `slot→(slot+1)%6`，入口 S0、顾客 S5。六只稳定实体盘 ID=0–5；盘只属于干净库存、脏盘库存、环上或暂存区之一；环同槽不能重叠，暂存区最多一盘。
- 六料理状态：`RiceBase` 米基底、`FilledRice` 卷料、`Roll` 成卷、`HeatedRoll` 熟卷、`SmallRoll` 小份卷、`SmallHeatedRoll` 小份熟卷。整份为 2 食材单位，小份为 1；空盘使用零数量与库存位置，不增加第七料理状态。
- 四工站初始各一件：S1 `Filling` 加料，S2 `Rolling` 卷制，S3 `Heating` 加热，S4 `Cutting` 切分。加料仅米基底→卷料，卷制仅卷料→成卷；加热使成卷/小份卷变熟卷/小份熟卷；切分仅整份成卷/熟卷。所有不适用盘通过并产生原因事件。
- 初始 18 金、18 步，每六步停在圈边界；每轮共有 4 次工站调整，移动、交换、转卖、购置各消耗一次成功动作。挪站 2 金，购置 6，转卖 3；移动至已有工站执行原子交换，无销毁或自动购置。每种工站最多一件；非法动作、失败交易与无变化操作不扣钱/次数。
- 投入一份原料套餐 3 金，含这一份的米与卷料材料；后续加工只改状态、不凭空加食材单位。洗盘 1 金。装料默认可交付、不开基础出售。价格和守恒量不得由视图自行解释。
- 每轮只有一个主订单：`WholeHeated` 需整份熟卷 2 盘，每盘 10 金，等待 18 步；`QuickSmall` 需小份卷 2 盘，每盘 7 金，等待 12 步。另一类型通过创建新轮对照，不能在同轮用不同订单回收任意料理。
- 基础出售须逐盘公开安排，在顾客点按食材单位×1收款，无额外份量溢价，留下脏盘。匹配且可交付的主订单优先，不重复基础出售。弃单仅对等待订单合法，罚 2 金；离席不再收弃单费，也不自动清空料理。
- 所有轮统一在第18步结算。主订单完成为 `OrderCompleted`；否则实际基础收入至少6为降级补救 `BaseTradeCompleted`，其余 `Failed`。卖站收入不算基础收入。订单完成和离席都不立即终止环；未卖料理无结算变现。失败可从相同订单初态重试，新轮重置资金与盘，不把上轮资产带入。

## 窗口、步序与守恒

`Preparation→Running→每6步CircleBoundary→Running→Finished`。准备与圈边界可调交付/保留、基础出售标记、付费改站、弃单。**投料与付费洗盘允许任意完整单步之间**，包括 Running；这是 v0.2 对未定义时序的补充，连续模式可暂停后操作。入口占用不得覆盖；Finished 后都不能操作。运行中仍不能调标或临时重排工站。

一完整步同步执行：

1. 收集当步已有环上盘并同步前移；按稳定顺序记录移动。
2. 上一步暂存小份在入口空时进入 S0，本步不移动/加工；入口被移动后的原盘占用时继续暂存并提示，不能覆盖或丢失。
3. 仅处理原有环上盘，按槽位与盘 ID 排序加工。切分先检查额外干净盘、空环容量及暂存容量，再原子分量；新盘继承两个标记，本步只暂存。前置不足保留原料理、数量、库存和资金。
4. S5 先检查订单标记、状态、份量，成功时收款、扣需求、食材离开系统、实体盘进脏盘库存；否则说明保留/份量/状态/无有效订单。再处理该盘已安排的基础出售，成功订单盘不能再卖。
5. 更新等待。合法当步交付先于离席；恰好最后一步完成订单不判超时。更新圈边界或第18步最终结算，不执行第19步。

始终满足：六实体盘身份唯一；环槽唯一；`累计投料份数×2=现存食材量+订单交付量+基础出售量`；`钱包=18+订单收入+基础收入+转卖收入−原料−清洗−改站−购置−弃单`。干净/脏盘不带食材；洗盘不会返还材料。正款、不透支；失败交易没有命令提交或事件奖励。

## 接口与恢复

Core 程序集 `SushiWorkshop.Core`，namespace `SushiWorkshop`，无 Unity 引用。`Session.CreatePrototype(OrderKind)` 建立初态，`Retry()` 返回独立新轮。只读 `State` 深拷贝、`LastEvents` 拷贝；`CanPrepare` 表示准备或圈边界。视图不能写回 State、再算金额或调用第二套加工。

- `StartOrResume(commandId)`、`Step(commandId)`、`LoadIngredient(commandId)`、`WashOne(commandId)`、`AbandonOrder(commandId)`。
- `SetDeliverable(plateId,value,commandId)`、`QueueBaseSale(plateId,value,commandId)`。
- `MoveStation(sourceSlot,targetSlot,commandId)`、`SellStation(slot,commandId)`、`BuyStation(slot,kind,commandId)`。
- 所有命令返回 `CommandResult.Success/AlreadyApplied/Reason/Events`。可显式传唯一 commandId；省略时生成不冲突编号。成功命令同 ID 重发只返回 AlreadyApplied，无新事件与收益；失败命令不登记。`GameEvent` 为 Sequence、Step、Kind、Slot、PlateId、Amount、Reason；展示与音效只消费这次结果的新事件。
- `ExportSnapshot()` 输出 `[Serializable]` 的纯 public 字段，适用于 JsonUtility；不写文件。`TryRestore(snapshot,out Session,out reason)` 与 `ValidateSnapshot` 校验版本、范围、盘/槽/食材/金额/阶段，再从同订单初态经生产命令重放，逐字段核对配置、订单、状态、费用、成功命令与事件历史。恢复不免费清洗、重加工、重派奖，LastEvents 为空；幂等编号继续保留。
- 保存点为每个同步命令提交完成后，含 Running 的完整步间、圈边界与 Finished；没有半步状态。磁盘校验/备份/写失败 UI 由持久化适配承担。重放拒绝自相矛盾或无法生成的状态，**不是防篡改认证**；合法历史自行重建与跨文件完整性另由实际存储合同处理。

## 独立推导的动作样本

以下先按原规则逐槽与公开价格推导，再由生产命令测试；测试文件存在不代表 Unity 已运行。

- **整份成功**：准备将切分 S4→S0（2金），投一份（3金）；S1/S2/S3分别在第1/2/3步加料/卷制/加热，第5步 S5交付。第6步圈边界投第二份（3金），第11步交付。第18步结算；钱包 `18−2−6+20=30`，食材4单位全部交付，2脏盘，4干净盘。
- **小份成功**：准备将加热 S3→S0（2金），投一份（3金）；第1/2步加料/卷制，第4步切分为两小份。原盘第5步交付；新盘第5步进入 S0且不加工，随后第6–10步走到顾客再交付。第18步结算；钱包 `18−2−3+14=27`，2单位全部交付。这个配置对整份熟卷订单不能交付，保持订单互斥。
- **无干净盘切分**：初态投料，开始；第1–4步每步结束再投一份，共5份/15金。第4步首次切分使用额外第六实体盘；第5步旧第二份到切分时已无干净盘，必须保持熟卷2单位。此时6实体盘在6不同环槽，食材10单位、钱包3，无复制或切分扣费。
- **保留与洗盘**：转卖切分站后保留熟卷，第5步经过匹配顾客不交付；第6步调为可交付，第11步才交付变脏。未洗前该盘不参与投料分配，付1金洗后恢复干净库存。
- **缺关键站补救**：转卖卷制站得3，三次移动共扣6，再弃单扣2，资金13；各圈投入并安排基础出售，共3份原料花9、按2单位各卖2，总基础收入6。第18步降级经营成功，钱包 `18+3+6−6−9−2=10`，低于整份路线30，缺站不强迫重开。
- **末步优先**：整份第一盘第5步交付，第二份延至第13步后投入；第14–18步前进并于第18步交付，订单完成应先于最终结算，不能先离席或多走一步。
