## 1. 项目标识与执行依据

- 用户明确要求：在当前工程创建独立项目，分析 `E:\SteamLibrary\steamapps\common\Crunch Time` 的完整代码、内容和资产。
- 目录：`prototypes/re-crunch-time`；无原方案编号，不并入第一批原型排期。
- 来源：用户指定的 Steam 本机安装；安装原文件保持只读，分析使用 `local/build-copy`。
- 当前范围：全安装文件清单/哈希、游戏程序集全量反编译与索引、全部 Unity 容器对象与依赖、内容数据与规则整理、可解码资产本地导出、完整中文分析报告。
- 助手实施选择：静态分析优先，按代码、内容、资产、验证分层；派生第三方内容仅保存在忽略的 `local/`。仓库保存原创报告、分析工具与不包含完整第三方源码/媒体的证据索引。
- 差异：这是既有游戏的分析工程，不创建 Unity 2022 新游戏、不擅自移植或修改目标、不执行发行。目标引擎版本由安装证据确定。
- 权威入口：[README](README.md)、[来源记录](sources/target-register.md)、[分析报告](reports/analysis.md)。

## 2. 开工准备

- 本机目录初查：25 个文件，407,121,399 字节；`Assembly-CSharp.dll` 162,816 字节；两个大型 `.assets`、`mainData`、内置资源和 Mono 运行时。

## 3. 本项目分析要求

- **代码**：全量还原游戏托管程序集的可读 C# 和 IL，统计类型/方法、继承、字段、调用与字符串；分清原始符号与反编译推断。
- **内容与规则**：追踪启动、界面、主循环、输入、关卡/棋盘、分数、计时、道具、解锁、随机、结束与重开、保存和联网；每条关键结论定位至符号或对象。
- **资产**：容器、对象类型/名称/path ID/大小、依赖、脚本映射和场景层级全量登记；逐类型导出纹理、音频、网格、材质、动画、字体与序列化数据，失败显式列出。
- **验证**：安装与副本逐文件 SHA256 一致；对象数量和导出结果闭合；程序集覆盖与反编译错误检查；报告本地链接有效。静态结论不冒充真实游玩、听感或原始工程重建。
- **保存与许可**：第三方代码、原始构建和媒体留在本机忽略目录；公开备份仅原创分析与必要索引，不把合法持有安装文件等同于取得再分发许可。

## 4. 实施阶段与放行证据

1. 准备：来源、范围、工具和副本哈希明确。
2. 代码：程序集全量输出与方法/类型索引，核心系统逐类分析。
3. 内容资产：全部容器读入、对象/依赖/内容关联与导出覆盖闭合。
4. 交付：中文报告、可复跑工具、全量索引、本地派生产物；定向验证和独立 Git 备份。
