## 对局与胜利

两家公司各有一个随机不同项目、独立完整 95 张牌堆、五个员工槽和五个负面事件槽。五部门索引固定为 0 声音、1 程序、2 设计、3 美术、4 测试。初始各五张手牌；第一个周次双方不额外补牌，之后每方开始出牌前补 `max(1,5−当前手牌数)` 张，五张是补牌阈值，不是手牌硬上限。

牌堆每次按均匀随机下标抽取，随后移除；没有弃牌洗回牌堆代码。员工牌先设置本回合允许部门，同回合可以继续出该部门员工；正面卡可解除部门限制。对方正在工作的同 ID 员工禁止重复入场，同类型但不同 ID 不等于同一员工。

员工需要两个或四个所属方工作回合。出牌后的员工在后续回合开始推进；有目标部门/全体负面事件时被阻断，未阻断才能正常工作。完成后为自身项目对应部门 `done += 1`、预算 `+1250`，卡进所属弃牌区。持续负面事件在受影响方出牌结束后的结算推进，到期解除阻断并进入原出牌方弃牌区。

项目五个部门全满足 `done >= goal` 即胜利。完成量允许超过目标；卡牌使用为所属方预算 `+500`。预算为排名指标，没有支付费用、购买卡、市场、永久升级、解锁或战役关卡系统的实现。项目缩减目标可直接满足胜利条件，但不给额外任务完成预算。证据：PlayCard.Use `0600006F`，ProjectCard.CompleteTask `060000C4` / RemoveTask `060000C7` / CheckProjectFinished `060000C9`。

## 全部 95 张卡牌

ID 连续 1–95，无重复或缺项。类型 5 没有定义，是枚举编号留空，不是漏解析。所有字段以加载器默认值补齐：Type=0、Turns=0、Target=-1、Function=0、Num=0、Repair 为空、Picture=Default。

- **ID 1–42 员工**：声音 6、程序 12、设计 6、美术 12、测试 6。21 张工作两回合、21 张工作四回合。显示姓名、引言、说明，职业与男/女图像关联；重复职业的员工依然是不同 ID。
- **ID 43–62 持续阻断（Type 6，20 张）**：全体或特定部门阻断，持续 1–3 回合。43/46/48 全体一回合；44/47/50 全体两回合；45/49 全体三回合；51–62 为部门一回合阻断，声音 2、程序 3、设计 2、美术 3、测试 2。多张负面事件可同时存在，解除一张后仍需检查其它匹配事件。
- **ID 63–68 即时员工干预（Type 7，6 张）**：Function 0 偷走、1 退回对方手牌、2 移除到弃牌，各两张。目标为对方在场员工；偷走需要己方员工槽有空位。选择目标和移动/翻面/重新归属在动作队列中执行。
- **ID 69–81 正面增益（Type 8，13 张）**：69–71 推进全部未阻断员工一回合；72–75 让全部未阻断员工完成当前工作；76–78 允许本回合任意部门员工；79–81 选择己方部门减少一个目标任务。
- **ID 82–86 修复（Type 9，5 张）**：82–84 允许修复负面 ID 44/45/49/50；85–86 修复 47/48。`Repair` 是以 `|` 分隔的具体 ID 白名单，不是清除全部负面牌。回合开始自动扫描可用修复，也存在手动交互。
- **ID 87–88 谈判反制（Type 10，2 张）**：普通出牌判定不可主动使用；遇到对方总部干预时在手牌中检查。玩家约六秒决策，AI 通过策略判断；成功反制消费双方相关卡但不执行总部任务改动。
- **ID 89–95 总部干预（Type 11，7 张）**：89 程序目标+2，90 设计+1，91 美术+2，92 测试+1，93 声音+1；94/95 选择对方已完成的部门重开一个任务（done−1）。常量名称 DEL_TASK 对应此分支，但实际不是 goal−1；与己方正面“减目标”不可混为一谈。

每张卡的 Target/Function/Turns/Num/Repair/Picture、Sprite 对象 ID 均在逐 ID 索引。95 张卡使用 28 个不同的资源 Sprite；资源表的大小写规范化后全部匹配，无缺失图片。英文与西班牙文各有 Name/Quote/Description 三项，共 285 个卡牌文本键。

## 可出牌约束

`CardManager.iCanIPlay`（060001C1）返回 -1 表示可出，其它值是原因码：0 非当前玩家；1 员工槽满；2 不符合本回合部门；3 对方负面槽满；4 对方无员工；5 对方没有已完成任务；6 同 ID 员工在对方工作；7 己方没有未阻断员工；8 无可搭配员工手牌；9 当前卡不可用/无匹配修复。不同类型只检查相关约束，持续阻断不要求目标部门已经有员工。

员工使用、反制、项目部门选择与手动弃牌/退回等交互由卡牌状态控制；`bUseAvailable` 既用于 UI 高亮也供 AI 候选集合使用。不能只依据 XML 类型解释是否可出，需同时读合法性函数和 PlayCard 对应 Use 分支。

## 全部 28 个项目与配置差异

ID 连续 1–28。模拟平台分布：Oui 4、X720 7、Doors OS 7、EnjoyStation 9、Touch OS 1。每个项目有 Title/SubTitle 两个双语文本键，共 56 键；平台是内容标签，未见按平台另设收益、发行门槛或兼容策略。

原 XML 的五个工作量标签为 Design/Programming/Art/Animation/Sound。Loader 的 Switch 中却读取 Design/Programming/Art/**Testing**/Sound；Animation 没有分支，Testing 保留初始化 2。28 项原 Animation 分布为 1×10、2×12、3×6，实际 Testing 全部等于 2。

有效值不同的项目 ID：**3、4、5、6、11、12、14、17、18、20、21、22、23、26、27、28**。例如 ID 3 原 Animation=1，但有效 Testing=2；ID 1 原值恰为 2，虽然 Animation 同样被忽略，数值看起来不变。忽略字段与数值差异是两项不同事实。

全部项目其它四部门数值原样读取，实际总任务数：11 个任务的项目 6 个，12 个任务的项目 12 个，13 个任务的项目 10 个。原 Animation 五部门总量为 12，所以不能用原配置总量假定所有项目运行难度相同。索引同时保留 raw 与 effective，未修改游戏来“修复”此差异。

## 其它内容与局内叙事

Texts 含 79 键，覆盖操作、公司名、部门、回合提示、不可用原因、两页教程、胜败、新记录、预算符号和制作人员信息。加上卡牌与项目，共 420 唯一文本键、840 语言格；4 个空格来自空 ID 和 REASON_-1 的英/西两语，未发现重复 ID。语言只有 English/Spanish，没有中文本地化。

hLanguage 使用三个 XML 组成字典并实时重载界面/卡牌；缺少键记录错误并返回空文本。预算按语言格式化分隔符与货币符号，WordWrap 按空格/行长度。完整文案、教程与 credits 都保存在本地 XML/目录，不以复制所有文案进公开报告代替内容分析。

## 静态边界与待实机核对

确认的字段差异可直接由 Loader 与 XML 复核。空牌堆访问、超额任务得分、重复完成预算、非标准分辨率适配及动画队列的极端顺序是静态识别出的行为或边界，本轮未在原生对局中复现。没有将这些推断写成已观察的游戏崩溃，也没有改变目标规则或存档。
