## 2. 开工准备

1. 核对需求/设计、共同标准和工作区，建立本项目独立任务包、工程、场景/参数版本、定向测试与构建入口。
2. 固定一房间、三污物、两材料、两刷头、一有限滤芯，准备同布局小/大桶、同容量不同布局及关闭滤芯的对照。
3. 登记每格剩余污物、材料产出、覆盖顺序、共享容量、转换上限/配方、清洁剂槽、行动与耐久成本。数量和效果均可查，不将未测值写成平衡结论。
4. 首批制作污物/清洁状态、刷头接触范围、桶内两材料、满桶阻塞、出售点与滤芯反馈样件；先成立基础擦洗反馈再加成长。

## 3. 玩法与技术重点

- 首轮关闭升级，先比较容量和布局，再启用滤芯。基础工具可完成普通清洁，顽渍有公开基础处理方式；不加敌人、机器人、流体、燃烧或清洁电网。
- 规则共同维护污物、接触覆盖、容量、配方、工具/行动和事件。实际能装多少才减多少污物，桶满残余留场；不能先擦掉画面再拒绝入桶。
- 吸取先校验目标/成本和容量，按稳定覆盖顺序处理；滤芯只有合法配方/上限/槽空间才消耗已有材料并腾容量，再接新料。无条件时回到普通容量处理。
- 出售、丢弃、转换和使用清洁剂具有互斥物料去向；失败动作不执行一半，转换不能产无限清洁剂。腾桶/换头/补给位置和成本公开。
- 最后一次有效清洁先更新完成度，再判断预算耗尽；同布局/输入复现库存和完成度。成本系统若只叠加惩罚，不默认保留两套。

## 4. 美术、音频与交付

刷头范围、实际污物减少、桶变化与滤芯消耗/产出同事件同步；满桶/材料不足/清洁剂不适用用短文字与形状说明。污物视觉可渐变，但不能表现已清空而规则仍残留。

二维素材或Blender道具按俯视读图需要选择，视觉维度不扩大覆盖/容量；保存源、导出与单位/枢轴或透明边界记录，逐项清理许可和哈希。吸取、擦洗、满桶、转换、出售和完成音有静音替代；先检验基础动作听感，完整音乐/环境后续分阶段制作，不强加配音。

## 5. 首次纵切与阶段顺序

顺序建议：无滤芯基础移动/清洁 → 桶容量/材料/腾桶 → 两刷头覆盖与成本 → 滤芯/清洁剂/互斥出售 → 单房间完整目标/失败重试 → 正式样件与Windows真实操作 → 路线取舍成立后扩房间。

首次纵切执行 [CLN-A01–A05](../../docs/design/first-batch/proto-051-recycling-cleaners/requirements.md)，保留小/大桶满容量、无滤芯基础完成、同料出售/转换、两刷头及末动作的输入/事件/库存证据；产出和清洁减少必须能核账。

按共同标准，首次纵切还要定义动作结束的安全保存/恢复，核对污物残量、桶内两材料、清洁剂、工具/位置与预算；恢复不重复清洁、出售或转换，同一提交前后状态自洽。当前尚无存档实现或故障报告。

真实 Player 核对选区域、换头、腾桶、出售/转换、原因提示与重试，并记录版本、输入、画面和结果。再观察CLN-H01–H03的主动路线/留料变化与无升级基础手感；完成度上涨不等于策略成立。滤芯纯加成、路线恒定或反馈无趣时先重构，不扩商店。
