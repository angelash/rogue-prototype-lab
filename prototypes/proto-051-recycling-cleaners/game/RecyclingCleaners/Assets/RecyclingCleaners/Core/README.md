# 051 回收保洁队：规则接口与首轮参数

实施日期：2026-10-10；`Rules.Version=0.2.0`，快照格式1。依据为 [需求 v0.1](../../../../../../../docs/design/first-batch/proto-051-recycling-cleaners/requirements.md) 与 [设计 v0.1](../../../../../../../docs/design/first-batch/proto-051-recycling-cleaners/design.md)。以下填补地图、初值与交易时序，属于助手可调整建议，不是已测平衡。保持单房间、三污物、两材料、两头、一有限滤芯，无升级、战斗、流体或新工具。

## 房间与状态

- 6×6，格ID=`y*6+x`；x向右、y向房间深处。玩家初始/补给点(0,0)，障碍(4,2)/(4,3)。正交移动1格花1行动、0耐久，不穿墙/越界。
- `Compact`：普通碎屑(1,0)4、(2,1)4；可转碎屑(2,0)4；水(1,1)2、(3,2)2；顽渍(3,1)3。共19污物、普通材料8、可转材料4。`Separated`只将污格镜像为(5−x,5−y)，补给/障碍不动；材料/总目标相同。清完全部污物为成功，不要求把桶内剩料自动变现。
- 同布局可独立选择桶容量6或12、初始滤芯开/关。初始80行动、耐久48、现金6、窄头、空桶/空剂槽、滤芯剩3次。重试回到相同初始选择，不带上一轮钱、料或已清洁状态。
- 活跃阶段为 `Phase.Active`；所有同步合法动作完成后才检查结束。先更新清洁，若剩余污物0则 `Completed`，即使最后行动刚耗尽；否则行动0为 `Failed`。耐久0不直接结束：可花行动移动回补给点，并有现金时补给。任何补给都不增加行动预算。

## 范围、成本与材料

- 选择目标须为自身格或曼哈顿相邻1格、不能是障碍。窄头仅该格；广域头为该格+正交四邻，越界/障碍格剔除。覆盖按到玩家的曼哈顿距离、再格ID稳定排序；`PreviewCoverage`与实际动作共用这一规则。
- 窄头吸碎屑最多2单位，擦水最多2、擦顽最多1；每次有效动作1行动/1耐久。广头各适用覆盖格最多1单位，每次有效动作2行动/2耐久；只吸碎屑或只擦水/顽，不能混成免费两动作。成本不随覆盖格数重复扣。
- 每吸走1碎屑即把对应1材料放桶；两材料共享容量。实际只能装多少就减少多少，剩余留场并提示；空区、不可达、满桶且无合法转换、资源不足的失败操作不扣预算/耐久，也不删除污物。
- 换头仅补给点，1行动/1耐久；出售仅补给点，一次卖两类全库存，普通单价1、可转单价2，花1行动/1耐久。丢弃仅补给点，指定一类数量，1行动/1耐久且无现金；数量不足不执行一半。
- 滤芯开关任意位置，1行动/0耐久，不恢复次数。固定配方为2旧可转料→1清洁剂；剂槽最多2，总转换能力最多3次。手动转换任意位置，1行动/1耐久，每次只转一批；关闭、材料不足、剂槽满、滤芯耗尽时拒绝。
- 吸取前，只有滤芯打开、桶内旧可转料≥2、剂槽/次数允许且耐久支付得起额外1时，最多自动转一批。自动转换不加行动成本，但另扣1耐久；**本步新入料不参与循环转换**。任何转换条件不合法时回普通容量吸取；若仍满桶则阻塞。不能因付不起自动转换耐久而拒绝本来可做的普通吸取。
- `UseDetergent`仅所选可达顽渍格，消耗1剂/1行动/1耐久，最多清3单位；不适用格不扣剂。用过的剂不返回材料、不再次出售。
- `Restock`仅补给点：现金3、行动2，将耐久恢复48；满耐久/钱或预算不足拒绝。不会恢复滤芯能力、返还食材或改变房间/目标。初始窄头无滤芯的完整路线不需要补给。

原材料守恒：被清走的普通碎屑=`桶普通+已售普通+已弃普通`；被清走的可转碎屑=`桶可转+已售可转+已弃可转+2×转换次数`。剂存量=`转换次数−剂使用次数`；钱包=`6+已售普通+2×已售可转−3×补给次数`；耐久=`48+实际补回耐久−累计耐久消耗`。水/顽渍擦洗不产生第三类材料。全部变动和稳定事件在同一命令提交，表现不另算清洁或收入。

## 公共接口与检查点

纯 C# namespace `RecyclingCleaners`，程序集 `RecyclingCleaners.Core`，无 Unity 引用。

- `Session.CreatePrototype(LayoutKind,int bucketCapacity,bool filterEnabled)`；`Retry()`返回独立同配置新轮。`State`与`LastEvents`深拷贝；`PreviewCoverage(x,y)`返回格ID数组，非法目标为空。
- `Move(dx,dy,commandId)`、`SetBrush(BrushKind,commandId)`、`Vacuum(x,y,commandId)`、`Scrub(x,y,commandId)`、`UseDetergent(x,y,commandId)`、`Convert(commandId)`、`Sell(commandId)`、`Discard(MaterialKind,amount,commandId)`、`SetFilter(bool,commandId)`、`Restock(commandId)`。
- `CommandResult`含Success、AlreadyApplied、Reason、Events；显式唯一编号可选，省略时生成不冲突编号。成功编号重发只返回AlreadyApplied和空事件；失败不记入成功命令。事件含Sequence、ActionIndex、Kind、X、Y、Amount、Reason，行动序号按已付实际行动成本登记。
- `RoundSnapshot`保存版本、布局/初始容量/初始滤芯、当前开关、位置/工具/预算/耐久、36格污物与障碍、两材料/剂/滤芯次数、出售/弃料/转换/补给账和完整成功Commands/Events。`BucketUsed/RemainingDirt/CleanedUnits`为派生属性；JsonUtility存储使用public字段。
- `ExportSnapshot()`不写磁盘。`TryRestore(snapshot,out Session,out reason)`与`ValidateSnapshot`先校验范围/守恒，再从同初态经生产命令重放，逐项对比全部序列化字段。清洁、出售、转换、预算、布局或事件不匹配均拒绝；恢复清空LastEvents，不重新清洁、发奖或回补消耗，幂等编号保留。
- 安全点为每个完整同步动作提交后；没有半清洁状态。持久化适配负责完整payload校验、主/备份、提交失败与错误UI；规则验证不冒称防篡改认证，也不跨版本静默迁移。

## 无滤芯完整黄金路线：独立推导

同 `Compact`、窄头、初始滤芯关，容量6/12都可执行下列同一序列。坐标表示玩家移动到的格，吸/擦目标另列；这些期望先按地图和公开规则核算，不是录制实现输出。

1. 移至(1,0)，吸(1,0)两次，普通料4；移至(1,1)，擦水(1,1)一次；移至(2,1)，吸(2,1)一次，普通料总6、该格剩2。
2. 经(1,1)→(0,1)→(0,0)，出售6普通料；累计11行动、5耐久、现金12。
3. 经(1,0)→(2,0)，吸(2,0)两次得4可转料；移至(2,1)，吸剩余2普通料；经(1,1)→(0,1)→(0,0)，出售普通2+可转4；累计21行动、9耐久、现金22。
4. 经(1,0)→(2,0)→(3,0)，邻格擦顽(3,1)三次；移至(3,1)，邻格擦水(3,2)一次，清完19单位。累计29行动、13耐久，剩51行动/35耐久，钱包22，桶0、剂0、滤芯剩3；已售普通8、可转4。

第28动作后尚有水2、剩52行动。验收末行动顺序时，可在(3,1)↔(4,1)往返25次，花50行动/0耐久，再开滤芯花1行动；最后一行动擦(3,2)。应在行动0时成功，不能先判截止。生产测试还覆盖同布局桶差异、部分容量、刷头稳定覆盖、同料出售/转换、自动转换耐久不足回普通吸取、耐久0补给、重试与坏检查点。测试存在不表示实际Unity或Player已通过，结果由协调者登记。

`Separated`同样有无滤芯基础路线，容量6/12皆可：经x=3列到(3,5)，吸(4,5)两次、吸(3,5)一次；移到(4,5)擦(4,4)，经(3,5)沿x=3返回y=0再回(0,0)，出售普通4+可转2。再经x=3到(3,4)，吸(3,4)两次、吸(3,5)一次，擦(2,4)三次，移(2,4)擦(2,3)一次即完成。共26移动+11清洁+1出售=38行动，12耐久；剩42行动/36耐久，钱包14，最后桶普通4/可转2，共6未自动变现，滤芯剩3。地图改变会增加往返，但未把基础路线锁死；是否会改变真实玩家选择另作体验观察。
